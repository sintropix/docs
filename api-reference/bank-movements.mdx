A Bank Movement is a single transaction line pulled from a bank feed or entered manually against a Bank Account. Every Movement carries a workflow `status` that Sintropix computes on read: `unbooked`, `booked_pending_allocation`, or `reconciled`. This page covers listing, editing, booking, and matching Bank Movements, individually or in bulk. It also shows how to record an internal transfer between two Bank Accounts.

## Status

Read endpoints enrich each Movement with a `status` field (`bankMovementWithStatusSchema`) computed from its ledger link and allocations:

| Value | Meaning |
| --- | --- |
| `unbooked` | Movement has no Ledger Entry yet. |
| `booked_pending_allocation` | Movement is booked to a Ledger Entry, but the counterpart Open-Item line still has open amount. |
| `reconciled` | Movement is booked and every counterpart line is fully allocated. |

You can also filter (`status=...`) and group (`groupBy=status`) the `GET /movements` listing by this value.

## Review Status

Separately from the workflow `status`, every Movement carries a nullable `reviewStatus` field (`reviewStatusEnum`). It is a reminder an accountant sets by hand, cleared by setting the field back to `null`. Both create and update accept it in the body.

| Value | Meaning |
| --- | --- |
| `null` | Ordinary state (no review flag). |
| `pending_client_information` | The Movement is on hold waiting on information from the client. |
| `pending_statement` | The Movement is on hold waiting on a supporting statement. |
| `pending_counterpart` | The Movement is on hold waiting on its counterpart. |

<Note>
  Most routes are nested under a Bank Account. The base path is `/api/entities/:entityId/bank-accounts/:bankAccountId/movements`, and `:movementId` is a UUID. The one exception is `POST …/comments`, which sits directly under the Entity at `/api/entities/:entityId/bank-movements/:movementId/comments`.
</Note>

<Note>
  **Entities with Books.** When the Entity has at least one [Book](/api-reference/books), `GET /movements/:movementId/match-candidates` requires a `bookId` query parameter, and every write that posts a Ledger Entry (`POST /book`, `POST /match`) must name the target Book on the entry header. See [Books](/api-reference/books) for the model and the exact rule.
</Note>

## The Bank Movement object

Every read and write on this page returns Movements in this shape. Amounts are non-negative integers in the account currency's minor units; the direction is carried by `side`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Movement id. |
| `entityId` | uuid | Owning Entity. |
| `bankAccountId` | uuid | Bank Account the Movement sits on. |
| `movementDate` | string (`YYYY-MM-DD`) | Date the bank reported the line. |
| `amount` | integer | Magnitude in minor units, never negative. |
| `side` | `debit` \| `credit` | Direction against the Bank Account's mapped Ledger Account. `debit` is money in for a `bank` account. |
| `description` | string | The description the bank reported. |
| `externalRef` | string \| null | The bank's own reference for the line. Unique per Bank Account when present. |
| `partnerId` | uuid \| null | Counterparty Partner. |
| `ledgerEntryId` | uuid \| null | The Ledger Entry that books this Movement. `null` while unbooked. |
| `ledgerLineId` | uuid \| null | The bank line of that entry. `null` while unbooked. |
| `ledgerAccountId` | uuid \| null | The Ledger Account that bank line sits on. `null` while unbooked. |
| `metadata` | array of `{ label, value }` | Additional Information lines (up to 50). |
| `status` | `unbooked` \| `booked_pending_allocation` \| `reconciled` | Derived booking status. |
| `runningBalance` | integer | Balance of the Bank Account after this Movement, counting every Movement up to it regardless of filters. |
| `partnerName` | string \| null | Name of `partnerId`, for display. |
| `reconciliationLabel` | string \| null | Counterpart of the booking entry as `"<code> <name>"`, with `" +N"` when there are more counterpart lines. `null` while unbooked. |
| `createdAt`, `updatedAt` | ISO 8601 timestamp | Row timestamps. |

Write answers also return the Bank Account with its computed summary:

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Bank Account id. |
| `entityId` | uuid | Owning Entity. |
| `name` | string | Display name. |
| `kind` | `bank` \| `card` | Account kind. |
| `ledgerAccountId` | uuid | Ledger Account where booked activity accumulates. |
| `currency` | string | ISO 4217 code, for example `CLP`. |
| `feed` | object \| null | `{ bankConnectionId, providerAccountId, institutionName, lastSyncedAt }` when the account is fed by a bank connection; `null` otherwise. |
| `balance` | integer | Signed balance on the Ledger Account's normal side. |
| `unreconciledCount` | integer | Movements not yet reconciled. |
| `createdAt`, `updatedAt` | ISO 8601 timestamp | Row timestamps. |

## GET `/movements`

List Movements on a Bank Account. Returns a paginated `{ movements, nextCursor }` object.

**Query parameters**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `cursor` | string | No | The `nextCursor` value from the previous page. Cannot be combined with `aroundMovementId`. |
| `aroundMovementId` | uuid | No | Return the page that contains this Movement instead of continuing a walk. |
| `limit` | integer | No | Page size, `1` to `100`. Default `50`. |
| `status` | `unbooked` \| `booked_pending_allocation` \| `reconciled` | No | Filter by booking status. |
| `partnerId` | uuid | No | Filter by counterparty Partner. |
| `side` | `debit` \| `credit` | No | Filter by direction. |
| `movementDateFrom` | string (`YYYY-MM-DD`) | No | Earliest movement date, inclusive. |
| `movementDateTo` | string (`YYYY-MM-DD`) | No | Latest movement date, inclusive. |
| `amountMin` | integer | No | Minimum magnitude in minor units. Matched against the magnitude on either side. |
| `amountMax` | integer | No | Maximum magnitude in minor units. |
| `search` | string | No | Up to 100 characters. Matched against the description, the bank reference, and the Partner name. Blank is ignored. |
| `groupBy` | `none` \| `partner` \| `movementMonth` \| `status` | No | Attach a `group` object to every row. Default `none`. |
| `sort` | `movementDate` \| `partnerName` \| `description` \| `amount` | No | Sort field. Default `movementDate`. Sorting by `amount` sorts the signed amount, money in above money out. |
| `sortDirection` | `asc` \| `desc` | No | Default `desc`. |

**Response**

Each row is a Bank Movement object plus `group`: `null` when `groupBy=none`, otherwise `{ by, value, key, movementCount, startsGroup }` where `by` is the `groupBy` value, `value` is the Partner name (nullable), the `YYYY-MM` month, or the status, `movementCount` is the size of the group across the whole result, and `startsGroup` is `true` on the first row of the group. `nextCursor` is `null` on the last page.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$BANK_ACCOUNT_ID/movements?status=unbooked&limit=25" \
```


## GET `/movements/:movementId/match-candidates`

List Invoices and Ledger Entries that could plausibly settle this Movement (per Sintropix's matching heuristics). Up to 200 open Ledger Entry Lines on the side that settles the Movement, newest entry date first.

**Query parameters**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `bookId` | uuid | Conditional | Required when the Entity has at least one Book; must be omitted otherwise. The candidates are the open lines of that Book, plus the common ones. |

**Response:** `{ candidates: [...] }`, one item per open line:

| Field | Type | Description |
| --- | --- | --- |
| `line` | object | The open Ledger Entry Line: `id`, `entryId`, `accountId`, `entityId`, `functionalAmount`, `side`, `partnerId`, `transactionCurrency`, `transactionAmount`, `transactionFxRate`, `openAmount` (remaining unsettled amount, nullable), `createdAt`, `updatedAt`. |
| `entry` | object | `{ id, entryDate, memo }` of the entry the line belongs to. |
| `account` | object | `{ id, code, name }` of the Ledger Account the line sits on. |
| `partner` | object \| null | `{ id, name, legalName, taxId }` when the line names a Partner. |
| `invoice` | object \| null | `{ id, documentNumber, issueDate }` when the line is an Invoice's control line. |

Pass the candidate's `line.id` as `lineId` to `POST /movements/:movementId/match`.

## GET `/movements/:movementId/reconciliation`

Return the Movement's current booking or match state and the Ledger Lines that discharge it. Only a booked or matched Movement has one.

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `entry` | object | The booking Ledger Entry: `id`, `entityId`, `entryDate`, `memo`, `notes`, `status` (`active` \| `deleted` \| `reversed` \| `scheduled` \| `cancelled`), `reversalOfEntryId`, `createdAt`, `updatedAt`, plus `lines` and `allocations`. |
| `entry.lines[]` | array | Every line of the entry, each with the line fields above plus `accountCode`, `accountName`, `accountType`, `partnerName`, and `lineDimensionValues[]` (`{ dimensionId, dimensionValueId, dimensionName, dimensionValueCode, dimensionValueName }`). |
| `entry.allocations[]` | array | Every Allocation the entry's lines take part in: `id`, `entityId`, `debitLineId`, `creditLineId`, `accountId`, `amount`, `createdAt`, `updatedAt`, and `counterpart` (`{ lineId, entryId, entryMemo, accountId, partnerId, accountCode, accountName, partnerName }`). |
| `controlLine` | object \| null | The open-item counterpart line of the booking, with `openAmount`. `null` when the booking touches no open-item account. |
| `settledAllocations[]` | array | Allocations the control line settles. Same shape as `entry.allocations[]`, with `counterpart.entryDate` and `counterpart.invoiceDocumentNumber` (nullable) added. |

## POST `/movements`

Create a manual Bank Movement on the account. Requires `x-audit-actor` for API-key callers.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id. Retrying the same `POST` with the same id is rejected with `409` instead of creating a duplicate. |
| `movementDate` | string (`YYYY-MM-DD`) | Yes | Date of the Movement. |
| `amount` | integer | Yes | Magnitude in minor units, `0` or greater. |
| `side` | `debit` \| `credit` | Yes | Direction against the Bank Account's mapped Ledger Account. |
| `description` | string | Yes | Non-empty description. |
| `externalRef` | string \| null | No | Bank reference. Must be unique on the Bank Account when present. |

```bash
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "3f1c2a2e-0d1b-4c6f-9a8e-5b7d2e1f0a11",
```

## POST `/movements/bulk`

Create up to 100 Movements on the Bank Account in a single request and transaction. Each element carries its own client-supplied `id` (required and unique within the batch) so a retry collides on the primary key rather than double-inserting.

- **Body:** `BulkCreateBankMovementDto` — `{ movements: CreateBankMovement[] }` (1 to 100 elements).
- **Response:** array of `createBankMovementResultSchema`, in input order.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$BANK_ACCOUNT_ID/movements/bulk" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "movements": [ /* CreateBankMovement, up to 100 */ ] }'
```

<Note>
  The bulk routes are declared before `:movementId` in the controller so Nest does not read `bulk`, `book`, or `match` as a movement id. Match that ordering when composing URLs.
</Note>

## POST `/movements/book`

Book up to 100 already-created Movements in a single transaction. Each element carries a `movementId` plus the booking instructions used by the single-movement endpoint.

- **Body:** `BulkBookBankMovementDto` — `{ bookings: (BookBankMovement & { movementId })[] }` (1 to 100 elements).
- **Response:** array of `reconcileBankMovementResultSchema`, in input order.

## POST `/movements/match`

Match up to 100 already-created Movements to existing documents in a single transaction. Each element carries a `movementId` plus the match instructions used by the single-movement endpoint.

- **Body:** `BulkMatchBankMovementDto` — `{ matches: (MatchBankMovement & { movementId })[] }` (1 to 100 elements).
- **Response:** array of `reconcileBankMovementResultSchema`, in input order.

<Info>
  Bulk endpoints run as one database transaction. If any element fails validation or a domain rule, the whole batch is rejected and the response identifies the offending element by its zero-based `elementIndex` (`bulkElementFailureSchema`).
</Info>

## PATCH `/movements/:movementId`

Edit an existing Movement (for example, correct a description or counterparty).

**Body:** any subset of the create fields except `id`. Every field is editable while the Movement is unbooked; once booked or matched, only `partnerId` and `metadata` may change.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `movementDate` | string (`YYYY-MM-DD`) | No | Unbooked only. |
| `amount` | integer | No | Unbooked only. Minor units, `0` or greater. |
| `side` | `debit` \| `credit` | No | Unbooked only. |
| `description` | string | No | Unbooked only. Non-empty. |
| `externalRef` | string \| null | No | Unbooked only. |
| `partnerId` | uuid \| null | No | `null` clears the Partner. |
| `metadata` | array of `{ label, value }` | No | Replaces the whole list. |

**Response:** `{ movement, bankAccount }`.

```bash
curl -X PATCH "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$BANK_ACCOUNT_ID/movements/$MOVEMENT_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "partnerId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d" }'
```

## DELETE `/movements/:movementId`

Remove a Movement. Booked or matched Movements are refused; unbook or unmatch first.

**Response:** `{ movementId, bankAccount }`, the id of the deleted Movement and the Bank Account with its refreshed summary.

## POST `/movements/:movementId/book`

Book a Movement to a Ledger Entry. Sintropix generates the balanced Ledger Entry from the Movement plus the booking instructions in the body. You supply the entry header and the counterpart lines; the bank line on the Bank Account's mapped Ledger Account is built for you, so it can never be on the wrong side or for the wrong amount.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id of the Ledger Entry to create. |
| `entryDate` | string (`YYYY-MM-DD`) | Yes | Entry date. |
| `memo` | string \| null | Yes | Entry memo. Pass `null` for none. |
| `notes` | string \| null | No | Free-text notes. Blank is stored as `null`. |
| `bookId` | uuid \| null | Conditional | Book the entry counts in; `null` marks it common. Send (as an id or as `null`) when the Entity has at least one Book; omit otherwise. |
| `movementPartnerId` | uuid \| null | No | Set the Movement's Partner in the same write. Omit to keep the current Partner; `null` clears it. |
| `newCounterpartLines` | array of line objects | Yes | At least one counterpart line (see below). |
| `bankLineFxRate` | decimal string | Conditional | FX rate for the generated bank line. Required exactly when the Bank Account's currency differs from the Entity's functional currency; omit otherwise. |

**Counterpart line object**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | uuid | Yes | Ledger Account to post to. |
| `functionalAmount` | integer | Yes | Amount in the functional currency's minor units, `0` or greater. |
| `side` | `debit` \| `credit` | Yes | Line side. |
| `partnerId` | uuid \| null | No | Counterparty on this line. |
| `transactionCurrency` | string \| null | No | ISO 4217 code of a foreign-currency line. |
| `transactionAmount` | integer \| null | No | Amount in that currency's minor units. |
| `transactionFxRate` | decimal string \| null | No | Rate used, as a decimal string such as `"943.25"`. `transactionCurrency`, `transactionAmount`, and `transactionFxRate` must be given together or not at all. |
| `dimensionValueIds` | array of uuid | No | Dimension Values to tag the line with. Default `[]`. |

**Response:** `{ movement, bankAccount, reconciliation }`, where `reconciliation` has the same shape as `GET /movements/:movementId/reconciliation`.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$BANK_ACCOUNT_ID/movements/$MOVEMENT_ID/book" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "7d8e9f0a-1b2c-4d3e-8f4a-5b6c7d8e9f0a",
    "entryDate": "2025-12-30",
    "memo": "Consulting fee from Acme SpA",

    "newCounterpartLines": [
      {
        "accountId": "4e5f6a7b-8c9d-4e0f-a1b2-c3d4e5f6a7b8",
        "functionalAmount": 1250000,
        "side": "credit",
        "partnerId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d",
        "dimensionValueIds": []
      }
    ]
  }'
```

## POST `/movements/:movementId/match`

Match a Movement to an existing document (Invoice or Ledger Entry) rather than booking a new entry. Sintropix records an Allocation between the Movement's counter-account line and the matched document's open-item line.

**Body:** the same fields as `POST /book` without `movementPartnerId`, plus the line to settle:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id of the Ledger Entry to create. |
| `entryDate` | string (`YYYY-MM-DD`) | Yes | Entry date. |
| `memo` | string \| null | Yes | Entry memo. Pass `null` for none. |
| `notes` | string \| null | No | Free-text notes. |
| `bookId` | uuid \| null | Conditional | Same rule as `POST /book`. The Book of the entry must match the Book of the line being settled. |
| `newCounterpartLines` | array of line objects | Yes | At least one line. Include the settlement line on the open-item account (and any realized-FX line); the allocation is sized from it. |
| `bankLineFxRate` | decimal string | Conditional | Same rule as `POST /book`. |
| `lineId` | uuid | Yes | The open Ledger Entry Line to settle, for example `candidates[].line.id` from `GET /match-candidates`. To match an Invoice, pass its control line. |

**Response:** `{ movement, bankAccount, reconciliation }`.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$BANK_ACCOUNT_ID/movements/$MOVEMENT_ID/match" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "9a0b1c2d-3e4f-4a5b-8c6d-7e8f9a0b1c2d",
    "entryDate": "2025-12-30",
    "memo": "Payment of invoice 1042",
    "lineId": "5b6c7d8e-9f0a-4b1c-8d2e-3f4a5b6c7d8e",
    "newCounterpartLines": [
      {
        "accountId": "2c3d4e5f-6a7b-4c8d-9e0f-1a2b3c4d5e6f",
        "functionalAmount": 1250000,
        "side": "credit",
        "partnerId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d"
      }
    ]
  }'
```

## Record an internal transfer

An Internal Transfer moves money between two Bank Accounts of the same Entity, for example from checking to savings or through a currency conversion. It is never income or expense. There is no dedicated transfer endpoint. You record a transfer with `POST /book` and an Allocation.

Each leg of the transfer passes through a bridge account. A bridge account is an open-item Ledger Account with sub-type `internal_transfer` (see [Chart of Accounts](/api-reference/chart-of-accounts)). An open line on the bridge account is money in transit. The Allocation that joins the two bridge lines shows that both legs arrived.

1. Book each leg with `POST /movements/:movementId/book`. Put one counterpart line on the bridge account, on the side opposite to the bank line. Add extra lines, such as a bank fee or realized FX, as needed. The Entry must balance. Keep the id of the bridge line from the response.
2. Join the two bridge lines with an Allocation, in one of two ways:
   - Call [Match Lines](/api-reference/allocations) (`POST /api/entities/:entityId/ledger/allocations/match`) with the two bridge line ids in `lineIds`. Use this for cross-currency transfers.
   - Book only the first leg, then call `POST /movements/:movementId/match` on the second Movement with `lineId` set to the open bridge line. The settlement line and the bridge line must have the same currency.

Give both bridge lines the same functional amount. Sintropix does not refuse unequal bridge lines. The Allocation takes the smaller amount, and the difference stays as an Open Amount on the bridge account. If only one leg has arrived, book it and leave its bridge line open until the other leg arrives.

```bash
# Leg A: money out of checking, into the bridge account
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$CHECKING_ID/movements/$MOVEMENT_A_ID/book" \
  -H "x-api-key: $SINTROPIX_API_KEY" \

  -d '{
    "id": "0c1d2e3f-4a5b-4c6d-8e7f-8a9b0c1d2e3f",
    "entryDate": "2025-12-30",
    "memo": "Transfer to savings",
    "newCounterpartLines": [
      { "accountId": "6d7e8f9a-0b1c-4d2e-8f3a-4b5c6d7e8f9a", "functionalAmount": 150000, "side": "debit" }
    ]
  }'

# Leg B: money into savings, out of the bridge account
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-accounts/$SAVINGS_ID/movements/$MOVEMENT_B_ID/book" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "1d2e3f4a-5b6c-4d7e-8f8a-9b0c1d2e3f4a",
    "entryDate": "2025-12-30",
    "memo": "Transfer from checking",
    "newCounterpartLines": [
      { "accountId": "6d7e8f9a-0b1c-4d2e-8f3a-4b5c6d7e8f9a", "functionalAmount": 150000, "side": "credit" }
    ]
  }'

# Join the two bridge lines taken from the book responses
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/allocations/match" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "lineIds": ["'"$BRIDGE_LINE_A_ID"'", "'"$BRIDGE_LINE_B_ID"'"] }'
```

## POST `/api/entities/:entityId/bank-movements/:movementId/comments`

Post a Comment on a Bank Movement. The author is taken from the session; the Comment appears in the Movement's [audit trail](/api-reference/audit-trail) alongside every other change, and inside the Movement panel of the app. Comments cannot be edited or deleted, and there is no `GET` for them: read them through the audit trail of the host Movement.

<Note>
  This route is nested directly under the Entity, not under a Bank Account. `movementId` alone identifies the Movement.
</Note>

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `body` | string | Yes | Free text. Trimmed, non-empty after trim, up to 4,000 characters. Line breaks are preserved. |

**Response** (`201`): the created Comment.

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Comment id. |
| `entityId` | uuid | Owning Entity. |
| `authorUserId` | uuid | User the session belonged to. |
| `body` | string | The text that was posted. |
| `bankMovementId` | uuid | The Movement the Comment belongs to. |
| `invoiceId` | null | Always null on this route. |
| `ledgerEntryId` | null | Always null on this route. |
| `createdAt`, `updatedAt` | ISO 8601 timestamp | Row timestamps. |

**Domain errors**

| Code | Status | Meaning |
| --- | --- | --- |
| `COMMENT_HOST_NOT_FOUND_ERROR` | `404` | The Bank Movement in the URL does not exist under this Entity. The response carries `params: { hostKind: "bank_movement", hostId }`. |

Bodies longer than 4,000 characters, or blank after trimming, are rejected with `400` before the Comment reaches the database.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/bank-movements/$MOVEMENT_ID/comments" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "body": "Cargo bancario correspondiente al proveedor Acme." }'
```

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success (`GET`, `PATCH`, `DELETE`, and `POST` actions on an existing Movement). |
| `201` | Movement or Comment created. |
| `400` | Validation error, or missing `x-audit-actor` on a key call. |
| `403` | Read-only key attempted a mutation. |
| `404` | Entity, Bank Account, or Movement not found. |
| `409` | Domain conflict (already booked, already matched, duplicate `id` or `externalRef`, and so on). |
