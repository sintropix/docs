The Chart of Accounts is the full tree of Account Groups and Ledger Accounts for an Entity. You build it one group and one account at a time, and read the whole chart in one call. This page also covers the Ledger Account endpoints under `entities/:entityId/ledger/accounts`, and the [group chart](#the-group-chart) that the Organization shares across its Entities.

## The group chart

The Organization owns one flat group chart. It is a list of Group Accounts (**Cuentas de grupo**), each with a code, a name, and a type. Every Ledger Account of every Entity of the Organization maps to exactly one Group Account of its own type. Because the mapping is total, the group chart adds up the books of every Entity by construction.

- A Group Account code is unique in the Organization.
- A Ledger Account names its Group Account in `groupAccountId` when you [create](#post-/api/entities/entityid/ledger/accounts) it. You can't create one without it.
- To map a Ledger Account to another Group Account, `PATCH` it with a new `groupAccountId`.
- A Ledger Account that changes `type` must name a Group Account of the new type in the same request.
- You can always change a Group Account's code and name. Its type can't change, and it can't be deleted, while a Ledger Account maps to it.
- An Entity that has Ledger Accounts can't [move to another Organization](/api-reference/entities#patch-/api/entities/entityid/organization).

In the app, **Plan de cuentas** lives in the Organization's settings. It opens on **Grupo**, which lists each Group Account with the Ledger Accounts of each Entity nested under it. Pick an Entity in the switcher to see its own chart, with a **Cuenta de grupo** column. Pick the Organization's own row, with its logo and name, to go back to the group chart.

The group chart routes live under the Organization, not under an Entity. Read the `organizationId` from the [Entity](/api-reference/entities#response-shape). They need the `books` permission in the Organization: `books` read for `GET`, `books` write for the other methods. An API key confined to one Entity can call them for that Entity's Organization, and the listing shows only that Entity's Ledger Accounts.

## GET /api/organizations/:organizationId/group-accounts

List the Group Accounts of the Organization, ordered by code. Each one carries the Ledger Accounts that map to it.

- **Path param:** `organizationId` (UUID)
- **Success response:** array of Group Account objects, each with a `ledgerAccounts` array
- **Status:** 200

Each item of `ledgerAccounts` carries `id`, `entityId`, `code`, and `name`, ordered by code.

```json
    "type": "asset",
    "createdAt": "2026-02-01T12:00:00.000Z",
    "updatedAt": "2026-02-01T12:00:00.000Z",
    "ledgerAccounts": [
      {
        "id": "33333333-3333-4333-8333-333333333333",
        "entityId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",

        "name": "Caja"
      },
      {
```

## POST /api/organizations/:organizationId/group-accounts

Create a Group Account.

- **Path param:** `organizationId` (UUID)
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | UUID | Yes | Client-supplied idempotency id |
| `code` | string | Yes | Code, non-empty and unique in the Organization |
| `name` | string | Yes | Name, non-empty |

- **Success response:** the created Group Account object
- **Status:** 201

```bash
curl -X POST https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/group-accounts \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
```

## PATCH /api/organizations/:organizationId/group-accounts/:groupAccountId

Rename, recode, or retype a Group Account. Send at least one field. The new code and name show on every Ledger Account that maps to it.

- **Path params:** `organizationId` (UUID), `groupAccountId` (UUID)
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `code` | string | No | New code, unique in the Organization |
| `name` | string | No | New name |
| `type` | enum | No | New type. Refused while a Ledger Account maps to the Group Account |

- **Success response:** the updated Group Account object
- **Status:** 200

```bash
curl -X PATCH https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/group-accounts/$GROUP_ACCOUNT_ID \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"name": "Caja y fondos fijos"}'
```

## DELETE /api/organizations/:organizationId/group-accounts/:groupAccountId

```bash

```

- **Path params:** `entityId` (UUID), `accountId` (UUID)

| `tracking` | enum | No | `balance` or `open_item` |
| `subtype` | enum or null | No | `fixed_asset`, `receivable`, `unbilled_receivable`, `payable`, `internal_transfer`, `migration_clearing`, `suspense`, `cash`, `prepaid_expense`, `deferred_revenue`, `expense_rendition_payable`, `retained_earnings`, or null to clear (transition rules apply) |

### Sub-type changes on an account with entries

While an account has entries (`hasEntries` is `true`), its sub-type follows these rules:

- An account with no sub-type can still take one.
- A stated sub-type can switch between `payable` (**Por pagar**) and `expense_rendition_payable` (**Rendición por pagar**), in either direction. A `payable` Invoice takes either one as its control account, so the lines already posted keep their meaning.
- Every other change of a stated sub-type, including clearing it to `null`, is refused with `409` and `LEDGER_ACCOUNT_SUBTYPE_LOCKED_ERROR`.
- An account that a record pins keeps its sub-type even within the pair. For example, while the [Expense Claim setting](/api-reference/expense-claims#before-you-submit-claims) names an account, changing its sub-type is refused with `409` and `LEDGER_ACCOUNT_FACT_PINNED_ERROR`.

A switch changes only the sub-type. The account's lines, open items, and Matches stay as they are, and its open lines stay in the payables [open positions](/api-reference/reports#open-positions-receivables-and-payables) and the payable total of the home dashboard.

<Warning>
  A switch changes the [default cash flow category](#cash-flow-categories) of an account whose `cashFlowCategory` is `null`: `payable` defaults to `supplier_payments`, and `expense_rendition_payable` to `employee_payments`. The cash flow statement then reports the account's cash under the new category in every period, past periods included. To keep the old category, set `cashFlowCategory` explicitly.
</Warning>

Use the switch when the Entity already books renditions into a `payable` account, such as *Rendiciones por pagar*, and you want the [Expense Claim setting](/api-reference/expense-claims#before-you-submit-claims) to name it as its **Rendición por pagar** account:

```bash
curl -X PATCH https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts/$ACCOUNT_ID \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"subtype": "expense_rendition_payable"}'
```

In the app, **Editar cuenta** on an account with entries offers only **Por pagar** and **Rendición por pagar** when the account has one of them, and explains why. For any other sub-type, the **Subtipo** field is locked.

### Cash Accounts

The sub-type `cash` marks a Cash Account: an account that holds cash, such as a bank current account or petty cash. The [cash flow statement](/api-reference/reports#cash-flow-statement) reads the entries that post to Cash Accounts, and its closing cash equals their balance.

To mark an account as a Cash Account, create it or `PATCH` it with `type: "asset"`, `tracking: "balance"`, and `subtype: "cash"`. These rules apply:

- Only an `asset` account with `balance` tracking can take the sub-type. Another type is refused with `LEDGER_ACCOUNT_SUBTYPE_TYPE_INCOMPATIBLE_ERROR`, and `open_item` tracking with `LEDGER_ACCOUNT_SUBTYPE_TRACKING_INCOMPATIBLE_ERROR`.
- A [Bank Account](/api-reference/bank-accounts) of kind `bank` must map to a Cash Account.
- While a Bank Account of kind `bank` maps the account, removing or changing its sub-type returns `LEDGER_ACCOUNT_FACT_PINNED_ERROR`. Delete the Bank Account first.

### Cash flow categories

Every account can carry a `cashFlowCategory`. It decides where the [cash flow statement](/api-reference/reports#cash-flow-statement) shows the cash that an entry moves on the account. A category never changes a posted amount, so you can set, change, or clear it at any time.

| Activity | Categories |
| --- | --- |
| Operating | `customer_receipts`, `supplier_payments`, `employee_payments`, `taxes`, `other_operating` |
| Investing | `fixed_assets`, `other_investing` |
| Financing | `borrowings`, `interest`, `dividends`, `equity_contributions` |

While `cashFlowCategory` is `null`, the account uses `defaultCashFlowCategory`, taken from its sub-type first and then from its type:

| Account | Default category |
| --- | --- |
| Sub-type `receivable`, `unbilled_receivable`, or `deferred_revenue` | `customer_receipts` |
| Sub-type `payable` or `prepaid_expense` | `supplier_payments` |
| Sub-type `expense_rendition_payable` | `employee_payments` |
| Sub-type `fixed_asset` | `fixed_assets` |
| Sub-type `retained_earnings` | `equity_contributions` |
| Sub-type `cash`, `internal_transfer`, `migration_clearing`, or `suspense` | None |
| Type `income`, with no sub-type | `customer_receipts` |
| Type `cost_of_goods_sold` or `operating_expense`, with no sub-type | `supplier_payments` |
| Type `other_income` or `other_expense`, with no sub-type | `other_operating` |
| Type `equity`, with no sub-type | `equity_contributions` |
| Type `asset` or `liability`, with no sub-type | None |

The statement reports the cash of an account with no category and no default under `unclassified`. For example, set `borrowings` on a bank loan account to report its drawdowns and repayments as financing:

```bash
curl -X PATCH https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts/$ACCOUNT_ID \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"cashFlowCategory": "borrowings"}'
```

### The Suspense Account

The sub-type `suspense` marks the Entity's Suspense Account. When a [bank Match](/api-reference/bank-movements#overpayments-and-the-suspense-account) pays more than the target's Open Amount, Sintropix books the rest there until you assign it. Without a Suspense Account, a Match that leaves a rest is refused.

To mark an account as the Suspense Account, create it or `PATCH` it with `type: "asset"`, `tracking: "open_item"`, and `subtype: "suspense"`. These rules apply:

- Only an `asset` account can take the sub-type.
- An Entity has at most one Suspense Account. A second one is refused with `LEDGER_ACCOUNT_SUSPENSE_ALREADY_EXISTS_ERROR`.
- An account takes the sub-type only while it has no lines. Otherwise Sintropix returns `LEDGER_ACCOUNT_SUSPENSE_REQUIRES_NO_LINES_ERROR`.
- Only Match, Assign, and Unassign post to it. Manual entries, Reclassify, Scheduled Entries, Bank Account mapping, Booking Templates, and Fixed Asset Classes that name it are refused with `LEDGER_ACCOUNT_SUSPENSE_RESERVED_ERROR`.

### Prepaid expenses and deferred revenue

The sub-types `prepaid_expense` and `deferred_revenue` mark the accounts that hold a [Deferral](/api-reference/invoices#deferrals): an Invoice line whose amount is recognized over several months instead of in the invoice month.

| Sub-type | Use it for | Type | Tracking |
| --- | --- | --- | --- |
| `prepaid_expense` | A cost paid ahead of the months that consume it, such as an annual software subscription. A deferred line of a payable Invoice debits it. | `asset` | `balance` |
| `deferred_revenue` | Revenue billed ahead of the months that earn it, such as a multi-month service. A deferred line of a receivable Invoice credits it. | `liability` | `balance` |

Create the account, or `PATCH` an existing one, with the matching `type`, `tracking: "balance"`, and the sub-type. Another type is refused with `LEDGER_ACCOUNT_SUBTYPE_TYPE_INCOMPATIBLE_ERROR`, and `open_item` tracking with `LEDGER_ACCOUNT_SUBTYPE_TRACKING_INCOMPATIBLE_ERROR`. In the cash flow statement, a prepaid expense account counts by default under `supplier_payments` and a deferred revenue account under `customer_receipts`.

### Expense rendition payable

The sub-type `expense_rendition_payable` (**Rendición por pagar**) marks the account for what the Entity owes the people who paid its expenses with their own money. When an [Expense Claim](/api-reference/expense-claims) is approved, its Expense Rendition credits this account with the person as Partner.

Create the account, or `PATCH` an existing one, with `type: "liability"`, `tracking: "open_item"`, and the sub-type. A `payable` Invoice accepts it as its control account, as it accepts a `payable` account. Its open lines appear in the payables [open positions](/api-reference/reports#open-positions-receivables-and-payables) (**Por pagar**) and in the payable total of the home dashboard. In the cash flow statement, it counts by default under `employee_payments`.

### The retained earnings account

The sub-type `retained_earnings` (**Resultados acumulados**) marks the account that carries the result of every closed [Fiscal Year](/api-reference/reports#the-fiscal-year-in-reports). Income and expense accounts open each Fiscal Year at `0`, and every report adds the result of the earlier years to this account's balance. Sintropix posts no closing entry: the account keeps its own lines, such as a dividend, and the closed results add to them when a report reads it.

Create the account, or `PATCH` an existing one, with `type: "equity"`, `tracking: "balance"`, and `subtype: "retained_earnings"`. These rules apply:

- Only an `equity` account with `balance` tracking can take the sub-type. Another type is refused with `LEDGER_ACCOUNT_SUBTYPE_TYPE_INCOMPATIBLE_ERROR`, and `open_item` tracking with `LEDGER_ACCOUNT_SUBTYPE_TRACKING_INCOMPATIBLE_ERROR`.
- An Entity has at most one retained earnings account. A second one is refused with `409` and `LEDGER_ACCOUNT_RETAINED_EARNINGS_ALREADY_EXISTS_ERROR`.
- An account that already has lines can take the sub-type.
- In the cash flow statement, it counts by default under `equity_contributions`.

Until the Entity has one, the balance sheet and the eight-column balance show the result of the closed years on its own line, **Resultados anteriores pendientes de cierre**.

```bash
curl -X PATCH https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts/$ACCOUNT_ID \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"subtype": "retained_earnings"}'
```

## DELETE /api/entities/:entityId/ledger/accounts/:accountId

Delete a Ledger Account. The account must not be referenced by any Ledger Entry Line, Bank Account, Partner default purchase account, or vendor [Booking Template](/api-reference/partners#booking-templates) line; the `deleteBlockedBy` field of the Chart of Accounts tells you in advance which reference would block the delete.

- **Path params:** `entityId` (UUID), `accountId` (UUID)
- **Success response:**

| Field | Type | Description |
| --- | --- | --- |
| `deletedAccountId` | UUID | Id of the removed account |

- **Status:** 200

```bash
curl -X DELETE https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts/$ACCOUNT_ID \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent"
```
