The FX Rates API exposes the official currency rates Sintropix uses to value foreign-currency amounts. Rates are mirrored as each central bank publishes them. You look up a rate for an Entity, and the Entity's country decides which Rate Source answers. The sync endpoint refreshes the stored rates and is restricted to staff.

## Rate Sources

A **Rate Source** is the fixed set of official rates an Entity reads, one pair at a time. The Entity's country picks it:

| Entity country | Rate Source | `rateSource` |
| --- | --- | --- |
| Chile (`CL`) | Banco Central de Chile | `banco_central_de_chile` |
| Mexico (`MX`) | Banco de México | `banco_de_mexico` |
| Brazil (`BR`) | Banco Central do Brasil | `banco_central_do_brasil` |
| Colombia (`CO`) | Superintendencia Financiera de Colombia | `superintendencia_financiera_de_colombia` |
| United States (`US`), Cayman Islands (`KY`) | Central banks against the dollar | `central_banks_against_usd` |

An Entity in any other country has no Rate Source, so a lookup for it returns `404` with `FX_RATE_SOURCE_NOT_FOUND_ERROR`. Type the rate yourself on the line instead. On a [manual Ledger Entry](/api-reference/ledger-entries#foreign-currency-lines), that means an `overrideFxRate` with its reason.

There is no fallback from one Rate Source to another. If the Entity's Rate Source doesn't include a pair, the lookup returns `404` with `FX_RATE_NOT_FOUND_ERROR`, even when another source has it. For example, a Chilean Entity gets no MXN rate from Banco de México.

### Central banks against the dollar

No US authority publishes a daily rate for the currencies Sintropix values, so an Entity in the United States or the Cayman Islands reads each currency's rate against the dollar from that currency's own central bank:

| Currency | Pair | Publisher | `series` |
| --- | --- | --- | --- |
| EUR | `EUR/USD` | European Central Bank | `euro_foreign_exchange_reference_rate` |
| GBP | `EUR/GBP` | European Central Bank | `euro_foreign_exchange_reference_rate` |
| MXN | `USD/MXN` | Banco de México | `tipo_cambio_fix` |
| CLP | `USD/CLP` | Banco Central de Chile | `dolar_observado` |
| BRL | `USD/BRL` | Banco Central do Brasil | `ptax_venda` |
| COP | `USD/COP` | Superintendencia Financiera de Colombia | `tasa_representativa_del_mercado` |
| KYD | `KYD/USD` | Cayman Islands Monetary Authority | `cayman_dollar_value` |

GBP is read through the euro, so a GBP amount in a USD Entity uses `EUR/USD` and `EUR/GBP`. These are the only pairs this Rate Source includes. PEN and ARS aren't included yet, so a lookup for them returns `404` with `FX_RATE_NOT_FOUND_ERROR`, and you type the rate: on a manual Ledger Entry, as an `overrideFxRate` with its reason. An Entity that keeps its books in KYD can't get a GBP rate, because the link would need three pairs.

For USD/MXN, a US or Cayman Entity reads the Banco de México's FIX, the spot rate of its day. A Mexican Entity keeps the rate for settling obligations (`tipo_cambio_solventar_obligaciones`), as Mexican law requires.

### Superintendencia Financiera de Colombia

The Superintendencia Financiera de Colombia certifies only the dollar's rate in pesos, the Tasa Representativa del Mercado (TRM). Colombian tax rules convert every other currency to dollars first, so an Entity in Colombia reads the TRM for `USD/COP` and each other currency's rate against the dollar from that currency's own central bank, the same entries as the [central banks against the dollar](#central-banks-against-the-dollar):

| Currency | Pair | Publisher | `series` |
| --- | --- | --- | --- |
| USD | `USD/COP` | Superintendencia Financiera de Colombia | `tasa_representativa_del_mercado` |
| EUR | `EUR/USD` | European Central Bank | `euro_foreign_exchange_reference_rate` |
| MXN | `USD/MXN` | Banco de México | `tipo_cambio_fix` |
| CLP | `USD/CLP` | Banco Central de Chile | `dolar_observado` |
| BRL | `USD/BRL` | Banco Central do Brasil | `ptax_venda` |
| KYD | `KYD/USD` | Cayman Islands Monetary Authority | `cayman_dollar_value` |

A COP Entity values any currency other than USD in two legs through the dollar. For example, a EUR amount uses `EUR/USD` from the European Central Bank, then the TRM. These are the only pairs this Rate Source includes:

- GBP isn't included, because it would need three pairs (`EUR/GBP`, `EUR/USD`, and the TRM).
- PEN and ARS aren't included yet.

A lookup for any of them returns `404` with `FX_RATE_NOT_FOUND_ERROR`, and its `params` name the Rate Source, the currencies, and the date. Type the rate yourself: on a manual Ledger Entry, as an `overrideFxRate` with its reason.

### Rate series

Each stored rate comes from one series, named in the rate's `series`. A series has one publisher, and it can serve more than one Rate Source:

| Publisher | Pair | `series` | Rate Sources |
| --- | --- | --- | --- |
| Banco Central de Chile | `USD/CLP` | `dolar_observado` | `banco_central_de_chile`, `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |
| Banco Central de Chile | `EUR/CLP`, `GBP/CLP` | `tipo_cambio_observado` | `banco_central_de_chile` |
| Banco Central de Chile | `MXN/CLP`, `COP/CLP`, `ARS/CLP`, `BRL/CLP`, `PEN/CLP` | `tipo_cambio_referencial` | `banco_central_de_chile` |
| Banco de México | `USD/MXN` | `tipo_cambio_solventar_obligaciones` | `banco_de_mexico` |
| Banco de México | `EUR/USD`, `GBP/USD`, `CLP/USD`, `PEN/USD`, `COP/USD`, `BRL/USD`, `ARS/USD` | `equivalencia_monedas_dolar` | `banco_de_mexico` |
| Banco de México | `USD/MXN` | `tipo_cambio_fix` | `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |
| Banco Central do Brasil | `USD/BRL` | `ptax_venda` | `banco_central_do_brasil`, `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |
| Banco Central do Brasil | `EUR/BRL`, `GBP/BRL`, `CLP/BRL`, `MXN/BRL`, `PEN/BRL`, `COP/BRL`, `ARS/BRL`, `KYD/BRL` | `ptax_venda` | `banco_central_do_brasil` |
| European Central Bank | `EUR/USD` | `euro_foreign_exchange_reference_rate` | `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |
| European Central Bank | `EUR/GBP` | `euro_foreign_exchange_reference_rate` | `central_banks_against_usd` |
| Superintendencia Financiera de Colombia | `USD/COP` | `tasa_representativa_del_mercado` | `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |
| Cayman Islands Monetary Authority | `KYD/USD` | `cayman_dollar_value` | `superintendencia_financiera_de_colombia`, `central_banks_against_usd` |

`ptax_venda` is the sell rate (venda) of the Banco Central do Brasil's daily PTAX closing. The buy rate isn't stored.

A rate's `rateDate` is the day the series dates the value for:

- **Banco Central de Chile:** the publication date.
- **`tipo_cambio_solventar_obligaciones`:** the day the rate applies, which is the day after Banco de México publishes it in the Diario Oficial de la Federación (DOF). Rates for the coming days are available ahead of time.
- **`equivalencia_monedas_dolar`:** the day the DOF publishes the monthly table of each currency's equivalence to the dollar. A lookup uses that table until the next one is published.
- **`tipo_cambio_fix`:** the day Banco de México determines the FIX.
- **`ptax_venda`:** the business day of the PTAX closing. The Banco Central do Brasil publishes it around 13:10 Brasília time, so earlier in the day a lookup for today answers the previous business day. Weekends and Brazilian holidays have no PTAX, so a lookup for one of those days answers the last business day before it.
- **`euro_foreign_exchange_reference_rate`:** the day the European Central Bank publishes the reference rate, around 16:00 Frankfurt time. Days without a reference rate answer the last day before them.
- **`tasa_representativa_del_mercado`:** the first day the TRM is valid. The TRM computed from one business day's trades is valid from the next day, and the Superintendencia Financiera de Colombia publishes it the evening before, so the rate for tomorrow is available ahead of time. A Friday's TRM stays valid through the weekend and any holidays after it, so a lookup for one of those days answers that TRM. A lookup never uses a TRM dated after the day it values.
- **`cayman_dollar_value`:** `1974-04-01`, the date the fixed value of 1.20 US dollars per Cayman dollar applies from. A new official value would be a new rate with its own date.

Rates are stored with the decimals the Rate Source publishes. Banco Central de Chile publishes at most two decimals, so for currencies worth less than one Chilean peso, such as COP and ARS, the rate is below one (for example `"0.24"`), and the published rounding carries through to the converted amount. The Banco Central do Brasil publishes eight decimals, and trailing zeros are dropped, so a published `5,58400000` is stored as `"5.584"`. Every rate is per one unit of the base currency.

### How a lookup links two currencies

A lookup links the transaction currency to the Entity's functional currency with rates from the Entity's Rate Source only:

- **Direct:** one stored pair, for example `USD/CLP` for a USD amount in a CLP Entity.
- **Inverted:** one stored pair read the other way, for example `USD/CLP` divided out to value CLP in a Chilean Entity that keeps its books in USD.
- **Through one other currency:** two stored pairs, for example `EUR/USD` then `USD/MXN` for a EUR amount in a Mexican MXN Entity. The two pairs can come from different publishers within the same Rate Source, for example `EUR/USD` from the European Central Bank and `KYD/USD` from the Cayman Islands Monetary Authority for a EUR amount in a KYD Entity.

The answer names each stored rate it used in `legs`, and its `rateDate` is the oldest `rateDate` among them. So an answer that goes through `KYD/USD`, such as EUR for an Entity that keeps its books in KYD, has `rateDate` `1974-04-01`. A direct rate is the published value, digit for digit. A rate through two pairs keeps every digit of their product, and an inverted rate is rounded to 20 decimals. A lookup where the transaction currency is the functional currency has no rate and returns `404`.

In the app, the rate field of an Invoice and a Movement's reconciliation is prefilled with the Entity's rate. The hint under the field names the series and date of each rate it used, for example **PTAX venda** for a Brazilian Entity, **TRM vigente desde el** and the date for a Colombian Entity, or the ECB reference rate for EUR in a US Entity. When there is no rate, the field shows why, and you type the rate.

A manual entry line has no rate field. Sintropix [values the line](/api-reference/ledger-entries#foreign-currency-lines) at the Entity's rate on the Entry Date, and the line shows that rate with its date and series. To use another rate, choose **Usar otro tipo de cambio** and give its reason.

## The FX Rate object

One stored rate, as its Rate Source publishes it.

| Field | Type | Description |
| --- | --- | --- |
| `baseCurrency` | string | ISO 4217 code of the base currency, for example `USD`. |
| `quoteCurrency` | string | ISO 4217 code of the quote currency, for example `CLP`. |
| `rateDate` | string (`YYYY-MM-DD`) | The day the series dates the rate for. See [Rate series](#rate-series). |
| `rate` | decimal string | One major unit of `baseCurrency` equals `rate` major units of `quoteCurrency`, for example `"943.25"`, or `"0.24"` for `COP/CLP`. Always a string, never a float. |
| `series` | `dolar_observado` \| `tipo_cambio_observado` \| `tipo_cambio_referencial` \| `tipo_cambio_solventar_obligaciones` \| `equivalencia_monedas_dolar` \| `ptax_venda` \| `tipo_cambio_fix` \| `euro_foreign_exchange_reference_rate` \| `cayman_dollar_value` \| `tasa_representativa_del_mercado` | Which series the rate came from. |
| `createdAt` | ISO 8601 timestamp | When the rate was stored. |

## GET `/entities/:entityId/fx-rate`

Return the rate that values one unit of a transaction currency in the Entity's functional currency on a given date. The `date` is the date being valued (an Invoice's issue date, for example), not necessarily a `rateDate`: the answer uses the most recent rates dated on or before it.

The route is an Entity route, so you need access to the Entity.

**Query parameters**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `transactionCurrency` | string | Yes | Currency of the amount to value, for example `USD`. |
| `date` | string (`YYYY-MM-DD`) | Yes | The date to value. |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `transactionCurrency` | string | The requested currency. |
| `functionalCurrency` | string | The Entity's functional currency. |
| `rate` | decimal string | One unit of `transactionCurrency` equals `rate` units of `functionalCurrency`. Use it as the `transactionFxRate` of an Invoice or bank line. A [manual Ledger Entry](/api-reference/ledger-entries#foreign-currency-lines) takes no rate: Sintropix values its foreign lines at this rate. |
| `rateDate` | string (`YYYY-MM-DD`) | The oldest `rateDate` among `legs`. |
| `rateSource` | `banco_central_de_chile` \| `banco_de_mexico` \| `banco_central_do_brasil` \| `superintendencia_financiera_de_colombia` \| `central_banks_against_usd` | The Entity's Rate Source. |
| `legs` | array | The one or two stored rates the answer used, in order. Each has `baseCurrency`, `quoteCurrency`, `rateDate`, `rate`, and `series` as in [the FX Rate object](#the-fx-rate-object), and `inverted`: `true` when the lookup divided by the rate instead of multiplying. |

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/fx-rate?transactionCurrency=EUR&date=2026-11-10" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

For a Mexican Entity that keeps its books in MXN, EUR goes through the dollar:

```json
{
  "transactionCurrency": "EUR",
  "functionalCurrency": "MXN",
  "rate": "21.40126292",
  "rateDate": "2026-11-03",
  "rateSource": "banco_de_mexico",
  "legs": [
    { "baseCurrency": "EUR", "quoteCurrency": "USD", "rateDate": "2026-11-03", "rate": "1.1563", "series": "equivalencia_monedas_dolar", "inverted": false },
    { "baseCurrency": "USD", "quoteCurrency": "MXN", "rateDate": "2026-11-10", "rate": "18.5084", "series": "tipo_cambio_solventar_obligaciones", "inverted": false }
  ]
}
```

**Errors**

A refusal answers `404` with a `code` and `params` you can show to the reader:

| Code | When | `params` |
| --- | --- | --- |
| `FX_RATE_SOURCE_NOT_FOUND_ERROR` | The Entity's country has no Rate Source. | `entityId`, `country`, `transactionCurrency`, `functionalCurrency`, `date` |
| `FX_RATE_NOT_FOUND_ERROR` | The Entity's Rate Source links no rate for the pair on or before `date`, the pair is outside the Rate Source, or `transactionCurrency` is the functional currency. | `rateSource`, `transactionCurrency`, `functionalCurrency`, `date` |

```json
{
  "statusCode": 404,
  "code": "FX_RATE_NOT_FOUND_ERROR",
  "params": {
    "rateSource": "banco_central_de_chile",
    "transactionCurrency": "KYD",
    "functionalCurrency": "CLP",
    "date": "2026-11-10"
  },
  "requestId": "..."
}
```

## GET `/fx-rates/recent`

List the most recent rates of one Rate Source: up to 100 rates, newest `rateDate` first. This route is Entity-independent.

**Query parameters**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `rateSource` | `banco_central_de_chile` \| `banco_de_mexico` \| `banco_central_do_brasil` \| `superintendencia_financiera_de_colombia` \| `central_banks_against_usd` | Yes | The Rate Source to list. |

- **Response:** array of FX Rate objects.

```bash
curl "https://api.sintropix.com/api/fx-rates/recent?rateSource=banco_de_mexico" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

## GET `/organizations/:organizationId/fx-rates/presentation-rates`

Suggest a presentation rate for each functional currency of some Entities of the Organization, to read them in one presentation currency. Pass the suggestions as `presentationRates` to a [consolidated report](/api-reference/consolidation#scope-currency-and-rates), or use the one for a single Entity in its [reports](/api-reference/reports).

Each functional currency is valued at the Rate Source of the Entities that keep it. The route needs the `books` read permission, so every Role can call it. An API key [confined to one Entity](/guides/api-keys) reads that Entity only.

**Query parameters**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `presentationCurrency` | string | Yes | The currency to present in, for example `USD`. |
| `date` | string (`YYYY-MM-DD`) | Yes | The date to value. |
| `entityIds` | UUID | No | An Entity to include. Repeat the parameter once per Entity. Without it, the route reads every Entity of the Organization you can reach. |

**Response:** an array with one item per functional currency of the Entities, sorted by currency:

| Field | Type | Description |
| --- | --- | --- |
| `functionalCurrency` | string | A functional currency of the Entities. |
| `suggestedRate` | object \| null | The suggestion, or `null` when there is none (see below). |
| `suggestedRate.presentationCurrency` | string | The requested presentation currency. |
| `suggestedRate.functionalCurrency` | string | Same as `functionalCurrency`. |
| `suggestedRate.presentationRate` | decimal string | One unit of the presentation currency equals `presentationRate` units of the functional currency. |
| `suggestedRate.rateDate` | string (`YYYY-MM-DD`) | The oldest `rateDate` among the rates it used. |
| `suggestedRate.rateSource` | `banco_central_de_chile` \| `banco_de_mexico` \| `banco_central_do_brasil` \| `superintendencia_financiera_de_colombia` \| `central_banks_against_usd` | The Rate Source it read. |

`suggestedRate` is `null` when:

- the functional currency is the presentation currency;
- the Entities that keep the currency sit under different Rate Sources, for example a Chilean and a Mexican Entity that both keep USD books, so Sintropix doesn't pick one;
- those Entities' country has no Rate Source; or
- their Rate Source links no rate for the pair on or before `date`.

In those cases, type the rate yourself.

## POST `/fx-rates/sync` (staff only)

Force a sync of published rates from every publisher. The response summarizes what was fetched and stored. Every series is fetched independently, so one failing series does not withhold the others.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `startDate` | string (`YYYY-MM-DD`) | No | First `rateDate` to fetch. Must be given together with `endDate`, and be on or before it. |
| `endDate` | string (`YYYY-MM-DD`) | No | Last `rateDate` to fetch. Must be given together with `startDate`. |

A given range applies to every publisher. An empty body (or no body) syncs each publisher's default window:

- **Banco Central de Chile:** the last 10 days ending today, on the Chilean calendar.
- **Banco de México:** the last 10 days ending today, plus the next 7 days, on the Mexico City calendar.
- **Banco Central do Brasil:** the last 10 days ending today, on the São Paulo calendar.
- **European Central Bank:** the last 10 days ending today, on the Frankfurt calendar.
- **Superintendencia Financiera de Colombia:** the last 10 days ending today, plus the next 7 days, on the Bogotá calendar.

The value of the Cayman dollar is fixed, so the sync doesn't fetch it.

When a publisher now publishes a different value for a stored rate, the sync replaces the stored value and reports it in `revisedRates`.

**Response:** `{ series: [...] }`, one entry per series and pair, Banco Central de Chile first:

| Field | Type | Description |
| --- | --- | --- |
| `baseCurrency` | string | Base currency of the series. |
| `quoteCurrency` | string | Quote currency of the series. |
| `series` | string | The series, as in [the FX Rate object](#the-fx-rate-object). |
| `fetched` | integer | Rows seen in the window. |
| `inserted` | integer | Rows that were genuinely new. Already-stored rates are not counted. |
| `revisedRates` | array | Stored rates whose value changed, each `{ rateDate, previousRate, rate }`. Empty when none changed. |
| `failureMessage` | string | Present only when the series failed; `fetched` and `inserted` are then `0`. |

- **Status:** `200`.

```bash
curl -X POST "https://api.sintropix.com/api/fx-rates/sync" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "x-audit-reason: Backfill December rates" \
  -H "Content-Type: application/json" \
  -d '{ "startDate": "2025-12-01", "endDate": "2025-12-31" }'
```

```json
{
  "series": [
    { "baseCurrency": "USD", "quoteCurrency": "CLP", "series": "dolar_observado", "fetched": 22, "inserted": 3, "revisedRates": [] },
    { "baseCurrency": "EUR", "quoteCurrency": "CLP", "series": "tipo_cambio_observado", "fetched": 22, "inserted": 3, "revisedRates": [] },
    { "baseCurrency": "MXN", "quoteCurrency": "CLP", "series": "tipo_cambio_referencial", "fetched": 0, "inserted": 0, "revisedRates": [], "failureMessage": "Upstream request timed out" },
    { "baseCurrency": "USD", "quoteCurrency": "MXN", "series": "tipo_cambio_solventar_obligaciones", "fetched": 31, "inserted": 4, "revisedRates": [{ "rateDate": "2025-12-15", "previousRate": "18.1234", "rate": "18.1243" }] }
  ]
}
```

<Note>
  This route requires the `staff` Role in at least one Organization. Other callers receive `403` with `PERMISSION_DENIED_ERROR`.
</Note>

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success. |
| `400` | Validation error on query or body, such as a missing or unknown `rateSource`, or missing `x-audit-actor` or `x-audit-reason` on an API-key sync call. |
| `403` | `POST /sync` called by a User with no `staff` Role in any Organization. |
| `404` | An Entity lookup found no rate (`FX_RATE_NOT_FOUND_ERROR`), or the Entity's country has no Rate Source (`FX_RATE_SOURCE_NOT_FOUND_ERROR`). See [Errors](#errors). |

A sync doesn't fail when a publisher does: a series it can't fetch comes back with `failureMessage` in the `200` response.
