An Integration is a linked external system: the credentials, tokens, and configuration Sintropix stores to reach that system on the Entity's behalf. Every grant to an external account is an Integration, including the banks and payment providers that feed Bank Accounts. Integrations are the credential side. The feeds are the recurring pull jobs that import data through them.

What an Integration can feed depends on its kind:

| Kind | Feeds |
| --- | --- |
| `bsale`, `wasabil`, `sii_mirror` | A [Source](/api-reference/sources), through a [Source Feed](/api-reference/source-feeds) |
| `fintoc`, `plaid`, `global66`, `cardda`, `dlocal`, `mercadopago`, `polar` | One or more [Bank Accounts](/api-reference/bank-accounts), through [bank feeds](/api-reference/bank-feeds) |
| `mercadolibre`, `gmail`, `resend` | Nothing yet |

An Entity can hold more than one Integration at a time (for example, a Bsale document feed alongside a Fintoc bank and a Mercado Pago authorization). Each external account still belongs to a single Entity.

The `fintoc` kind connects a bank login through the [Fintoc](https://fintoc.com) widget. The `global66` kind connects Global66 with a client id, a client secret, and the accounts you name. The `cardda` kind connects a Cardda company with its API key, and the `dlocal` kind connects a dLocal Go merchant with its API key and secret key. Sintropix reads the Provider before it stores the credentials, so credentials that cannot read are refused at connect.

The `plaid` kind connects a US bank through [Plaid](https://plaid.com) Link. Plaid Link shows US banks only, in English, and asks for access to the bank's transactions, with up to 730 days of history. Your bank password goes to Plaid and never reaches Sintropix. It can feed Bank Accounts with the bank's posted transactions. See [`POST /integrations/plaid/link-tokens`](#post-integrations-plaid-link-tokens) and [Bank Feeds](/api-reference/bank-feeds#plaid).

The `mercadopago` kind connects a Mercado Pago account through OAuth. It can feed a Bank Account with the account's available money. See [Bank Feeds](/api-reference/bank-feeds#mercado-pago).

The `gmail` kind connects a Gmail mailbox through Google OAuth. You grant Sintropix read-only Gmail access (the `gmail.readonly` scope). If you clear the Gmail permission on Google's consent screen, Sintropix refuses the connection and stores nothing. An Entity can connect several mailboxes, but each mailbox can belong to only one Entity. Sintropix does not read any email through this Integration yet: you can connect, renew, and disconnect the mailbox only.

The `polar` kind connects a [Polar](https://polar.sh) account through OAuth. You grant Sintropix read-only access to the account's organizations, orders, payments, refunds, disputes, transactions, and payouts. If you clear the transactions or payouts permission on Polar's consent screen, Sintropix refuses the connection and stores nothing. Sign in to Polar as a user with the owner, admin, or finance role in the organization: Polar shows an organization's money to those roles only. It can feed a USD Bank Account with each organization's Polar balance. Sintropix only reads: it never charges, refunds, or withdraws money. See [Bank Feeds](/api-reference/bank-feeds#polar).

The `resend` kind is an email inbox that Sintropix gives the Entity, with an address on `inbox.sintropix.com`. It holds no credential and lands no documents. Staff reads the email the inbox receives through [Email inboxes](#email-inboxes-staff-only).

To connect a bank that no Provider reads, such as a credit card Fintoc can't fetch, store its login as a [Bank Login](#portal-logins). To connect the Getnet merchant portal, store its login as a [Getnet Login](#portal-logins). Neither is an Integration kind, but the app lists them with the Integrations.

The `sii_mirror` kind is the SII Mirror ("SII Espejo") document Provider, and the only SII document Provider. It reads the RCV registers of the Entity's RUT directly from Sintropix's Chilean SII mirror, so it has no credential to paste. You can only connect it on an Entity whose country is Chile. The mirror reads the SII registers every 4 hours, so a document reaches it a few hours after the SII records it.

## The Integration object

The access token is stored encrypted and is never returned on any read.

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Integration id. |
| `entityId` | uuid | Owning Entity. |
| `kind` | `bsale` \| `wasabil` \| `sii_mirror` \| `fintoc` \| `global66` \| `cardda` \| `dlocal` \| `plaid` \| `mercadopago` \| `mercadolibre` \| `gmail` \| `polar` \| `resend` | The external system. |
| `providerRef` | string \| null | The provider's own handle for the connected account (for Bsale, the instance number; for `sii_mirror`, the Entity's RUT; for `fintoc`, the Fintoc Link; for `plaid`, the Plaid Item id; for Mercado Pago and Mercado Libre, the account ID; for `gmail`, the mailbox email address; for `polar`, the email address of the Polar user who granted access; for `resend`, the inbox address). `null` when a document provider could not determine it at connect time. |
| `documentCount` | integer \| null | Number of documents the provider reported when the credential was verified at connect time. `null` for every kind that is not a document integration: the bank kinds, the OAuth authorizations, and `resend`. |
| `institutionName` | string \| null | The bank's display name, as the Provider reports it. Only `fintoc` and `plaid` state it; `null` for every other kind. |
| `holderId` | string \| null | The account holder's tax id (RUT), unformatted, as the Provider reports it. Only `fintoc` and `cardda` state it; `null` for every other kind. |
| `mode` | `test` \| `live` \| null | Whether a `fintoc` or `plaid` Integration runs against the Provider's test or live environment. `null` for every other kind. |
| `sourceFeed` | Source Feed object \| null | The Source Feed that reads through this Integration, in the shape documented on [Source Feeds](/api-reference/source-feeds). `null` when the Integration feeds no Source. |
| `fedBankAccounts` | array | `{ id, name }` of each Bank Account this Integration feeds, in name order. Empty when it feeds none. |
| `createdAt`, `updatedAt` | ISO 8601 timestamp | Row timestamps. |

## POST `/integrations`

Create an Integration by handing Sintropix a provider-issued access token. The token is verified against the provider once, then stored encrypted.

This route connects the document Providers and the bank Providers. Mercado Pago, Mercado Libre, Gmail, and Polar use OAuth and are connected from **Settings → Integrations** in the Sintropix app. You cannot create them through this endpoint. To create a `resend` inbox, use [`POST /integrations/resend`](#post-integrations-resend).

**Body.** The shape depends on `kind`. Every kind takes an `id`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id. Retrying the same `POST` with the same id is rejected instead of creating a duplicate. |
| `kind` | `bsale` \| `wasabil` \| `sii_mirror` \| `fintoc` \| `plaid` \| `global66` \| `cardda` \| `dlocal` | Yes | The external system to link. `mercadopago`, `mercadolibre`, `gmail`, `polar`, and `resend` are not accepted here. |

Each kind adds its own fields:

| Kind | Fields | Description |
| --- | --- | --- |
| `bsale`, `wasabil` | `accessToken` (string) | The provider's API access token. Whitespace is trimmed and must be non-empty. |
| `sii_mirror` | None | Reads Sintropix's SII mirror using the Entity's RUT and takes no credential. |
| `fintoc` | `exchangeToken` (string) | The token the Fintoc widget mints after you [create a link intent](#post-integrations-fintoc-link-intents) and the user completes the widget. |
| `plaid` | `publicToken` (string) | The public token Plaid Link mints after you [create a Link token](#post-integrations-plaid-link-tokens) and the user signs in to the bank. Connecting the same Plaid Item twice is refused with `409`. |
| `global66` | `clientId` (string), `clientSecret` (string), `accounts` (array) | Your Global66 client credentials and at least one account to read. Each account is `{ accountId, currency }`, where `currency` is an ISO 4217 code of three uppercase letters. A currency Sintropix does not know is refused with `INTEGRATION_CURRENCY_UNKNOWN_ERROR` before Global66 is called. |
| `cardda` | `apiKey` (string) | The Cardda API key. It selects the company, and the Integration discovers that company's one CLP wallet. |
| `dlocal` | `apiKey` (string), `secretKey` (string) | The dLocal Go API key and its paired secret key. They name the merchant, and the Integration discovers its one balance. |

For `sii_mirror`, Sintropix verifies at connect time that the Entity's country is Chile and that the mirror already follows the Entity's RUT. The connect is refused otherwise (see [Status codes](#status-codes)).

Credentials the Provider refuses answer `422` with `INTEGRATION_CONNECT_REJECTED_ERROR`. An external account another Integration already holds answers `409` with `INTEGRATION_ACCOUNT_ALREADY_CONNECTED_ERROR`.

- **Response** (`201`): the Integration object (its `sourceFeed` is `null` and its `fedBankAccounts` is empty on creation).

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "d3e4f5a6-b7c8-4d9e-8f0a-1b2c3d4e5f6a",
    "kind": "bsale",
    "accessToken": "b7f3c9e1a2d4f6081e3c5a7b9d1f2e4c"
  }'
```

```json
{
  "id": "d3e4f5a6-b7c8-4d9e-8f0a-1b2c3d4e5f6a",
  "entityId": "8b0a7d5e-6a3c-4f2b-9e1d-2c4b6a8f0e21",
  "kind": "bsale",
  "providerRef": "12345",
  "documentCount": 355,
  "institutionName": null,
  "holderId": null,
  "mode": null,
  "sourceFeed": null,
  "fedBankAccounts": [],
  "createdAt": "2025-01-02T12:00:00.000Z",
  "updatedAt": "2025-01-02T12:00:00.000Z"
}
```

## POST `/integrations/fintoc/link-intents`

Start the Fintoc connect flow. Sintropix creates a Link Intent at Fintoc and answers what the frontend needs to open the Fintoc widget. When the user completes the widget, it mints an exchange token. Send that token to [`POST /integrations`](#post-integrations) with `kind: "fintoc"`.

The widget needs a browser, so you can't complete a Fintoc connect from the API alone.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `holderType` | `business` \| `individual` | Yes | Who holds the account at the bank. |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `widgetToken` | string | Token the Fintoc widget needs. |
| `publicKey` | string | Public key for the widget session. |

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations/fintoc/link-intents" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{"holderType":"business"}'
```

## POST `/integrations/plaid/link-tokens`

Start the Plaid connect flow. Sintropix creates a Link token at Plaid and answers it. Open Plaid Link with it. When the user signs in to the bank, Plaid Link mints a public token. Send that token to [`POST /integrations`](#post-integrations) with `kind: "plaid"`.

Plaid Link needs a browser, so you can't complete a Plaid connect from the API alone. No request body.

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `linkToken` | string | Token that opens Plaid Link. |

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations/plaid/link-tokens" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent"
```

Then connect with the public token Plaid Link minted:

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "4a5b6c7d-8e9f-4a0b-9c1d-2e3f4a5b6c7d",
    "kind": "plaid",
    "publicToken": "public-production-1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d"
  }'
```

The response is the Integration object, with the bank's name in `institutionName`. Next, [list the bank's accounts](/api-reference/bank-feeds#get-discovered-accounts) and feed them into Bank Accounts.

## POST `/integrations/:integrationId/reconnect`

Restore a Fintoc Integration whose bank stopped trusting the stored grant. You know it needs this when [its discovered accounts](/api-reference/bank-feeds#get-discovered-accounts) answer `status: "login_required"`. Run the Fintoc widget again and send the fresh exchange token. The Integration keeps its id and every feed it holds.

Only `fintoc` Integrations reconnect. To repair a Global66, Cardda, dLocal Go, or Plaid Integration whose credentials stopped working, disconnect it and connect again. For Plaid, this includes a bank login that expired.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `exchangeToken` | string | Yes | Fresh token from the Fintoc widget. |

A grant from another bank or another holder, or an Integration that is not `fintoc`, is refused with `409` and `INTEGRATION_GRANT_MISMATCH_ERROR`.

- **Response:** the restored Integration object.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations/$INTEGRATION_ID/reconnect" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{"exchangeToken":"ex_tok_456"}'
```

## GET `/integrations`

List every Integration for the Entity, including any Mercado Pago, Mercado Libre, Gmail, or Polar authorization connected from the app and any `resend` inbox. Each item carries the Source Feed and the Bank Accounts it feeds.

- **Response:** array of Integration objects.

## DELETE `/integrations/:integrationId`

Remove an Integration. Every feed of the Integration is removed as part of the same operation: its Source Feed and the feed of each Bank Account it fed. The Source, the Bank Accounts, and the documents and Movements already landed stay.

- For a `fintoc` Integration, Sintropix also deletes the Link at Fintoc, so the bank stops being read.
- For a `plaid` Integration, Sintropix first removes the bank login at Plaid. If Plaid already removed it, the disconnect still succeeds. If Plaid fails or can't be reached, the disconnect answers `502` or `503` and the Integration stays. Retry later.
- For every other kind, Sintropix removes the stored credentials or authorization only. The grant on the provider's side is not revoked.
- For a `resend` inbox, the address stops showing its email in [Email inboxes](#email-inboxes-staff-only).

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `deletedIntegrationId` | uuid | The removed Integration. |
| `unfedBankAccounts` | array | Every Bank Account that lost its feed, in the shape documented on [Bank Accounts](/api-reference/bank-accounts) without the summary fields, and with `feed` set to `null`. Empty when the Integration fed no Bank Account. |

```bash
curl -X DELETE "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations/$INTEGRATION_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent"
```

```json
{
  "deletedIntegrationId": "0192a8b4-0000-7000-8000-000000000001",
  "unfedBankAccounts": []
}
```

## Portal Logins

A Portal Login is the login of a portal that no Provider reads. Sintropix stores the login and the password encrypted and uses them only to read the portal. No read ever returns them, so not even you can see them again in Sintropix. A Portal Login has one of two kinds:

| Kind | Portal | What you store |
| --- | --- | --- |
| `bank_login` | A bank, such as a credit card Fintoc can't fetch | The bank's name, plus the RUT and the password you sign in with |
| `getnet_login` | The Getnet merchant portal | The username or email, and the password you sign in with |

Sintropix doesn't sign in to the portal when you store a Portal Login, so a wrong login or password isn't refused. A Portal Login has no health status: it's stored, never "working" or "failed". To change the password, delete the Portal Login and store it again.

In the app, connect one from **Settings → Integrations** with **Banco** or **Getnet**. It shows in the list with the status **Guardada**.

<Note>
  A `client` or `staff` caller can store and delete Portal Logins. A `viewer` can only list them. See [Access and roles](/api-reference/overview#access-and-roles).
</Note>

### The Portal Login object

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Portal Login id. |
| `entityId` | uuid | Owning Entity. |
| `kind` | `bank_login` \| `getnet_login` | The kind of portal. |
| `label` | string | The portal's name. For a `bank_login`, the bank's name as you entered it. For a `getnet_login`, always `Getnet`. |
| `createdAt`, `updatedAt` | ISO 8601 timestamp | When the Portal Login was stored and last changed. |

### POST `/portal-logins`

Store a Portal Login for the Entity.

**Body.** The shape depends on `kind`. Every kind takes an `id`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id. Retrying with the same id is answered `409` (`CREDENTIAL_ALREADY_EXISTS_ERROR`). |
| `kind` | `bank_login` \| `getnet_login` | Yes | The kind of portal. |

Each kind adds its own fields:

| Kind | Field | Type | Description |
| --- | --- | --- | --- |
| `bank_login` | `label` | string | The bank's name, for example `Banco de Chile`. Whitespace is trimmed and must be non-empty. |
| `bank_login` | `rut` | string | The RUT you sign in to the bank with. Dots, spaces, and the hyphen are optional, and a lowercase `k` is accepted. A RUT whose check digit doesn't match is refused with `400` (`RUT_INVALID_ERROR`). |
| `bank_login` | `password` | string | The bank password. Must be non-empty. |
| `getnet_login` | `username` | string | The username or email you sign in to the Getnet portal with. Must be non-empty. |
| `getnet_login` | `password` | string | The Getnet password. Must be non-empty. |

Each name can be used once per Entity. A Bank Login whose bank name is already in use is refused with `409` (`CREDENTIAL_LABEL_ALREADY_USED_ERROR`). Sintropix names every Getnet Login `Getnet`, so an Entity holds at most one. A second Getnet Login is refused with the same error. To store another Getnet login, delete the first one.

- **Response** (`201`): the Portal Login object.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/portal-logins" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "5c6d7e8f-9a0b-4c1d-8e2f-3a4b5c6d7e8f",
    "kind": "bank_login",
    "label": "Banco de Chile",
    "rut": "12.345.678-5",
    "password": "my-bank-password"
  }'
```

```json
{
  "id": "5c6d7e8f-9a0b-4c1d-8e2f-3a4b5c6d7e8f",
  "entityId": "8b0a7d5e-6a3c-4f2b-9e1d-2c4b6a8f0e21",
  "kind": "bank_login",
  "label": "Banco de Chile",
  "createdAt": "2026-10-05T14:00:00.000Z",
  "updatedAt": "2026-10-05T14:00:00.000Z"
}
```

Store a Getnet Login:

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/portal-logins" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "6d7e8f9a-0b1c-4d2e-9f3a-4b5c6d7e8f9a",
    "kind": "getnet_login",
    "username": "pagos@acme.cl",
    "password": "my-getnet-password"
  }'
```

### GET `/portal-logins`

List the Entity's Portal Logins of both kinds.

- **Response:** array of Portal Login objects.

### DELETE `/portal-logins/:portalLoginId`

Delete a Portal Login and its stored login and password. Sintropix stops reading the portal with it. Your login at the portal is unchanged.

An id that isn't one of the Entity's Portal Logins answers `404` (`CREDENTIAL_NOT_FOUND_ERROR`).

- **Response:** the deleted Portal Login object.

```bash
curl -X DELETE "https://api.sintropix.com/api/entities/$ENTITY_ID/portal-logins/$PORTAL_LOGIN_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent"
```

## Email inboxes (staff only)

An email inbox is a `resend` Integration: an address on `inbox.sintropix.com` that receives email for the Entity. Staff reads that email through the routes below. Sintropix does not store the email or turn it into documents; every read fetches it live.

<Warning>
  Staff-only. `POST /integrations/resend` and both `/received-emails` routes require the `staff` Role in the Entity's Organization. A `client` or `viewer` caller (session or API key) receives `403` with `PERMISSION_DENIED_ERROR`. See [Access and roles](/api-reference/overview#access-and-roles). `GET /integrations` and `DELETE /integrations/:integrationId` serve `resend` inboxes like any other Integration.
</Warning>

### POST `/integrations/resend`

Create an inbox for the Entity. The address is `<inboxName>@inbox.sintropix.com`.

**Body.** Unknown keys are rejected with `400`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Client-generated id. Retrying with the same id is answered `409`. |
| `inboxName` | string | Yes | The part of the address before `@`. Up to 64 characters: lowercase letters and digits, in groups joined by a single `.` or `-` (for example, `acme` or `acme-compras`). |

An address belongs to one Entity only. An address another Entity already holds is refused with `409` (`INTEGRATION_ACCOUNT_ALREADY_CONNECTED_ERROR`). An Entity can hold several inboxes.

- **Response** (`201`): the Integration object, with `kind: "resend"` and the inbox address in `providerRef`.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/integrations/resend" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "id": "a2b3c4d5-e6f7-4a8b-9c0d-1e2f3a4b5c6d", "inboxName": "acme" }'
```

### GET `/received-emails`

List the email the Entity's inboxes received, newest first. An email belongs to the Entity when one of its inbox addresses appears in the email's To or Cc recipients, ignoring case. An email the inbox received only as Bcc is not listed. The list has no paging.

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `inboxAddresses` | string[] | The Entity's inbox addresses. Empty when the Entity has no inbox, and `emails` is then empty too. |
| `emails` | array | The received emails, newest first. See below. |

Each element of `emails`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Email id. Use it with `GET /received-emails/:emailId`. |
| `from` | string | Sender. |
| `to` | string[] | To recipients. |
| `subject` | string | Subject line. |
| `receivedAt` | ISO 8601 timestamp | When the inbox received the email. |
| `attachments` | array | `{ id, filename, contentType, size }` for each attachment. `filename` can be `null`; `size` is in bytes. |

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/received-emails" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

```json
{
  "inboxAddresses": ["acme@inbox.sintropix.com"],
```

### GET `/received-emails/:emailId`

Read one received email with its body and attachment download links. `emailId` must be a UUID. An email that is not addressed to one of the Entity's inboxes answers `404` (`RECEIVED_EMAIL_NOT_FOUND_ERROR`), the same as an id that does not exist.

**Response:** every field of a listed email, plus:

| Field | Type | Description |
| --- | --- | --- |
| `text` | string \| null | Plain-text body. |
| `html` | string \| null | HTML body. Render it in a sandbox: it can load remote images. |
| `attachments` | array | `{ id, filename, contentType, size, downloadUrl }` for each attachment, up to 100. `downloadUrl` expires shortly after the read, so read the email again to get a fresh link. |

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success on `GET`, `DELETE`. |
| `201` | Integration or Portal Login created. |
| `400` | Validation error (including a Portal Login RUT that fails its check digit, `RUT_INVALID_ERROR`), missing `x-audit-actor` on a key-authenticated mutation, or connecting `sii_mirror` on an Entity whose country is not Chile or whose RUT the mirror does not follow. |
| `403` | A non-staff caller on `POST /integrations/resend` or `/received-emails` (`PERMISSION_DENIED_ERROR`). |
| `404` | Entity, Integration, Portal Login (`CREDENTIAL_NOT_FOUND_ERROR`), or received email (`RECEIVED_EMAIL_NOT_FOUND_ERROR`) not found. |
| `409` | Integration id already exists, the external account (for `resend`, the inbox address) is already connected to an Entity (`INTEGRATION_ACCOUNT_ALREADY_CONNECTED_ERROR`), a reconnect names another grant or a non-Fintoc Integration (`INTEGRATION_GRANT_MISMATCH_ERROR`), a Portal Login id already exists (`CREDENTIAL_ALREADY_EXISTS_ERROR`), or a Portal Login names a portal the Entity already uses, including a second Getnet Login (`CREDENTIAL_LABEL_ALREADY_USED_ERROR`). |
| `410` | The Provider no longer holds the grant (`INTEGRATION_GRANT_GONE_ERROR`). Disconnect the Integration and connect it again. |
| `422` | The Provider refused the credentials (`INTEGRATION_CONNECT_REJECTED_ERROR`), or a Global66 account names a currency Sintropix does not know (`INTEGRATION_CURRENCY_UNKNOWN_ERROR`). |
| `502` | The Provider failed (`BANK_FEED_PROVIDER_FAILURE_ERROR`). Retry later. |
| `503` | The Provider can't be reached right now (`BANK_FEED_PROVIDER_UNREACHABLE_ERROR`), Sintropix can't connect that Provider right now (`INTEGRATION_NOT_CONFIGURED_ERROR`), the inbox email could not be read right now (`RECEIVED_EMAIL_UNAVAILABLE_ERROR`), or Sintropix can't store a Portal Login right now (`CREDENTIAL_NOT_CONFIGURED_ERROR`). Retry later. |
