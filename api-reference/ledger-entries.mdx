Ledger Entries are the core double-entry transactions in Sintropix. Each entry has a header (date, memo, notes) and at least two balanced lines. This page covers creating entries (one at a time or [in bulk](#post-/api/entities/entityid/ledger/entries/bulk)), listing, reversing, and unbooking them, plus Scheduled Entries and line-level updates.

All amounts are integers in the minor unit of the currency (for example, cents). Dates are `YYYY-MM-DD` strings; timestamps are ISO 8601 datetimes.

<Note>
  **Entities with Bases.** An Entity may hold zero or more [Bases](/api-reference/bases). When it has at least one, a manual or Scheduled Entry may name a `basisId` on the header; without one, or with `null`, the Entry is common. A Basis Entry cannot post to a [common-only account](/api-reference/bases#common-only-accounts). The Ledger Entry listing and the Open Item Lines read must carry `basisId` as a query parameter. See [Bases](/api-reference/bases) for the model and the exact rule.
</Note>

## GET /api/entities/:entityId/ledger/entries

List Ledger Entries with pagination, filtering, and sorting. Defaults to live entries (`active` and `reversed` statuses). The list includes [Computed Entries](#computed-entries), such as Revaluation Entries and their reversals. Pass `ids` instead to read the full detail of up to 100 specific entries in one request.

- **Path param:** `entityId` (UUID)
- **Query params:**

| Param | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `ids` | UUID[] | No | — | 1 to 100 entry ids. Repeat the parameter for each id (`?ids=A&ids=B`). Cannot be combined with any other query parameter. See [Reading several entries by id](#reading-several-entries-by-id). |
| `cursor` | UUID | No | — | Last entry id of the previous page |
| `limit` | integer | No | 50 | Page size, max 100 |
| `from` | ISO date | No | — | Earliest entry date |
| `to` | ISO date | No | — | Latest entry date (must be >= from) |
| `search` | string | No | — | Up to 100 characters. Case-insensitive contains-match on the memo, the notes, and the name of any account the entry posts to. A search that reads as an amount also matches the entry's `total`; see [Search by amount](/api-reference/overview#search-by-amount). |
| `sort` | enum | No | `date` | `date`, `memo`, or `amount` |
| `direction` | enum | No | `desc` | `asc` or `desc` |
| `statuses` | string | No | `active,reversed` | Comma-separated list of `active`, `deleted`, `reversed`, `scheduled`, `cancelled` |
| `basisId` | UUID | Conditional | — | Required when the Entity has at least one [Basis](/api-reference/bases); must be omitted otherwise. The page lists the common entries plus the entries of that Basis |

- **Success response:** a page of entries
- **Status:** 200

| Field | Type | Description |
| --- | --- | --- |
| `entries` | array | Ledger Entries on this page, each with the fields below |
| `nextCursor` | UUID or null | Pass as `cursor` to fetch the next page; `null` on the last page |

Each item in `entries` carries the Ledger Entry fields plus three line-derived totals:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Entry id |
| `entityId` | UUID | Owning Entity |
| `entryDate` | ISO date | Transaction date |
| `memo` | string or null | Short description |
| `notes` | string or null | Longer notes |
| `status` | enum | `active`, `deleted`, `reversed`, `scheduled`, or `cancelled` |
| `reversalOfEntryId` | UUID or null | The entry this one reverses; `null` for ordinary entries |
| `basisId` | UUID or null | The [Basis](/api-reference/bases) the entry counts in; `null` for a common entry |
| `createdAt` | ISO datetime | Creation timestamp |
| `updatedAt` | ISO datetime | Last update timestamp |
| `total` | integer | Sum of the entry's debit lines |
| `lineCount` | integer | Number of lines |
| `accountNames` | string[] | Distinct names of the accounts the entry touches, debit-side accounts first |
| `attachmentCount` | integer | Number of [attachments](/api-reference/attachments) on the entry |
| `basisName` | string or null | Name of the entry's Basis; `null` for a common entry |

The first ten fields are the **Ledger Entry** object; other endpoints on this page return it on its own.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries?limit=20&sort=date&direction=desc" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

### Reading several entries by id

When you pass `ids`, the response is an array of Ledger Entry detail objects instead of a `{ entries, nextCursor }` page. Each element has the same shape as the response of [`GET /api/entities/:entityId/ledger/entries/:entryId`](#get-/api/entities/entityid/ledger/entries/entryid), including `lines`, `relatedInvoices`, `relatedMovements`, and `allocations`. Use this when you already hold a set of entry ids and need their full detail without one request per entry.

- Results follow the order of `ids`. A repeated id is returned once, at its first position.
- Ids the Entity does not hold are left out of the array rather than refused. Compare the returned `id` values against the ids you sent.
- Combining `ids` with `cursor`, `limit`, `statuses`, or any other query parameter returns 400.
- Sintropix reads every element from one consistent snapshot.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries?ids=$ENTRY_ID_1&ids=$ENTRY_ID_2" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

## POST /api/entities/:entityId/ledger/entries

Create a new Ledger Entry. The entry must have at least two lines and total debits must equal total credits. The client supplies the idempotency id. Sintropix values each foreign-currency line itself; see [Foreign-currency lines](#foreign-currency-lines). To read that valuation without writing, send [`?dryRun=true`](#dry-run).

- **Path param:** `entityId` (UUID)
- **Query param:** `dryRun` (boolean, optional). `true` runs the write and rolls it back. See [Dry run](#dry-run).
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | UUID | Yes | Client-supplied idempotency id |
| `entryDate` | ISO date | Yes | Transaction date |
| `memo` | string or null | Yes | Short description |
| `notes` | string or null | No | Longer notes; trimmed, blank becomes null |
| `basisId` | UUID or null | No | [Basis](/api-reference/bases) the Entry counts in. Omit it, or send `null`, to post a common Entry. A Basis Entry cannot post a line to a [common-only account](/api-reference/bases#common-only-accounts) (`409`, `LEDGER_ENTRY_BASIS_LINE_ON_COMMON_ONLY_ACCOUNT_ERROR`). An Entity with no Basis must omit it. |
| `newLedgerEntryLines` | array | Yes | At least 2 lines, max 10,000, balanced once valued |
| `exchangeDifferenceLineId` | UUID | No | Client-generated id of the Exchange Difference Line, on an entry that [settles open lines](#settle-open-lines). Send it when the valued lines leave a gap |
| `exchangeDifferenceReason` | string | No | Why the settlement's implied rate is beyond the [rate bound](/api-reference/bank-movements#the-rate-bound), 1 to 500 characters after trimming. Send it only when Sintropix asks for it |

Each line in `newLedgerEntryLines` is either **domestic**, in the Entity's functional currency, or **foreign**, in another currency:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | UUID | Yes | Client-supplied line id. Must not already exist. |
| `accountId` | UUID | Yes | Ledger Account id |
| `side` | enum | Yes | `debit` or `credit` |
| `functionalAmount` | integer | Domestic only | Nonnegative magnitude in the functional currency. Required on a domestic line, refused on a foreign line |
| `transactionCurrency` | string | Foreign only | Currency code of a foreign line. Sending it makes the line foreign. It cannot be the Entity's functional currency |
| `transactionAmount` | integer | Foreign only | Nonnegative amount in the minor units of `transactionCurrency`. Required on a foreign line |
| `overrideFxRate` | decimal string | No | Foreign only. A rate of your own, such as `"950.25"`, instead of the published one. Greater than zero, with no sign or exponent. Requires `overrideFxRateReason` |

Each must be a Value of the Entity's Organization; see [Dimensions](/api-reference/dimensions#dimensions-belong-to-the-organization). ### Foreign-currency lines

A foreign line states its currency and its amount. Sintropix works out its functional amount; you never send that amount or the rate.

1. **Rate.** Sintropix values the line at the latest rate the Entity's [Rate Source](/api-reference/fx-rates#rate-sources) published on or before the `entryDate`, the same rate an [FX rate lookup](/api-reference/fx-rates) for that date answers. The line records the rate in `transactionFxRate`, its date in `transactionFxRateDate`, and `transactionFxRateOrigin: "published"`.
2. **Own rate.** When the evidence names another rate, such as a contract rate, send `overrideFxRate` with `overrideFxRateReason`. The line takes `transactionFxRateOrigin: "overridden"`, keeps the reason, and keeps the published rate it replaced in `replacedFxRate`. An override is also the only way to book a currency the Rate Source doesn't publish.
3. **Rounding.** Lines of one currency, rate, and side round as a group. Each line rounds down, and the minor units still missing from the group's rounded total go one each to the lines with the most units, a tie going to the first in request order. On an ordinary entry, the rounding unit lands on the largest line, and no line goes negative. Each line's `roundingAdjustment` shows where a unit landed.
4. **Balance.** The entry must balance once every line is valued. Check that with a [dry run](#dry-run) before you write.

`transactionFxRateOrigin` tells you where a line's rate came from:

| Value | Meaning |
| --- | --- |
| `published` | The rate of the Entity's Rate Source on or before the Entry Date, dated in `transactionFxRateDate` |
| `overridden` | A rate the caller stated with `overrideFxRate` and its reason |
| `settled_item` | The carrying rate of the open line the line settles, dated in `transactionFxRateDate`. A line with [`settlesLineId`](#settle-open-lines) posts it, as does the settlement line of a [bank Match or Assign](/api-reference/bank-movements#settle-a-foreign-open-item) |
| `stated` | A rate the caller stated without a check: every foreign line booked before Sintropix valued foreign lines. [Invoice booking](/api-reference/invoices#foreign-currency-invoices) and the [bank routes](/api-reference/bank-movements#foreign-currency-and-the-exchange-difference) value their lines like this page does |

The valuation adds these refusals, all `409`:

| Code | When | `params` |
| --- | --- | --- |
| `LEDGER_ENTRY_LINE_FX_RATE_NOT_FOUND_ERROR` | The Rate Source published no rate for the pair on or before the date, and the line has no override | `{ lineId, transactionCurrency, functionalCurrency, date, rateSource }` |
| `LEDGER_ENTRY_LINE_FX_RATE_SOURCE_NOT_FOUND_ERROR` | The Entity's country has no Rate Source, and the line has no override | `{ lineId, transactionCurrency, functionalCurrency, date, country }` |
| `LEDGER_ENTRY_LINE_VALUED_AMOUNT_OUT_OF_RANGE_ERROR` | The line values past the largest functional amount the ledger accepts. Check its amount or its rate | `{ lineId }` |
| `LEDGER_ENTRY_UNBALANCED_AFTER_VALUATION_ERROR` | The valued lines don't balance | `{ debitTotal, creditTotal, gap, valuedLines }` |

Use it to size the counterpart lines. An entry whose lines are all domestic and don't balance still answers `400`, before any valuation.

### Settle open lines

A line can settle an open item: an open line on an [Open-Item Account](/api-reference/chart-of-accounts), such as an Invoice's Control Line or an advance to a supplier. Name the open line in the line's `settlesLineId`. Sintropix values the line at the item's carrying amount and records the [Allocation](/api-reference/allocations) in the same write, so the item is settled when the entry books.

Use it when no Bank Movement pays the item, such as a payment through a card or a provider's clearing account. Use it also to net two open lines in different currencies against each other, such as a supplier's USD Invoice and a CLP payment booked to the same payable, or two lines in one foreign currency booked at different rates. An [Allocation](/api-reference/allocations) refuses both, because it posts nothing and can't book the exchange difference between them. When a Bank Movement pays the item, [match the Movement](/api-reference/bank-movements#post-/movements/movementid/match) instead.

Read the items to settle with [`GET /ledger/open-item-lines`](#get-/api/entities/entityid/ledger/open-item-lines) or the [open positions](/api-reference/reports#open-positions-receivables-and-payables). Each line there states what a settling line needs: `openAmount`, `openTransactionAmount`, `entryBasisId`, and `dimensionValueIds`.

**The settling line.** It mirrors the item it settles:

- It posts to the item's account, on the other side, with the item's Partner.
- It's in the item's denomination. On a foreign item, it sends the item's `transactionCurrency` and the units it settles, at most `openTransactionAmount`. On a domestic item, it sends the `functionalAmount` it settles, at most `openAmount`. The amount must be above `0`.
- The entry is in the item's Basis: its `basisId` is the item's `entryBasisId`, or it's omitted for a common item.
- The item must be open: a line of a live entry, on an Open-Item Account other than the Suspense Account, with something left to settle.
- Each item takes one settling line. One entry may settle several items, on any accounts and in any denominations.
- In a [bulk create](#post-/api/entities/entityid/ledger/entries/bulk), an entry may settle a line that an earlier entry of the same request creates.

A foreign settling line takes the item's carrying amount: all the open units take the whole open functional amount, and fewer units take their share of it. Its `transactionFxRateOrigin` is `settled_item`. A partial settlement follows the [bank rule](/api-reference/bank-movements#settle-a-foreign-open-item) for `LEDGER_ENTRY_SETTLEMENT_PARTIAL_NOT_MEASURABLE_ERROR`. The Allocation records the amount settled, and on a foreign item the units too.

**The exchange difference.** When the valued lines leave a gap, declare an Exchange Difference Line: send `exchangeDifferenceLineId`, a new UUID, on the entry. Don't send a line of your own for the difference. Sintropix fills in its amount, side, and account, with the ground `settlement`, the same way as on the [bank acts](/api-reference/bank-movements#the-exchange-difference-line). An entry with no settling line can't declare one, and answers `LEDGER_ENTRY_EXCHANGE_DIFFERENCE_NOT_ALLOWED_ERROR`.

The lines, other than the Exchange Difference Line, decide how Sintropix checks the difference:

- **Two denominations**, such as USD and CLP. Sintropix measures the rate the settlement implies: the functional amount of the lines in the other denomination per unit of the foreign currency. It compares it with the published rate of the entry date, under the 5% [rate bound](/api-reference/bank-movements#the-rate-bound). Beyond the bound, or when no rate is published, the write answers `LEDGER_ENTRY_EXCHANGE_DIFFERENCE_RATE_UNEXPLAINED_ERROR`. Send `exchangeDifferenceReason` only when a document shows that rate was really applied. A manual entry has no Suspense Account to leave a rest on, so otherwise check the units, or settle fewer and leave the rest open. When the entry settles items in two foreign currencies, such as EUR and USD, Sintropix measures the rate in the currency of the settled item with the largest carrying amount (its open functional amount). A tie goes to the item with the lowest line id. The order of the lines in the request doesn't change which currency is measured.
- **One foreign currency**, such as a USD Invoice netted against a USD advance booked at another rate. No other denomination prices the units, so the debit and credit units in that currency must be equal, counting every line in it. Settle the smaller side's open units on both lines and leave the rest of the larger item open. Unequal units answer `LEDGER_ENTRY_SETTLEMENT_UNITS_UNBALANCED_ERROR`.

**Rate overrides.** A settling line never takes `overrideFxRate`. When the entry also declares an Exchange Difference Line, no foreign line of it takes one. To record a payment at your own rate, send it as a domestic line with its `functionalAmount`, so the measure reads it. Both cases answer `LEDGER_ENTRY_LINE_OVERRIDE_ON_SETTLEMENT_ERROR`.

**After booking.** The entry's date can't change; see [PATCH](#patch-/api/entities/entityid/ledger/entries/entryid). Unbooking or reversing the entry reopens the items it settled.

Run the entry with [`?dryRun=true`](#dry-run) first. The dry run answers the valued lines and the Exchange Difference Line, or the refusal the write would give.

#### Example

A Chilean Entity holds a supplier's USD 1,000.00 Invoice, booked at 943.25, so its Control Line carries a CLP 943,250 credit on the payables account. The Entity paid the supplier CLP 950,000 by card, booked as an open debit on the same account. One entry nets the two:

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries?dryRun=true" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{
    "id": "4d4d4d4d-4d4d-4d4d-8d4d-4d4d4d4d4d4d",
    "entryDate": "2026-11-10",
    "memo": "Factura 812 pagada con tarjeta",
    "exchangeDifferenceLineId": "5e5e5e5e-5e5e-4e5e-8e5e-5e5e5e5e5e5e",
    "newLedgerEntryLines": [
      { "id": "c3c3c3c3-c3c3-4c3c-8c3c-c3c3c3c3c3c3", "accountId": "66666666-6666-4666-8666-666666666666", "side": "debit", "partnerId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d", "transactionCurrency": "USD", "transactionAmount": 100000, "settlesLineId": "d1d1d1d1-d1d1-4d1d-8d1d-d1d1d1d1d1d1" },
      { "id": "c4c4c4c4-c4c4-4c4c-8c4c-c4c4c4c4c4c4", "accountId": "66666666-6666-4666-8666-666666666666", "side": "credit", "partnerId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d", "functionalAmount": 950000, "settlesLineId": "d2d2d2d2-d2d2-4d2d-8d2d-d2d2d2d2d2d2" }
    ]
  }'
```

The USD line takes the Invoice's carrying amount, CLP 943,250. The Exchange Difference Line takes the gap, a CLP 6,750 debit (a loss), on the Entity's Exchange Difference Account. The implied rate is 950, so the entry books if the published rate of 10 November is within 5% of it. Send the same body without `dryRun` to book it. Both items then leave the open items.

| Code | Status | When | `params` |
| --- | --- | --- | --- |

| `LEDGER_ENTRY_SETTLEMENT_SIDE_MISMATCH_ERROR` | `409` | The line is on the item's side. `settledSide` is the item's side, so the line goes on the other one | `{ lineId, settledSide }` |
| `LEDGER_ENTRY_SETTLEMENT_PARTNER_MISMATCH_ERROR` | `409` | The line carries another Partner than the item's | `{ lineId, partnerId, settledPartnerId }` |
| `LEDGER_ENTRY_SETTLEMENT_DENOMINATION_MISMATCH_ERROR` | `409` | The line is in another denomination than the item. Each denomination is a currency code, the functional currency's on a domestic line | `{ lineId, denomination, settledDenomination }` |
| `LEDGER_ENTRY_SETTLEMENT_EXCEEDS_OPEN_AMOUNT_ERROR` | `409` | The line settles more than is open. Both amounts are in `settledDenomination`: units on a foreign item, functional on a domestic one | `{ lineId, openAmount, settlementAmount, settledDenomination }` |
| `LEDGER_ENTRY_SETTLEMENT_AMOUNT_ZERO_ERROR` | `409` | The line is `0`, so it settles nothing | `{ lineId }` |
| `LEDGER_ENTRY_SETTLEMENT_BASIS_MISMATCH_ERROR` | `409` | The entry is in another Basis than the item's entry | `{ lineId, settlesLineId }` |
| `LEDGER_ENTRY_SETTLEMENT_UNITS_UNBALANCED_ERROR` | `409` | Every line but the Exchange Difference Line is in one foreign currency, and its debit and credit units differ. The units are minor units of that currency | `{ transactionCurrency, debitUnits, creditUnits }` |
| `LEDGER_ENTRY_LINE_OVERRIDE_ON_SETTLEMENT_ERROR` | `409` | A settling line carries `overrideFxRate`, or any foreign line does on an entry that settles and declares an Exchange Difference Line | `{ lineId }`. In each, `lineId` is the settling line and `settlesLineId` the item. A `settlesLineId` that names a line of a [Computed Entry](#computed-entries) answers `LEDGER_ENTRY_LINE_COMPUTED_ERROR`. The Exchange Difference Line answers the [foreign-currency errors](/api-reference/bank-movements#foreign-currency-errors) of the bank acts, such as `LEDGER_ENTRY_EXCHANGE_DIFFERENCE_REQUIRED_ERROR`. In a bulk create, each refusal also carries `elementIndex`.

#### Settle in the app

In **Partidas abiertas**, **Por cobrar**, and **Por pagar**, select open lines in more than one currency, or in one foreign currency at different rates. Such a selection offers only **Liquidar con diferencia de cambio**, not **Conciliar**. The dialog opens when the selection has at least one debit and one credit, all in one Basis. Otherwise the selection bar says why it can't settle: the lines are all on one side, or they span two Bases.

The dialog lists each line with the amount it settles under **Liquida**, which you can lower to settle part of an item. In one foreign currency, each side starts at the smaller side's units, so the entry balances in units and the rest of the larger item stays open. A line that settles nothing reads **No liquida: queda abierta.** and stays out of the entry. As you edit, it runs a dry run and shows the **Diferencia de cambio** row with its account and amount. Beyond the rate bound, it asks for **Motivo de la diferencia de cambio**.

**Liquidar** books one entry in the Basis of the selected lines, and each settling line carries the Dimension Values of its item. If Sintropix refuses it, the dialog keeps your draft and shows why. The booked entry lists the items it settled under **Conciliado contra**. **Conciliar** still matches a selection in one currency, and in one rate for a foreign currency.

### Dry run

Add `?dryRun=true` to `POST /ledger/entries` or [`POST /ledger/entries/bulk`](#post-/api/entities/entityid/ledger/entries/bulk) to read what Sintropix would book, without booking it. Use it to read the functional amount of each foreign line, then size the other lines so the entry balances.

- A dry run runs the whole write, with every check, then rolls it back. It answers `200` with the answer the write would give plus `dryRun: true` (on each element of a bulk answer), or with the refusal the write would give.
- It stores nothing: no entry, no audit change. The entry and line ids stay free, so you can send the same body without `dryRun` to book it.
- It counts as a write for permissions. It needs the write's permission and [audit headers](/api-reference/overview), and a read-only key gets `403`.
- Audit ids are not reused, so a dry run leaves a gap in them, as a refused write does.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries?dryRun=true" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d @entry.json
```

If the credit line of the example above carried 943000, the dry run, like the write, answers:

```json
{
  "code": "LEDGER_ENTRY_UNBALANCED_AFTER_VALUATION_ERROR",
  "params": {
    "debitTotal": 943250,
    "creditTotal": 943000,
    "gap": 250,
    "valuedLines": [
      { "lineId": "b1b1b1b1-b1b1-4b1b-8b1b-b1b1b1b1b1b1", "side": "debit", "functionalAmount": 943250, "transactionFxRate": "943.25", "transactionFxRateDate": "2026-11-06", "transactionFxRateOrigin": "published" },
      { "lineId": "b2b2b2b2-b2b2-4b2b-8b2b-b2b2b2b2b2b2", "side": "credit", "functionalAmount": 943000, "transactionFxRate": null, "transactionFxRateDate": null, "transactionFxRateOrigin": null }
    ]
  }
}
```

### In the app

In the new entry screen, you type a foreign line's currency and amount. As you type, the screen runs a dry run and shows what Sintropix would book: each line's figure, the rate with its date and series, any rounding, the totals, and **Balanceado** or **Diferencia**. **Usar otro tipo de cambio** opens the override. There you type the rate and its required **Motivo**, and see the published rate it replaces and the difference. A currency the Rate Source doesn't publish is refused on its line, with the next step.

A booked entry shows each foreign line's rate origin and date: **Publicado para el** and the date, or **Tipo de cambio propio** with its reason and the published rate it replaced. A line booked before Sintropix valued foreign lines shows **Indicado al contabilizar**.

## POST /api/entities/:entityId/ledger/entries/bulk

Create up to 100 Ledger Entries in a single request and transaction. Each element is a full entry with the same fields as [`POST /api/entities/:entityId/ledger/entries`](#post-/api/entities/entityid/ledger/entries), and follows the same rules, including the [valuation of foreign-currency lines](#foreign-currency-lines). An entry may [settle](#settle-open-lines) a line that an earlier entry of the same request creates.

- **Path param:** `entityId` (UUID)
- **Query param:** `dryRun` (boolean, optional). `true` runs the whole batch and rolls it back; see [Dry run](#dry-run).
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `entries` | array | Yes | 1 to 100 entries, each with the body of the single create. Each `id` must be unique within the request. No other field is accepted. |

- **Success response:** an array of the created entries, in request order. Each element has the same shape as the single create response.
- **Status:** 201, or 200 for a dry run

The request is all or nothing:

- An empty `entries`, more than 100 entries, or two entries with the same `id` return `400`, and Sintropix writes nothing.
- When any entry fails validation or a domain rule, Sintropix writes no entry. The response carries the error the single create would return (for example `404 LEDGER_ACCOUNT_NOT_FOUND_ERROR` or `409 LEDGER_ENTRY_DATE_LOCKED_ERROR`) plus `elementIndex`, the zero-based position of the refused entry in `entries`.

Retrying is safe. When you send a batch again, each entry whose `id` is already a live entry of the Entity (`active` or `reversed`) answers the stored entry, and the response is `201` again. An `id` whose entry is no longer live, for example an unbooked one, returns `409` with `LEDGER_ENTRY_ALREADY_EXISTS_ERROR` and its `elementIndex`, and Sintropix writes nothing.

```bash
curl -X POST https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries/bulk \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{
    "entries": [
      {
        "id": "33333333-3333-4333-8333-333333333333",

        ]
      },
      {
        "id": "99999999-9999-4999-8999-999999999999",
        "entryDate": "2026-01-16",
        "memo": "Pago de arriendo",
        "newLedgerEntryLines": [
          { "id": "a1a1a1a1-a1a1-4a1a-8a1a-a1a1a1a1a1a1", "accountId": "55555555-5555-4555-8555-555555555555", "functionalAmount": 500, "side": "debit" },
```

## PATCH /api/entities/:entityId/ledger/entries/:entryId

Update an entry's header fields (date, memo, notes). At least one field must be provided.

An entry with a `published`, `overridden`, or `settled_item` [foreign-currency line](#foreign-currency-lines), or with an [Exchange Difference Line](/api-reference/bank-movements#the-exchange-difference-line), was valued on its date, whichever route booked it. So a new `entryDate` answers `409` with `LEDGER_ENTRY_VALUED_LINES_DATE_CHANGE_ERROR` and `params: { ledgerEntryId }`. To move it, unbook the entry and book it again on the new date. - **Path params:** `entityId` (UUID), `entryId` (UUID)
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |

| `memo` | string or null | No | New memo |
| `notes` | string or null | No | New notes; trimmed, blank becomes null |

- **Success response:** the updated Ledger Entry object (see the list endpoint)
- **Status:** 200

```bash
curl -X PATCH https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries/$ENTRY_ID \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"memo": "Updated description"}'
```

## POST /api/entities/:entityId/ledger/entries/:entryId/reverse

Reverse a live Ledger Entry by posting a mirror entry. The reversal date must be on or after the original entry date and after the ledger lock date. The reversal takes the Basis of the original; do not send `basisId`. It copies each line's valuation as it stands, with sides flipped: the amounts, rate, rate origin, rate date, override reason, and replaced rate. Sintropix values nothing again.

- **Path params:** `entityId` (UUID), `entryId` (UUID)
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | UUID | Yes | Client-supplied idempotency id for the reversal entry |
| `entryDate` | ISO date | Yes | Reversal date |

If the entry books a [deferred](/api-reference/invoices#deferrals) or [accrued](/api-reference/invoices#accruals) Invoice line, its booked Releases are reversed on the same date and its Scheduled ones are cancelled. This includes a booked Release on or before the ledger lock date, as a reversal dated in an open month reverses any locked entry.

An Entry that still holds a line on the Suspense Account is refused with `LEDGER_REVERSAL_ENTRY_HAS_SUSPENSE_LINE_ERROR`. Unbook the Bank Movement instead, or [assign](/api-reference/bank-movements#post-/movements/movementid/assign) the rest first.

- **Success response:** every row the reversal changed
- **Status:** 201

| Field | Type | Description |
| --- | --- | --- |
| `reversalEntry` | object | The mirror entry just posted: Ledger Entry fields plus `ledgerEntryLines` (same shape as the create response) |
| `reversedEntry` | object | The original entry as it now stands, with `status` set to `reversed` |
| `severedInvoices` | array | Invoices whose booking link was cut (invoice fields as in the entry detail, without `partnerName`) |
| `severedMovements` | array | Bank movements whose booking link was cut (movement fields as in the entry detail, without `bankAccountCurrency`, `bankAccountLedgerAccountId`, and `partnerName`) |
| `settledChainEntries` | array | Ledger Entry objects whose status changed because a reversal chain was settled, in the order they changed; empty when nothing else changed |

```bash
curl -X POST https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/entries/$ENTRY_ID/reverse \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{
    "id": "44444444-4444-4444-8444-444444444444",
    "entryDate": "2026-01-20"
  }'
```

## DELETE /api/entities/:entityId/ledger/entries/:entryId

Unbook (soft-delete) a Ledger Entry. The entry status becomes `deleted`. This severs any linked invoices, bank movements, and allocations. If the entry is a reversal, the chain behind it is settled back to its prior state. If it books a [deferred](/api-reference/invoices#deferrals) or [accrued](/api-reference/invoices#accruals) Invoice line, its booked Releases are unbooked and its Scheduled ones are cancelled; a booked Release on or before the ledger lock date refuses the whole unbook with `LEDGER_ENTRY_UNBOOK_FROZEN_ERROR`. To correct that booking, [reverse](#post-/api/entities/entityid/ledger/entries/entryid/reverse) it on a date in an open month instead.

A Release is undone with its Invoice, never alone. Unbooking a Release entry is refused with `409` and `LEDGER_ENTRY_UNBOOK_RELEASE_ERROR`, and `params: { ledgerEntryId, invoiceId, invoiceDocumentNumber }` names the Invoice to unbook instead.

- **Path params:** `entityId` (UUID), `entryId` (UUID)
- **Success response:** every row the unbook changed
- **Status:** 200

## Linked lines

An [Intercompany Link](/api-reference/intercompany-links) joins a line of an Entry in one Entity to a line of an Entry in another Entity of the same Organization. A linked line names its Link in `intercompanyLinkId` in the [Entry detail](#get-/api/entities/entityid/ledger/entries/entryid). The Link writes nothing in the books, so the routes on this page treat a linked Entry like any other:

- Editing the Entry's header, or a linked line's Partner, account, or Dimension values, keeps the Link.
- [Unbooking](#delete-/api/entities/entityid/ledger/entries/entryid) or [reversing](#post-/api/entities/entityid/ledger/entries/entryid/reverse) the Entry removes its Links, as it removes its Allocations. After you book the corrected Entry, link its new line again. See [Correct a Link](/api-reference/intercompany-links#correct-a-link).

## Computed Entries

A Computed Entry is a Ledger Entry that Sintropix computes from your stored lines and FX Rates each time you read the books. It is never stored. Today, every Computed Entry is a [Revaluation Entry](#revaluation-entries) or its reversal.

A Computed Entry reads like any other entry:

- `GET /ledger/entries`, the entry detail, and `GET /ledger/lines` return it. The entry detail answers `isComputed: true`.
- Balances and reports include it: the balance sheet, the income statement, the eight-column balance, the general ledger, the journal, and the [consolidated reports](/api-reference/consolidation#revaluation-in-consolidated-reports).
- Its amounts follow your data and the published rates, so two reads can answer different amounts. Its id stays the same.

Open items and their open amounts, bank match candidates, and the activities of the cash flow statement read stored lines only. A Computed Entry never settles or changes an open item.

In the app, a Computed Entry shows a **Calculado** chip beside its status in the entry list, the general ledger, the entry page, and the **Libro Diario**. Its page offers no **Reverse** or **Unbook**, and no tasks, attachments, or messages. The **Libro mayor** Excel and the [month-end close workbook](/api-reference/reports#month-end-close-workbook) mark its lines with **Sí** in a last **Calculado** column, and the [Google Sheets export](/api-reference/integrations#libro-mayor) leaves its **Fecha de creación** empty.

### Computed ids

The ids of a Computed Entry and its lines are version 8 UUIDs that start with `ca1c21ed-`. The shape of the id alone marks it as computed. Random version 4 UUIDs never take this shape, so you don't need to change how you generate ids.

### Writes are refused

You can't change a Computed Entry. Every write that names one, or one of its lines, is refused with `409`:

- **An entry id** answers `LEDGER_ENTRY_COMPUTED_ERROR` with `params: { entryId, entryDate }`. This covers edit, reverse, unbook, the Scheduled Entry book, edit, and cancel, [attachments](/api-reference/attachments), [task](/api-reference/tasks) links, and messages on the entry.
- **A line id** answers `LEDGER_ENTRY_LINE_COMPUTED_ERROR` with `params: { lineId }`. This covers the line's Partner, account, and Dimension values, [Allocations](/api-reference/allocations), a bank Match, bulk Match, Assign, and Unassign, a [Follow-up](/api-reference/follow-ups) Plan that names the line, an [Intercompany Link](/api-reference/intercompany-links), and the acquisition line of a Fixed Asset.
- **A create** that sends a new entry id or line id of the computed shape is refused with the same codes. This covers entry create, bulk create, and dry run, Scheduled Entry create and reschedule, reverse, the bank Book, Match, and Assign, an Invoice booking, and a Follow-up Plan.

### Revaluation Entries

IAS 21 reports a foreign-currency monetary item at the closing rate. Sintropix does this with Revaluation Entries: it restates the foreign units of each position at the closing rate, and books the difference as an unrealized exchange difference.

These lines are revalued: live common lines (with no Basis) on a [Monetary Account](/api-reference/chart-of-accounts#monetary-accounts), an account with `isMonetary: true`, in a currency other than the Entity's functional currency. They form positions:

- **An open item** on an `open_item` account, on the units it still has open.
- **A balance** on a `balance` account: the units the account holds in one currency.

Each position has its own Revaluation Entry per month, from the month it is first held to the current month. A month where the position's amount doesn't differ from its carrying amount has none for that position.

- **Date.** A month that has passed is revalued on its last day. The current month is revalued on today's date, at the latest published rate, so its entry moves forward each day and keeps its id. A report can add one more entry on its own dates. See [Revaluation at a report's dates](#revaluation-at-a-reports-dates).
- **Rate.** The closing rate is the rate from the Entity's [Rate Source](/api-reference/fx-rates) on or before the entry date.
- **Lines.** Each entry has two lines. The item line, on the position's Monetary Account, carries the difference, with `transactionCurrency` set, a `transactionAmount` of `0`, and the closing rate in `transactionFxRate`. An [Exchange Difference Line](/api-reference/bank-movements#the-exchange-difference-line) with `exchangeDifferenceGround: "revaluation"` balances it on the Entity's [Exchange Difference Account](/api-reference/chart-of-accounts#exchange-difference-accounts): a gain on the `other_income` account and a loss on the `other_expense` account, or both on the one account the Entity tagged.
- **Partner.** The Exchange Difference Line of an open item carries the item's `partnerId`, so a Partner filter on `GET /ledger/lines` and the reports under that Partner find it. A balance position has no Partner.
- **Reversal.** Each Revaluation Entry has `status: "reversed"`. Its reversal is dated on the 1st of the next month, has `status: "active"`, and names it in `reversalOfEntryId`. The reversal takes the difference back on the same accounts, so each month restates the whole difference from the stored amounts.
- **Memo.** The memo names the position: `Dif. no realizada · {name} · {currency} {units} · al DD-MM-YYYY`, with the entry date. `{name}` is the memo of the open item's entry, or the account's name for a balance or an item whose entry has no memo. The units are an absolute value with Chilean grouping, such as `USD 1.234,56` or `JPY 1.234.567`, whatever the Entity's regional format. For example: `Dif. no realizada · Factura 1234 Acme Inc. · USD 1.234,56 · al 31-03-2026`. You can find an entry with the memo search of `GET /ledger/entries`.
- **Ids.** A position keeps the same entry id every month it is read. An open item's id follows the Entity and the item's line, so it stays the same when you [move the line to another account](#patch-/api/entities/entityid/ledger/lines/lineid/account). A balance's id follows the Entity, the account, and the currency.

An Entity with no Exchange Difference Account has no Revaluation Entries. Tag one to start revaluing. Lines of a Basis Entry are not revalued.

For example, a Chilean Entity holds USD 1,000.00 on a monetary Bank Account, bought at 900.00, so the books carry CLP 900,000:

1. On 31 March the closing rate is 940.00. The March Revaluation Entry, dated 31 March, debits the bank account CLP 40,000 and credits the Exchange Difference Account CLP 40,000. The balance sheet at 31 March shows the bank at CLP 940,000.
2. On 1 April the reversal takes the CLP 40,000 back.
3. On 30 April the closing rate is 920.00. The April Revaluation Entry books a CLP 20,000 gain. The income statement for April shows an exchange difference of CLP −20,000: the reversal of March's CLP 40,000 gain and April's CLP 20,000 gain.

#### Revaluation at a report's dates

A month's Revaluation Entry stands from its date through the last day of its month. A report whose last day, or the day before its first day, is a day no month's entry stands on gets one more Revaluation Entry per position on that day. That day is:

- A past day that isn't a month end.
- A day of the current month before today.
- A day of a month that hasn't started yet, such as the end of the current Fiscal Year.

The extra entry follows the rules above, with these differences:

- **Date and rate.** It's dated on that day, at the closing rate from the Entity's Rate Source on or before that day.
- **Reversal.** Its reversal is dated the next day.
- **Scope.** It exists only in a report that reaches that day. A report with other dates doesn't include it, and nothing is stored.
- **Ids.** Its id states the position and the day, so the same report answers the same id. Open it with the [entry detail](#get-/api/entities/entityid/ledger/entries/entryid) like any Computed Entry. Every write that names it is refused with `LEDGER_ENTRY_COMPUTED_ERROR`, with its date in `entryDate`.

So a balance sheet at any date carries foreign monetary items at that date's closing rate, and an income statement for any window shows only that window's exchange differences. Every read of the books includes it: the balance sheet, the income statement and its lines, the eight-column balance, the general ledger, the journal, `GET /ledger/entries`, the cash flow statement's `fxEffect`, the [consolidated reports](/api-reference/consolidation#revaluation-in-consolidated-reports), and [`GET /ledger/revaluation`](#get-/api/entities/entityid/ledger/revaluation).

In the example above, the closing rate on 15 April is 930.00:

- The balance sheet at 15 April gets a Revaluation Entry dated 15 April that books a CLP 30,000 gain, so it shows the bank at CLP 930,000. Its reversal is dated 16 April.
- The income statement for 1–15 April shows an exchange difference of CLP −10,000: the reversal of March's CLP 40,000 gain and the 15 April entry's CLP 30,000 gain.
- The income statement for 16–30 April shows CLP −10,000: the reversal of the 15 April entry and April's CLP 20,000 gain.
- The balance sheet at 30 April reads only the month entries, as before.

#### The revalued position

The item line moves no units, so its `transactionAmount` is `0` and the account's unit balance stays right. To read what the entry revalues, use `revaluedPosition` on the entry detail:

| Field | Type | Description |
| --- | --- | --- |
| `units` | integer | Foreign units the position holds, in minor units of `transactionCurrency` |
| `carryingAmount` | integer | Functional amount the stored lines carry for those units, in minor units |
| `closingAmount` | integer | Functional amount of those units at the closing rate, in minor units |

The three amounts are signed: positive for a debit position such as a receivable or a bank balance, and negative for a credit position such as a payable. The entry and its reversal answer the same object, so the reversal's direction comes from `reversalOfEntryId`. In the March example, the entry answers `{ "units": 100000, "carryingAmount": 900000, "closingAmount": 940000 }`, with CLP amounts in pesos.

In the app, the entry page and the entry panel show the units on the item line, with the functional amount as "from → to": carrying → closing on the entry, and closing → carrying on its reversal. A payable shows positive figures.

#### Notices in the app

The app shows these notices in a **Diferencia de cambio no realizada** banner above each report of an Entity's books. It reads the notices through the report's last day:

| Report | Read through |
| --- | --- |
| Balance sheet, eight-column balance, and cash flow statement | The cutoff date |
| Income statement, income statement by Dimension, **Libro mayor**, and the partner ledger | The end of the window |
| **Libro Diario** | The end of the window, or today when the window has no end |

The banner shows one line per notice, and nothing when no notice applies. To keep it short, it differs from the API answer in two ways:

- It hides the provisional rate of the current month. That month is always revalued at today's rate, so the notice would always show.
- Months that share one closing rate, or that all lack a rate for a currency, show once, at the newest month. For example, when a Rate Source stops publishing USD, the banner shows one line for the latest month instead of one per month.

The banner refreshes when the books change, when you tag an Exchange Difference Account, when you change whether an account is monetary, and when a Dimension or a Group Account's required Dimensions change.

The group's reports show the same banner with the notices of every Entity they read, each line opening with the Entity's name, as in `Andes Chile SpA: {notice}`. These are **Consolidado**, **Balance general**, and **Estado de resultados** of the [consolidated reports](/api-reference/consolidation), read through the report's date or the end of its period, and the [cash flow statement of the Organization](/api-reference/reports#cash-flow-statement-of-the-organization), read through the last day of its last month.

```bash
curl -X PATCH https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/lines/$LINE_ID/account \
```

### PUT /api/entities/:entityId/ledger/lines/:lineId/dimension-values

Replace the Dimension Value tags on a Ledger Entry Line. An empty array untags the line. On an account whose Group Account [requires Dimensions](/api-reference/dimensions#required-dimensions), the new set must keep a value of each required Dimension, or the request returns `400` with `DIMENSION_VALUE_REQUIRED_ERROR`.

- **Path params:** `entityId` (UUID), `lineId` (UUID)
- **Body:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `dimensionValueIds` | UUID[] | Yes | Full replacement tag set. Each must be a Value of the Entity's [Organization](/api-reference/dimensions#dimensions-belong-to-the-organization) |

- **Success response:** the updated Ledger Entry Line object plus `lineDimensionValues`, an array of `{ dimensionId, dimensionValueId, dimensionName, dimensionValueCode, dimensionValueName }`
- **Status:** 200

```bash
curl -X PUT https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/lines/$LINE_ID/dimension-values \
  -H "Content-Type: application/json" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -d '{"dimensionValueIds": ["dddddddd-dddd-4ddd-8ddd-dddddddddddd"]}'
```

The retag shows in the entry's history, with who made it and the Value before and after. See [Dimension tags in the history of an Entry](/api-reference/audit-trail#dimension-tags-in-the-history-of-an-entry).
