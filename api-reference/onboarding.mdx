The Onboarding API is how a Sintropix Superadmin provisions new Users and controls which Organizations they can access. Public sign-up is disabled, so User creation happens only through this surface.

<Warning>
  Superadmin only, from a signed-in browser session. A request that carries an API key or an OAuth access token receives `403` with `SUPERADMIN_SESSION_REQUIRED`, even when a Superadmin owns it. Any other signed-in User, including one with the `staff` Role in an Organization, receives `403` with `SUPERADMIN_REQUIRED`.
</Warning>

No API route makes a User a Superadmin. Being a Superadmin does not open any Entity's books: a Superadmin reaches an Entity only through a Membership of its Organization.

## POST `/onboarding/users`

Create a User. A User has no Role of their own: a new User reaches no Entity until you grant a Membership below, and the Role lives on that Membership.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `email` | string | Yes | A valid email address. Must be unique across all Users, ignoring case. |
| `name` | string | Yes | Display name. Surrounding whitespace is trimmed, and the result must not be empty. |

**Response** `201`

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | The new User's id. Use it in the `:userId` path segment of the routes below. |
| `email` | string | The email, stored in lowercase. |
| `name` | string | The display name, trimmed. |
| `createdAt` | ISO datetime | Creation timestamp. |

An email another User already holds returns `409` with `USER_ALREADY_EXISTS_ERROR`.

```bash
curl -X POST "https://api.sintropix.com/api/onboarding/users" \
  --cookie cookies.txt \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ana.perez@example.com",
    "name": "Ana Perez"
  }'
```

```json
{
  "id": "0192a3b4-c5d6-7e8f-9a0b-1c2d3e4f5a6b",
  "email": "ana.perez@example.com",
  "name": "Ana Perez",
  "createdAt": "2026-09-26T12:00:00.000Z"
}
```

## GET `/onboarding/users`

List Users, or look one up by email. Use the email filter to recover a User's id when all you hold is their address.

**Query params**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `email` | string | No | A valid email address. Matching ignores case. Without it, the response lists every User. |

**Response** `200`: an array of User objects in the shape returned by `POST /onboarding/users` (`id`, `email`, `name`, `createdAt`). An unknown email returns an empty array.

```bash
curl "https://api.sintropix.com/api/onboarding/users?email=ana.perez%40example.com" \
  --cookie cookies.txt
```

## GET `/onboarding/organizations`

List every Organization, each with the Entities it holds, whether or not you hold a Membership in it. Use it to pick the `organizationId` when you grant a Membership, create an Entity, or move an Entity. The response has the same shape as [`GET /organizations`](/api-reference/organizations), which lists only the Organizations where the caller holds the `staff` Role.

```bash
curl "https://api.sintropix.com/api/onboarding/organizations" \
  --cookie cookies.txt
```

## GET `/onboarding/users/:userId/memberships`

List the Organization Memberships a User holds. Each Membership gives the User one Role across every Entity of that [Organization](/api-reference/organizations).

**Response** `200`: an array of Memberships.

| Field | Type | Description |
| --- | --- | --- |
| `role` | enum | `staff`, `client`, or `viewer`. See [Access and roles](/api-reference/overview#access-and-roles). |
| `organization` | object | `{ id, name }` of the Organization. |

```bash
curl "https://api.sintropix.com/api/onboarding/users/$USER_ID/memberships" \
  --cookie cookies.txt
```

```json
[
  {
    "role": "client",
    "organization": { "id": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d", "name": "Grupo Acme" }
  }
]
```

## POST `/onboarding/users/:userId/memberships`

Grant a User a Membership in an Organization with one Role. The User reaches every Entity of the Organization, including Entities added to it later. A User holds at most one Membership per Organization.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `organizationId` | UUID | Yes | The Organization to grant access to. Must be an existing Organization. |
| `role` | enum | Yes | `staff`, `client`, or `viewer`. |

- **Status:** `204`.

```bash
curl -X POST "https://api.sintropix.com/api/onboarding/users/$USER_ID/memberships" \
  --cookie cookies.txt \
  -H "Content-Type: application/json" \
  -d '{ "organizationId": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d", "role": "client" }'
```

## PATCH `/onboarding/users/:userId/memberships/:organizationId`

Change the Role of an existing Membership.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `role` | enum | Yes | `staff`, `client`, or `viewer`. |

- **Status:** `204`.

```bash
curl -X PATCH "https://api.sintropix.com/api/onboarding/users/$USER_ID/memberships/$ORGANIZATION_ID" \
  --cookie cookies.txt \
  -H "Content-Type: application/json" \
  -d '{ "role": "viewer" }'
```

## DELETE `/onboarding/users/:userId/memberships/:organizationId`

Revoke a User's Membership in an Organization. The User loses access to every Entity of the Organization on their next request. Every [connected app](/guides/connected-apps) the User approved for that Organization is revoked with it. No request body.

- **Status:** `204`.

```bash
curl -X DELETE "https://api.sintropix.com/api/onboarding/users/$USER_ID/memberships/$ORGANIZATION_ID" \
  --cookie cookies.txt
```

## POST `/onboarding/users/:userId/set-password-link`

Send the User a link they can follow to set (or reset) their password. Sintropix emails the link to the User, in their language, and answers it too, so you can also relay it over your own channel. No request body.

- The link expires after 4 days and works once.
- Each call sends a new link. Links sent earlier keep working until they're used or expire.
- If the email can't be sent, the request fails and answers no link. Call it again.
- Setting the password through the link signs the User out of every session.
- Users can also ask for a link themselves: **¿Olvidaste tu contraseña?** on the sign-in page emails them a link. That link expires after 1 hour and also works once.

**Response** `201`

| Field | Type | Description |
| --- | --- | --- |
| `link` | URL | The one-time set-password link that was emailed to the User. |

```bash
curl -X POST "https://api.sintropix.com/api/onboarding/users/$USER_ID/set-password-link" \
  --cookie cookies.txt
```

```json
{
  "link": "https://api.sintropix.com/api/auth/reset-password/Qm9yamFNYXJxdWV6?callbackURL=https%3A%2F%2Fapp.sintropix.com%2Fset-password"
}
```

## POST `/onboarding/users/:userId/revoke-sessions`

Revoke every active session for a User, forcing a fresh sign-in on their next request. Use after a suspected credential compromise. No request body.

- **Status:** `204`.

```bash
curl -X POST "https://api.sintropix.com/api/onboarding/users/$USER_ID/revoke-sessions" \
  --cookie cookies.txt
```

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success on `GET /users`, `GET /organizations`, and `GET /memberships`. |
| `201` | Success on `POST /users` and `POST /set-password-link`. |
| `204` | Success on Membership grant, role change, revoke, and session revocation. |
| `400` | Validation error, including a blank name or a `:userId` that is not a UUID. |
| `403` | Caller is not a Superadmin (`SUPERADMIN_REQUIRED`), or the request carries an API key or token (`SUPERADMIN_SESSION_REQUIRED`). |
| `404` | User not found (`USER_NOT_FOUND_ERROR`), Organization not found (`ORGANIZATION_NOT_FOUND_ERROR`), or no Membership to change or revoke (`ORGANIZATION_MEMBERSHIP_NOT_FOUND_ERROR`). |
| `409` | The email is taken (`USER_ALREADY_EXISTS_ERROR`), or the User already holds a Membership in this Organization (`ORGANIZATION_MEMBERSHIP_ALREADY_EXISTS_ERROR`). |
