An Organization groups the Entities that a client runs as one business. Every Entity belongs to exactly one Organization. Users reach Entities through an Organization Membership, which carries one Role and covers every Entity of the Organization, including Entities added later. See [Access and roles](/api-reference/overview#access-and-roles) for what each Role allows.

An Organization also owns the data its Entities share, while each Entity keeps its own books. [Partners](/api-reference/partners#partners-belong-to-the-organization), [Dimensions](/api-reference/dimensions#dimensions-belong-to-the-organization), and [Integrations](/api-reference/integrations#integrations-belong-to-the-organization) are shared this way. For example, list the Partners with [`GET /api/organizations/:organizationId/partners`](/api-reference/partners#get-api-organizations-organizationid-partners), which asks the `books` read permission like an Entity route.

<AppLink
  url="https://app.sintropix.com/organizations/{organizationId}/settings"
  note="That is the Empresa page: the Organization's logo and name, and one row per Entity (Entidad legal) with its settings."
/>

Use this page to manage Organizations themselves. To grant, change, or revoke a User's Membership, use the [Onboarding API](/api-reference/onboarding). To move an Entity to another Organization, use [`PATCH /api/entities/:entityId/organization`](/api-reference/entities).

<Warning>
  Every route below except `GET /organizations`, [`PATCH /organizations/:organizationId/website`](#patch-organizations-organizationid-website), [`GET /organizations/:organizationId/logo`](#get-organizations-organizationid-logo), and [`GET /organizations/:organizationId/role`](#get-organizations-organizationid-role) is restricted to a Superadmin, and only from a signed-in browser session. A request that carries an API key or an OAuth access token receives `403` with `SUPERADMIN_SESSION_REQUIRED`, even when a Superadmin owns it. Any other signed-in User receives `403` with `SUPERADMIN_REQUIRED`.
</Warning>

A Superadmin is a User Sintropix designates to manage access. No API route grants Superadmin. Being a Superadmin does not open any Entity's books: a Superadmin reads and writes an Entity only through a Membership of its Organization, like any other User.

## GET `/organizations`

List the Organizations where you do Sintropix work, each with the Entities it holds.

- Every signed-in User can call it. You see only the Organizations where you hold the `staff` Role. A Superadmin sees only their own `staff` Organizations here too.
- An API key confined to one Entity receives an empty array.
- An OAuth access token sees at most the one Organization it was approved for. See [Connect an app with OAuth](/guides/connected-apps).

**Response** `200`: an array of Organization summaries.

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Organization id |
| `name` | string | Organization name |
| `entities` | array | `{ id, name, parentEntityId }` of each Entity in the Organization. `parentEntityId` is the Entity's parent Entity, always in the same Organization, or `null` for a root Entity. Build the group tree from it. |

```bash
curl https://api.sintropix.com/api/organizations \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

```json
[
  {
    "id": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d",
    "name": "Grupo Acme",
    "entities": [
      { "id": "11111111-1111-4111-8111-111111111111", "name": "Acme SpA", "parentEntityId": null },
      {
        "id": "22222222-2222-4222-8222-222222222222",
        "name": "Acme Inversiones SpA",
        "parentEntityId": "11111111-1111-4111-8111-111111111111"
      }
    ]
  }
]
```

## POST `/organizations`

Create an empty Organization. Add Entities to it by creating them with its `organizationId` or by moving existing Entities into it.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | 1 to 200 characters after trimming surrounding whitespace. Must contain a visible character. Unique across Organizations, ignoring case. |

**Response** `201`

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Organization id |
| `name` | string | Organization name, trimmed |
| `website` | string or null | The Organization's website, stored as a bare lowercase domain (`acme.cl`). `null` until staff [set it](#patch-organizations-organizationid-website). |
| `createdAt` | ISO datetime | Creation timestamp |

```bash
curl -X POST https://api.sintropix.com/api/organizations \
  --cookie cookies.txt \
  -H "Content-Type: application/json" \
  -d '{"name": "Grupo Acme"}'
```

```json
{
  "id": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d",
  "name": "Grupo Acme",
  "website": null,
  "createdAt": "2026-09-26T12:00:00.000Z"
}
```

A name that another Organization already uses, in any case, returns `409` with `ORGANIZATION_NAME_ALREADY_EXISTS_ERROR`.

## GET `/organizations/:organizationId`

Get one Organization with the Entities it holds. The response has the same shape as one item of `GET /organizations`.

```bash
curl https://api.sintropix.com/api/organizations/$ORGANIZATION_ID \
  --cookie cookies.txt
```

## PATCH `/organizations/:organizationId`

Rename an Organization. The body and validation rules match `POST /organizations`.

**Response** `200`: the renamed Organization (`id`, `name`, `website`, `createdAt`).

```bash
curl -X PATCH https://api.sintropix.com/api/organizations/$ORGANIZATION_ID \
  --cookie cookies.txt \
  -H "Content-Type: application/json" \
  -d '{"name": "Grupo Acme Holding"}'
```

## PATCH `/organizations/:organizationId/website`

Set or clear the website Sintropix reads the Organization's logo from. The app shows that logo in the company menu of the sidebar, in place of the Organization's initial.

- Only a member with the `staff` Role in the Organization can call it, from a session or an API key. A `client` or `viewer` member receives `403` with `PERMISSION_DENIED_ERROR`, and a User outside the Organization receives `404` with `ORGANIZATION_NOT_FOUND_ERROR`.
- An API key confined to one Entity receives `403` with `PERMISSION_DENIED_ERROR`.

**Body.** Unknown keys are rejected with `400`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `website` | string or null | Yes | A domain or a URL. Sintropix keeps only the host, lowercased and without `www.`: `https://www.Acme.cl/contacto` is stored as `acme.cl`. A value that is not a domain is refused with `400`, with the validation issue `WEBSITE_INVALID_ERROR`. Send `null` to clear the website. |

**Response** `200`: the Organization (`id`, `name`, `website`, `createdAt`).

```bash
curl -X PATCH https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/website \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"website": "https://www.acme.cl"}'
```

```json
{
  "id": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d",
  "name": "Grupo Acme",
  "website": "acme.cl",
  "createdAt": "2026-09-26T12:00:00.000Z"
}
```

## GET `/organizations/:organizationId/logo`

Read the Organization's logo: a 64 × 64 PNG that Sintropix takes from the icon of the Organization's `website`. Any member of the Organization can read it. A Partner and an Organization on the same website share one logo.

**Response**

- `200` with the PNG itself (`Content-Type: image/png`). The response carries `Cache-Control: private, max-age=31536000, immutable`, so a browser keeps it for up to a year. The URL stays the same when the `website` changes, so a cached logo can outlive it. Add the website to the URL, for example `?website=acme.cl`, to fetch the new logo after a change.
- `404` with `ORGANIZATION_LOGO_NOT_FOUND_ERROR` when the Organization has no `website`, or its site shows no usable icon. A `404` carries no cache header, so you can ask again later.
- `404` with `ORGANIZATION_NOT_FOUND_ERROR` when you are not a member of the Organization.

```bash
curl -i https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/logo \
  --cookie cookies.txt
```

## GET `/organizations/:organizationId/role`

Read who you are in the Organization: your User and the Role your Membership gives you. Any member of the Organization can call it, from a session or an API key. Use it to check what a key may do before you act with it.

- A User outside the Organization receives `404` with `ORGANIZATION_NOT_FOUND_ERROR`.
- An API key confined to one Entity receives `403` with `PERMISSION_DENIED_ERROR`.

**Response** `200`: one member, with the same fields as an item of [`GET /organizations/:organizationId/members`](#get-organizations-organizationid-members).

```bash
curl https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/role \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

```json
{
  "userId": "0192a3b4-c5d6-7e8f-9a0b-1c2d3e4f5a6b",
  "name": "Ana Perez",
  "email": "ana.perez@example.com",
  "role": "client"
}
```

## DELETE `/organizations/:organizationId`

Delete an empty Organization. Deleting an Organization also removes every Membership in it.

An Organization that still holds an Entity can't be deleted. The request returns `409` with `ORGANIZATION_NOT_EMPTY_ERROR`. Move its Entities to another Organization first. Release its [Agent Channels](/api-reference/agent-channels) first, too.

An Organization that holds an [Inbox](/api-reference/inbox) can't be deleted either. The request returns `409` with `ORGANIZATION_HAS_INBOX_ERROR`.

- **Status:** `204`.

```bash
curl -X DELETE https://api.sintropix.com/api/organizations/$ORGANIZATION_ID \
  --cookie cookies.txt
```

**Response** `200`: an array of members.

```

```

## Chat

Every Organization has one **Chat**, where its members write to each other. Every member reads it and writes in it, whatever their Role: `staff`, `client`, and `viewer` alike. A `viewer` can't write Entity data, but can write in the Chat. You see only the Chats of the Organizations you are a member of.

- An **ERP Message** is one plain-text message in the Chat, attributed to the User who wrote it and dated.
- An ERP Message of the main Chat can be answered in its **ERP Thread**. A reply is an ERP Message with a parent. You can reply to a message of the main Chat, but not to a reply, so an ERP Thread is one level deep.

The Chat isn't Erwin's: an ERP Message goes to the people of the Organization, not to Erwin. To talk to Erwin, use his Thread in the app or an [Agent Channel](/api-reference/agent-channels).

<AppLink
  url="https://app.sintropix.com/{entityId}/chat"
  note="The Chat tab of the sidebar. It is the same Chat from every Entity of the Organization. New messages and replies appear for everyone without a reload, and an ERP Thread opens beside the Chat with its reply count on the parent."
/>

Read the Chat in the app. The API has no route that lists ERP Messages.

### POST `/organizations/:organizationId/chat/messages`

Write an ERP Message in the Organization's Chat, or reply to one.

- Any member of the Organization can call it, from a session or an API key. A User outside the Organization receives `404` with `ORGANIZATION_NOT_FOUND_ERROR`.
- An API key confined to one Entity receives `403` with `PERMISSION_DENIED_ERROR`.
- The message is attributed to the User who calls: the signed-in User, or the User who owns the API key.

**Body.**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | UUID | Yes | Id of the new ERP Message. You choose it, so a retried request can't write the message twice: a second request with the same `id` receives `409` with `ERP_MESSAGE_ALREADY_EXISTS_ERROR`. |
| `text` | string | Yes | The message, in plain text. Sintropix trims spaces at both ends. It must be 1 to 4000 characters long after trimming. |
| `parentMessageId` | UUID or null | Yes | The ERP Message of the main Chat that this one answers, in the same Organization. Send `null` for a message of the main Chat. |

**Response** `201`: the ERP Message.

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | ERP Message id |
| `organizationId` | UUID | The Organization whose Chat holds it |
| `authorUserId` | UUID | The User who wrote it |
| `parentMessageId` | UUID or null | The ERP Message it answers; `null` in the main Chat |
| `text` | string | The message, trimmed |
| `createdAt` | ISO datetime | When it was written |
| `updatedAt` | ISO datetime | Last update timestamp |

**Errors**

| Code | Status | Meaning |
| --- | --- | --- |
| `ERP_MESSAGE_NOT_FOUND_ERROR` | `404` | `parentMessageId` names no ERP Message of this Organization. `params.messageId` is the id you sent. |
| `CHAT_REPLY_TO_REPLY_ERROR` | `409` | `parentMessageId` names a reply. Reply to the message of the main Chat it answers. `params.messageId` is the id you sent. |
| `ERP_MESSAGE_ALREADY_EXISTS_ERROR` | `409` | An ERP Message with this `id` already exists. `params.messageId` is the id. When you retry a request, treat it as written. |

```bash
curl -X POST https://api.sintropix.com/api/organizations/$ORGANIZATION_ID/chat/messages \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: closing-agent" \
  -H "x-audit-reason: Tell the team the October close is ready" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "5b1f0c3e-8a2d-4e7b-9c6f-1d2e3f4a5b6c",
    "text": "El cierre de octubre está listo para revisar.",
    "parentMessageId": null
  }'
```

```json
{
  "id": "5b1f0c3e-8a2d-4e7b-9c6f-1d2e3f4a5b6c",
  "organizationId": "7c1e4b2a-3d5f-4a6b-8c9d-0e1f2a3b4c5d",
  "authorUserId": "0192a3b4-c5d6-7e8f-9a0b-1c2d3e4f5a6b",
  "parentMessageId": null,
  "text": "El cierre de octubre está listo para revisar.",
  "createdAt": "2026-10-24T13:05:00.000Z",
  "updatedAt": "2026-10-24T13:05:00.000Z"
}
```

To reply in that message's ERP Thread, send another request with a new `id` and `"parentMessageId": "5b1f0c3e-8a2d-4e7b-9c6f-1d2e3f4a5b6c"`.

## Domain error codes

| Code | Status | Meaning |
| --- | --- | --- |
| `ORGANIZATION_NOT_FOUND_ERROR` | `404` | No Organization has this id, or you are not a member of it on the website, logo, role, and Chat routes. |
| `ORGANIZATION_LOGO_NOT_FOUND_ERROR` | `404` | The Organization has no `website`, or its site shows no usable icon. |
| `PERMISSION_DENIED_ERROR` | `403` | On the website route: the caller is not `staff` in the Organization, or uses an API key confined to one Entity. On the role and Chat routes: the caller uses an API key confined to one Entity. |
| `ORGANIZATION_NAME_ALREADY_EXISTS_ERROR` | `409` | Another Organization already uses this name, ignoring case. |
| `ORGANIZATION_NOT_EMPTY_ERROR` | `409` | The Organization still holds at least one Entity. |
| `ORGANIZATION_HAS_INBOX_ERROR` | `409` | The Organization holds an [Inbox](/api-reference/inbox). |
| `ERP_MESSAGE_NOT_FOUND_ERROR` | `404` | The parent of a Chat reply is not an ERP Message of this Organization. |
| `CHAT_REPLY_TO_REPLY_ERROR` | `409` | The parent of a Chat reply is itself a reply. |
| `ERP_MESSAGE_ALREADY_EXISTS_ERROR` | `409` | An ERP Message with this `id` already exists. |
| `SUPERADMIN_SESSION_REQUIRED` | `403` | The request carries an API key or an OAuth access token. Superadmin routes accept only a signed-in session. |
| `SUPERADMIN_REQUIRED` | `403` | The signed-in User is not a Superadmin. |

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success on `GET` and `PATCH`, including the logo PNG on `GET /organizations/:organizationId/logo`. |
| `201` | Organization created, or ERP Message written. |
| `204` | Success on `DELETE`. |
| `400` | Validation error, including a blank or too-long name, an invalid website (`WEBSITE_INVALID_ERROR`), a blank or too-long Chat message, or an `:organizationId` that is not a UUID. |
| `403` | Caller is not a Superadmin (`SUPERADMIN_REQUIRED`), the request carries an API key or token (`SUPERADMIN_SESSION_REQUIRED`), or the caller can't set the website or uses an API key confined to one Entity (`PERMISSION_DENIED_ERROR`). |
| `404` | Organization not found, the Organization has no logo (`ORGANIZATION_LOGO_NOT_FOUND_ERROR`), or a Chat reply names no message of the Organization (`ERP_MESSAGE_NOT_FOUND_ERROR`). |
| `409` | Duplicate name, the Organization still holds an Entity or an Inbox, or an ERP Message already exists or answers a reply. |
