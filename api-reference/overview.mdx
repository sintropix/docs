The Sintropix API is a JSON over HTTPS interface to the system that owns your ledger, your invoices, your bank movements, and your reports. Every business route is scoped to a single Entity (a legal company with its own books) and authenticated with an API key. Requests and responses are validated end to end, so field names, types, and enums are consistent across endpoints.

## Base URL

All routes are mounted under the `/api` prefix:

```text
https://api.sintropix.com/api
```

The API is not versioned in the URL path.

## Route Shape

Most business resources live under a single Entity:

```text
/api/entities/{entityId}/<resource>
```

For example:

```text
GET  /api/entities/{entityId}/ledger/accounts
POST /api/entities/{entityId}/invoices
GET  /api/entities/{entityId}/reports/balance-sheet
```

A handful of routes are Entity-independent: [`/api/entities`](/api-reference/entities) (list and create), [`/api/fx-rates`](/api-reference/fx-rates), [`/api/countries` and `/api/currencies`](/api-reference/reference-data), [`/api/onboarding/*`](/api-reference/onboarding) (staff only), and `/api/health`.

`{entityId}` is always a UUID. A request for an Entity the caller cannot access returns `404`, never `403`, so probing does not reveal whether an unknown Entity exists.

## Authentication

Programmatic callers authenticate with an API key in the `x-api-key` header. Keys are created in the Sintropix app; see [Get an API Key](/guides/api-keys).

Every mutating request (`POST`, `PUT`, `PATCH`, `DELETE`) must also send a Declared Actor:

```http
x-api-key: <secret>
x-audit-actor: <your-agent-label>
```

`x-audit-actor` is a self-reported software label (for example `claude-opus-4.8`) that lands verbatim in the [Audit Trail](/api-reference/audit-trail). Omitting it on a mutation returns `400`.

## Request Format

Requests are plain JSON. Include `Content-Type: application/json` on any request with a body.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

Path parameters that are ids must be valid UUIDs; a malformed id returns `400`.

## Response Format

Responses are the resource itself as JSON. There is no top-level `data` wrapper, no `meta` envelope, and no `pagination` block on non-paginated endpoints. Each reference page lists the fields every endpoint returns.

A single resource comes back as an object:

```json
{
  "id": "…",
  "name": "…"
}
```

A list endpoint returns a bare JSON array:

```json
[
  { "id": "…" },
  { "id": "…" }
]
```

A page endpoint (endpoints whose path ends in `/pages`, plus a handful of reports) returns a `{ rows, nextCursor }` object. `nextCursor` is `null` on the last page.

```json
{
  "rows": [ /* … */ ],
  "nextCursor": "…"
}
```

<Note>
  Pagination is opt-in per endpoint, not sitewide. Endpoints without `/pages` in their path return every row and take no `cursor` argument. Check the individual reference page for the endpoint you are calling.
</Note>

## Errors

Non-2xx responses are JSON. Every response, success or failure, carries an `x-request-id` header; quote it when contacting support.

| Status | Meaning |
| --- | --- |
| `200` | Request succeeded. |
| `201` | Resource created. |
| `204` | Request succeeded with no response body. |
| `400` | Body, query, or path failed validation; a required header is missing. |
| `401` | No valid API key. |
| `403` | The key is not allowed to perform this action (for example a read-only key attempting a mutation). |
| `404` | Resource does not exist, or the caller has no access to the requested Entity. |
| `409` | Domain conflict (for example an already-booked Ledger Entry, a duplicate row). |
| `429` | Rate limit exceeded on an API key. |
| `500` | Unhandled server error. |

Domain-level errors carry a stable string `code` in the body, for example `API_KEY_READ_ONLY_ERROR`. Match on `code`, not on the human-readable message.

## Rate Limits

Each API key is rate-limited to **25,000 requests per hour** on a sliding window. Exceeding the limit returns `429`; there is no `X-RateLimit-*` header response contract.

## Browser Callers

The API is designed for server-to-server use with an API key. Calling it directly from a browser requires your origin to be allowlisted by Sintropix; contact support if you need that.

## What Is Not Part of the API

<Warning>
  There is **no webhook system**. Sintropix does not push event notifications to external URLs. Poll the endpoints you care about, or the [Audit Trail](/api-reference/audit-trail) for a change feed.
</Warning>

<Warning>
  There is **no cursor pagination on most endpoints**. Only endpoints whose path ends in `/pages` (plus the general-ledger, open-item-lines, journal, and ledger-entries pagers) return `{ rows, nextCursor }`. Others return the full list.
</Warning>

<Warning>
  There is **no `Authorization: Bearer` scheme**. API keys go in the `x-api-key` header.
</Warning>

<Warning>
  There is **no `/v1` prefix**. The base path is `/api`.
</Warning>
