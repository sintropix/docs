The Reconciliation API lets you monitor and manage the matching of bank movements to accounting records across your entities. You can pull a summary of reconciliation completion for any entity and period, and you can manually match a bank transaction to a journal entry or document when you want to override or supplement Sintropix's automatic matching.

All Reconciliation endpoints require either the `read:financials` scope (for read operations) or the `write:reconciliation` scope (for match and approve operations).

---

## GET /reconciliation/status

Get a reconciliation summary for a specific entity and calendar month. This endpoint is useful for monitoring close progress — you can poll it to track how `completion_percentage` advances as Sintropix automatically matches transactions throughout the month.

```bash
curl "https://api.sintropix.com/v1/reconciliation/status?entity_id=ent_def456&period=2025-01" \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY"
```

### Query Parameters

<ParamField query="entity_id" type="string" required>
  The entity for which to retrieve the reconciliation summary.
</ParamField>

<ParamField query="period" type="string" required>
  The calendar month to summarize. Format: `YYYY-MM` (e.g., `2025-01` for January 2025).
</ParamField>

### Response Fields

<ResponseField name="entity_id" type="string">
  The entity this summary applies to.
</ResponseField>

<ResponseField name="period" type="string">
  The period in `YYYY-MM` format.
</ResponseField>

<ResponseField name="total_transactions" type="integer">
  Total number of transactions in the entity for this period.
</ResponseField>

<ResponseField name="matched" type="integer">
  Number of transactions successfully matched to an accounting record.
</ResponseField>

<ResponseField name="needs_review" type="integer">
  Number of transactions flagged for human review — Sintropix found a likely match but confidence is below the automatic approval threshold.
</ResponseField>

<ResponseField name="unmatched" type="integer">
  Number of transactions with no match found.
</ResponseField>

<ResponseField name="completion_percentage" type="number">
  Percentage of transactions that are `matched`, expressed as a value between `0` and `100`.
</ResponseField>

### Example Response

```json
{
  "data": {
    "entity_id": "ent_def456",
    "period": "2025-01",
    "total_transactions": 214,
    "matched": 198,
    "needs_review": 11,
    "unmatched": 5,
    "completion_percentage": 92.5
  },
  "meta": {
    "request_id": "req_2bQlI5gApR3tV8wM",
    "timestamp": "2025-01-15T12:00:00Z"
  }
}
```

<Tip>
  Integrate this endpoint into your close dashboard to surface per-entity reconciliation health at a glance. A `completion_percentage` above 95% is typically sufficient to proceed with the month-end review checklist in Sintropix.
</Tip>

## POST /reconciliation/match

Manually match a bank transaction to a journal entry or accounting document. Use this when you want to confirm a match that Sintropix flagged as `needs_review`, or to pair a transaction with a record that the automatic engine did not detect.

```bash
curl -X POST https://api.sintropix.com/v1/reconciliation/match \
  -H "Authorization: Bearer sk_live_YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "bank_transaction_id": "txn_xyz789",
    "entry_id": "je_stu321",
    "notes": "Confirmed with AP team — correct match for Invoice INV-0041"
  }'
```

### Request Body

<ParamField body="bank_transaction_id" type="string" required>
  The `id` of the bank transaction to match. Must be a transaction of type `bank_transaction`.
</ParamField>

<ParamField body="entry_id" type="string" required>
  The `id` of the journal entry, invoice, or accounting document to match the bank transaction against.
</ParamField>

<ParamField body="notes" type="string">
  Optional free-text note explaining the match decision. This note is stored in the audit trail and visible in the Sintropix reconciliation view.
</ParamField>

### Response Fields

<ResponseField name="status" type="string">
  Confirmation that the match was applied. Returns `"matched"`.
</ResponseField>

<ResponseField name="match_id" type="string">
  Unique identifier for this reconciliation match record.
</ResponseField>

<ResponseField name="matched_at" type="string">
  ISO 8601 timestamp of when the match was created.
</ResponseField>

### Example Response

```json
{
  "data": {
    "status": "matched",
    "match_id": "match_def456",
    "matched_at": "2025-01-15T12:15:00Z"
  },
  "meta": {
    "request_id": "req_8eUnL9kDsS6wY1bO",
    "timestamp": "2025-01-15T12:15:00Z"
  }
}
```

<Note>
  Both `bank_transaction_id` and `entry_id` must belong to the same entity. Attempting to match records across entities returns `400 Bad Request` with error code `CROSS_ENTITY_MATCH_NOT_ALLOWED`. For intercompany eliminations, use the Multi-Entity Management features in the Sintropix UI.
</Note>
