title: "ERP Reports: Balance Sheet, Income, Journal, and Ledger"
sidebarTitle: "Reports"
description: "Fetch financial reports for an entity including balance sheet, income statement with an optional Budget comparison, cash flow statement, journal, open positions (receivables and payables), revenue realization, customer status, and ledger reports. All endpoints are read-only and return bare JSON."
---

The Reports API surfaces financial and operational read models for a single entity. All endpoints are `GET` only. Pass the entity id as a UUID path parameter. Responses are bare JSON with no wrapper. Paginated endpoints return `{ rows, nextCursor }`.

All amounts are integers in the minor unit of the currency (for example, cents). Dates are `YYYY-MM-DD` strings. Where a report accepts `presentationCurrency` and `presentationRate`, the two must be supplied together, and every amount in the response is then expressed in the presentation currency.

<Note>
  **Entities with Books.** Every report on this page reads one [Book](/api-reference/books). When the Entity has at least one Book, pass the `bookId` query parameter on every request; the server answers `BOOK_REQUIRED_ERROR` (`409`) without it. When the Entity has no Book, omit `bookId`.
</Note>

<Tip>
  **Open in the app.** Every report here is a page in the Sintropix web app under `https://app.sintropix.com/{entityId}/`: `balance`, `eight-column-balance`, `income-statement`, `income-statement-by-dimension`, `cash-flow`, `general-ledger`, `journal`, `partner-ledger`, `receivables`, `payables`, `revenue-realization`, `customers`, and `fixed-assets`. Pass the period as `from` and `to`, or as `exerciseStart` and `cutoffDate` for the balances and the cash flow statement. When you report a figure to a user, link the page it came from. See [Link to the App](/guides/app-links#reports) for every parameter.
</Tip>

## Entity reports

Base path: `GET /api/entities/:entityId/reports`

### Home dashboard

`GET /api/entities/:entityId/reports/home`

Returns the home dashboard snapshot: cash position, daily balances for the last 60 days, monthly income for the last 6 months, receivables/payables open positions, and unbooked invoice counts.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `cash.total` | integer | Consolidated cash position as of today, in the functional currency |
| `cash.rateDate` | ISO date or null | Oldest publication date among the FX rates used; `null` when nothing was converted |
| `cash.unconvertedCurrencies` | string[] | Currencies left out because no rate was published |
| `dailyBalances` | array | Exactly 60 items of `{ date, total }`, one per calendar day |
| `monthlyIncome` | array | Exactly 6 items of `{ monthKey, total }`; `monthKey` is `YYYY-MM` |
| `priorMonthToDateIncomeTotal` | integer | Income in the prior month up to the same day of the month |
| `receivable` | object | `{ total, count }`: open receivable amount and the number of open lines |
| `payable` | object | `{ total, count }`: open payable amount and the number of open lines |
| `salesToBook` | integer | Unbooked sales invoices |
| `purchasesToBook` | integer | Unbooked purchase invoices |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/home" \
  -H "Cookie: <session-cookie>"
```

### Open positions (receivables and payables)

`GET /api/entities/:entityId/reports/open-positions`

Returns open items grouped by ledger account for a single subtype: receivables (asset accounts tracking money owed to the entity) or payables (liability accounts tracking money the entity owes). Use it to build a receivables or payables aging view, drill into a specific account's open lines, or filter down to one partner.

The response always lists every matching account with its open totals. Pass `expandedAccountId` to also load the individual open lines for one account; each account expands independently, and pagination applies only to the expanded account's lines.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `subtype` | enum | Yes | `receivable` or `payable` |
| `status` | enum | No | `unsettled` (default), `settled`, or `all` |
| `partnerId` | UUID | No | Restrict lines and account totals to one partner |
| `expandedAccountId` | UUID | No | Load lines for this one account; omit to return account totals only |
| `sort` | enum | No | `date` (default), `reference`, `partner`, `debit`, `credit`, `openAmount`, or `status` |
| `direction` | enum | No | `asc` (default) or `desc` |
| `cursor` | UUID | No | Id of the last line from the previous page |
| `limit` | integer | No | Page size for the expanded account's lines (default 50, max 100) |
| `bookId` | UUID | No | Restrict to a specific book |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `accounts` | array | Every ledger account of the requested subtype that has matching lines, each with the fields below |
| `lines` | array | Open-item lines for `expandedAccountId`; empty when `expandedAccountId` is not set |
| `nextCursor` | UUID or null | Pass as `cursor` to fetch the next page of `lines`; `null` on the last page |

Each item in `accounts` extends the Ledger Account with:

| Field | Type | Description |
| --- | --- | --- |
| `openDebitAmount` | integer | Sum of open amounts on debit lines |
| `openCreditAmount` | integer | Sum of open amounts on credit lines |
| `lineCount` | integer | Number of open-item lines under this account for the current filters |

Each item in `lines` extends the ledger entry line with:

| Field | Type | Description |
| --- | --- | --- |
| `openAmount` | integer | Amount still open on the line, in the functional currency |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `partner` | object or null | `{ id, name }` when the line has a counterparty |
| `dueDate` | ISO date or null | Due date carried by the source document |
| `reference` | object or null | Source document; currently `{ kind: "invoice", id, label }` |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/open-positions?subtype=receivable" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/open-positions?subtype=payable&expandedAccountId=<uuid>&limit=50" \
  -H "Cookie: <session-cookie>"
```

### Income statement

`GET /api/entities/:entityId/reports/income-statement`

Returns the income statement for the requested date range.

Pass `dimensionId` to split each account by the values of one [Dimension](/api-reference/dimensions), for example to see an income account per country or per business line. Each line then names the value it carries in `dimensionValueId`, and the response lists every value of the Dimension so you can group the lines yourself. The account totals and the lines don't change.

Pass `budgetId` to compare the actual results against a [Budget](/api-reference/budgets). Each account then carries the months the Budget plans for it in `budgetAmounts`, and the response names the Budget in `budget`.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`) |
| `dimensionId` | UUID | No | Dimension of the Entity to split the accounts by. A Dimension of another Entity returns `404` with `DIMENSION_NOT_FOUND_ERROR` |
| `budgetId` | UUID | No | Budget of the Entity to compare against. A Budget of another Entity returns `404` with `BUDGET_NOT_FOUND_ERROR` |
| `presentationCurrency` | string | No | Presentation currency |
| `presentationRate` | decimal string | No | Required together with `presentationCurrency` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `from` | ISO date | As requested |
| `to` | ISO date | As requested |
| `functionalCurrency` | string | The entity's functional currency |
| `presentationCurrency` | string | Currency the amounts are in |
| `presentationRate` | decimal string or null | Rate applied; `null` when no conversion was requested |
| `accountGroups` | array | Account Groups, each `{ id, parentGroupId, codePrefix, name }` |
| `accounts` | array | Result accounts in code order, each with the fields below. With `budgetId`, an account the Budget plans in the range is listed even when it has no lines |
| `dimension` | object or null | The Dimension asked for in `dimensionId`: `{ id, entityId, name, createdAt, updatedAt }`; `null` when none was asked |
| `dimensionValues` | array | Every value of that Dimension, ordered by code, each `{ id, code, name, parentId }`; `parentId` is `null` at the top level. Empty when no Dimension was asked |
| `budget` | object or null | The Budget asked for in `budgetId`: `{ id, name }`; `null` when none was asked |

Each item in `accounts`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Ledger Account id |
| `groupId` | UUID or null | Account Group the account belongs to |
| `code` | string | Account code |
| `name` | string | Account name |
| `type` | enum | `income`, `cost_of_goods_sold`, `operating_expense`, `other_income`, or `other_expense` |
| `normalSide` | enum | `debit` or `credit` |
| `lines` | array | Lines posted to the account in the period, newest entry first, each with the fields below |
| `budgetAmounts` | array | Months the Budget plans for the account, in month order, each `{ month, amount }`. Empty when no Budget was asked or the Budget doesn't plan the account |

Each item in `lines`:

| Field | Type | Description |
| --- | --- | --- |
| `entryId` | UUID | Parent entry |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `side` | enum | `debit` or `credit` |
| `amount` | integer | Amount in the presentation currency |
| `partnerId` | UUID or null | Counterparty partner |
| `partnerName` | string or null | Name of the partner |
| `partnerTaxId` | string or null | Tax id of the partner |
| `dimensionValueId` | UUID or null | Value of the asked Dimension the line carries; `null` when the line carries none or no Dimension was asked |

To total an account by value, add up its lines per `dimensionValueId`. To total a parent value, also add the lines of every value under it, following `parentId`. Lines with a `null` `dimensionValueId` make up the untagged remainder, so the values plus the remainder always add up to the account.

Each item in `budgetAmounts` covers a whole calendar month, given by its first day in `month`. Every month the range overlaps counts whole: with `from=2027-03-15`, March is still included in full. Like `lines`, `amount` is in the presentation currency, and it reads on the account's normal side, so a planned cost is positive.

To compare an account for a period, total its `lines` on the account's normal side to get the actual, and total its `budgetAmounts` for the months of the period to get the plan. The variance is actual minus plan. For an income account a positive variance is a better result; for a cost or expense account a negative variance is.

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2024-01-01&to=2024-12-31" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2024-01-01&to=2024-12-31&dimensionId=<uuid>" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2027-01-01&to=2027-12-31&budgetId=<uuid>" \
  -H "Cookie: <session-cookie>"
```

<Tip>
  To see only the net result per value across all accounts, use [Income statement by dimension](#income-statement-by-dimension) instead.
</Tip>

### Cash flow statement

`GET /api/entities/:entityId/reports/cash-flow`

Returns the cash flow statement for the period, prepared with the direct method. It reads the entries that post to a Cash Account, a Ledger Account with the sub-type `cash`, and classifies the cash they move into operating, investing, and financing activities. Pass `groupBy` to also get one statement per month, quarter, or year.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `exerciseStart` | ISO date | Yes | Start of the period |
| `cutoffDate` | ISO date | Yes | End of the period (must be on or after `exerciseStart`) |
| `groupBy` | enum | No | `none` (default), `month`, `quarter`, or `year` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

A positive amount is cash in; a negative amount is cash out. Every statement satisfies `closingCash = openingCash + netChange + fxEffect + cashInTransit`, and `closingCash` equals the balance of the Cash Accounts at its `cutoffDate`.

| Field | Type | Description |
| --- | --- | --- |
| `exerciseStart` | ISO date | As requested |
| `cutoffDate` | ISO date | As requested |
| `functionalCurrency` | string | The entity's functional currency |
| `openingCash` | integer | Balance of the Cash Accounts before `exerciseStart` |
| `closingCash` | integer | Balance of the Cash Accounts at `cutoffDate` |
| `netChange` | integer | Net flow of every activity plus `unclassified` |
| `fxEffect` | integer | Effect of exchange rate changes on cash; currently always `0` |
| `cashInTransit` | integer | Net cash moved through `internal_transfer` accounts: cash that left one of your accounts and has not reached the other |
| `activities` | array | Always `operating`, `investing`, and `financing`, each `{ activity, total, categories }` |
| `unclassified` | object | `{ total, accounts }`: cash on accounts with no cash flow category, or on the Suspense Account |
| `periods` | array | One statement per calendar period of `groupBy`, in date order; empty when `groupBy` is `none` |

Each item in `categories` is `{ category, total, accounts }`. Every category of the activity is listed, in the order below, even at zero:

| Activity | Categories |
| --- | --- |
| `operating` | `customer_receipts`, `supplier_payments`, `employee_payments`, `taxes`, `other_operating` |
| `investing` | `fixed_assets`, `other_investing` |
| `financing` | `borrowings`, `interest`, `dividends`, `equity_contributions` |

Each item in an `accounts` array is `{ accountId, code, name, amount }`, in code order. An account whose flows net to zero is left out.

Each item in `periods` has the same fields as the statement, without `functionalCurrency` and `periods`. The first and last periods are clipped to the requested range. Each period opens with the `closingCash` of the period before it, and the top-level fields always cover the whole range.

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/cash-flow?exerciseStart=2026-01-01&cutoffDate=2026-09-30&groupBy=quarter" \
  -H "Cookie: <session-cookie>"
```

### Customer status

Follow each customer: what you sold them, what you billed, what they paid, and what is still pending. In the app this is **Reports → Gestión de clientes**. Use the list to find the customers who owe you, then read one customer's detail to see the months and the documents behind each amount.

Amounts follow the [revenue realization](#revenue-realization) cohort. Each amount sits in the month the revenue was recognized, and its payment state is as of today (`paymentStateDate`). Revenue recognized after today isn't counted yet. All amounts are in the Entity's functional currency.

Amount fields present on `total`, on every customer row, and on every item of `months`:

| Field | Type | Description |
| --- | --- | --- |
| `recognized` | integer | Sold: revenue recognized |
| `billed` | integer | Billed: `billedOutstanding + collected` |
| `collected` | integer | Paid: amount collected |
| `recognizedAndUnbilled` | integer | Recognized but not yet billed |
| `billedOutstanding` | integer | Billed but not yet collected |
| `pending` | integer | Still to collect: `recognizedAndUnbilled + billedOutstanding` |

#### List every customer

`GET /api/entities/:entityId/reports/customer-status`

Returns one page of customers, one row each, sorted by `pending`, highest first. Customers with the same `pending` are sorted by name, and the row with no Partner comes last. Revenue booked with no Partner comes back as one row with `partnerId: null`.

The list is paginated. To read every customer, pass the `nextCursor` of each response as `cursor` until `nextCursor` is `null`. Keep `from`, `to`, `search`, `onlyPending`, and `bookId` the same on every page.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`) |
| `search` | string | No | Matches the customer's name or tax id, ignoring case, accents, punctuation, and spacing. At most 100 characters; blank is ignored. |
| `onlyPending` | boolean | No | `true` to keep only the customers with a `pending` amount other than `0`. Default `false`. |

### Eight-column balance

`GET /api/entities/:entityId/ledger/reports/eight-column-balance`

Returns the classic eight-column trial balance: debit, credit, debtor balance, creditor balance, asset, liability, loss, and profit per account.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `exerciseStart` | ISO date | Yes | Start of the exercise |
| `cutoffDate` | ISO date | Yes | End of the exercise (must be on or after `exerciseStart`) |
| `presentationCurrency` | string | No | Presentation currency |
| `presentationRate` | decimal string | No | Required together with `presentationCurrency` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
