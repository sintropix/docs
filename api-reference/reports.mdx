The Reports API surfaces financial and operational read models for a single entity. All endpoints are `GET` only. Pass the entity id as a UUID path parameter. Responses are bare JSON with no wrapper. Paginated endpoints return `{ rows, nextCursor }`.

All amounts are integers in the minor unit of the currency (for example, cents). Dates are `YYYY-MM-DD` strings. Where a report accepts `presentationCurrency` and `presentationRate`, the two must be supplied together, and every amount in the response is then expressed in the presentation currency.

<Note>
  **Entities with Books.** Every report on this page reads one [Book](/api-reference/books). When the Entity has at least one Book, pass the `bookId` query parameter on every request; the server answers `BOOK_REQUIRED_ERROR` (`400`) without it. When the Entity has no Book, omit `bookId`.
</Note>

<Tip>
  **Open in the app.** Every report here is a page in the Sintropix web app under `https://app.sintropix.com/{entityId}/`: `balance`, `eight-column-balance`, `income-statement`, `income-statement-by-dimension`, `cash-flow`, `general-ledger`, `journal`, `partner-ledger`, `receivables`, `payables`, `revenue-realization`, `customers`, and `fixed-assets`. Pass the period as `from` and `to`, as `cutoffDate` alone for the balance sheet, or as `exerciseStart` and `cutoffDate` for the eight-column balance and the cash flow statement. When you report a figure to a user, link the page it came from. See [Link to the App](/guides/app-links#reports) for every parameter.
</Tip>

## The Fiscal Year in reports

Each Entity has a Fiscal Year: the twelve months over which it measures its result. It starts on day 1 of the Entity's `fiscalYearStartMonth`, January unless you [set another month](/api-reference/entities#patch-/api/entities/entityid/fiscal-year-start). For example, with a start month of `7`, the Fiscal Year that holds 2026-03-15 runs from 2025-07-01 to 2026-06-30.

Every balance a report reads before a date follows one carry rule:

- **Result accounts** (`income`, `cost_of_goods_sold`, `operating_expense`, `other_income`, `other_expense`) carry only their lines of the current Fiscal Year. They open at `0` on the first day of each Fiscal Year.
- **The retained earnings account** carries its own lines plus the result of every closed Fiscal Year. Mark one equity account of the Entity with the `retained_earnings` [sub-type](/api-reference/chart-of-accounts#the-retained-earnings-account).
- **Any other account** carries every line before the date.

Sintropix posts no closing entry. Every report derives the close when it reads, so a change to a line of a closed year shows on the next read.

Until the Entity has a retained earnings account, no account carries the result of the closed years. The balance sheet shows it as `equity.priorPeriodResult`, and the eight-column balance shows it as `unclosedPriorResult`. The app labels it **Resultados anteriores pendientes de cierre**. Both are `0` once you mark the account.

A report that walks a running balance reads one Fiscal Year: the [eight-column balance](#eight-column-balance), the [general ledger](#general-ledger), the [general ledger of every account](#general-ledger-of-every-account), and the [partner ledger](#partner-ledger) of a result account. A window that crosses a Fiscal Year start returns `400` with `LEDGER_WINDOW_CROSSES_FISCAL_YEAR_ERROR`. `params.fiscalYearStart` is the start of the Fiscal Year that holds the window's start, so you can pick dates inside it:

```json
{
  "code": "LEDGER_WINDOW_CROSSES_FISCAL_YEAR_ERROR",
  "params": { "from": "2025-12-01", "to": "2026-01-31", "fiscalYearStart": "2025-01-01" }
}
```

The income statement, the journal, the cash flow statement, and the other reports that sum the lines between two dates take any window.

## Entity reports

Base path: `GET /api/entities/:entityId/reports`

### Home dashboard

`GET /api/entities/:entityId/reports/home`

Returns the home dashboard snapshot: cash position, daily balances for the last 60 days, monthly income for the last 6 months, receivables/payables open positions, and unbooked invoice counts.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `cash.total` | integer | Consolidated cash position as of today, in the functional currency |
| `cash.rateDate` | ISO date or null | Oldest publication date among the FX rates used; `null` when nothing was converted |
| `cash.unconvertedCurrencies` | string[] | Currencies left out because no rate was published |
| `dailyBalances` | array | Exactly 60 items of `{ date, total }`, one per calendar day |
| `monthlyIncome` | array | Exactly 6 items of `{ monthKey, total }`; `monthKey` is `YYYY-MM` |
| `priorMonthToDateIncomeTotal` | integer | Income in the prior month up to the same day of the month |
| `receivable` | object | `{ total, count }`: open receivable amount and the number of open lines. It counts only debit lines, the normal side of a receivable |
| `payable` | object | `{ total, count }`: open payable amount and the number of open lines. It counts only credit lines, the normal side of a payable. It includes what is owed on [Rendición por pagar](/api-reference/chart-of-accounts#expense-rendition-payable) accounts |
| `salesToBook` | integer | Unbooked sales invoices. Invoices [excluded from the books](/api-reference/invoices#exclude-an-invoice-from-the-books) don't count. |
| `purchasesToBook` | integer | Unbooked purchase invoices, the ones **Compras** lists. Excluded invoices and [Expense Renditions](/api-reference/sources#sources-that-hold-expense-renditions) don't count. |
| `expenseRenditionsToBook` | integer | Unbooked [Expense Renditions](/api-reference/sources#sources-that-hold-expense-renditions), the ones **Rendiciones** lists. Excluded invoices don't count. |
| `incompatibleStandingCount` | integer | Booked invoices whose DTE the SII holds as `claimed`, `annulment_requested`, or `annulled`. See [Incompatible Standing](/api-reference/source-feeds#incompatible-standing). |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/home" \
  -H "Cookie: <session-cookie>"
```

### Open positions (receivables and payables)

`GET /api/entities/:entityId/reports/open-positions`

Returns open items grouped by ledger account for one invoice direction: receivables (accounts tracking money owed to the entity) or payables (accounts tracking money the entity owes). Use it to build a receivables or payables aging view, drill into a specific account's open lines, or filter down to one partner.

The response always lists every matching account with its open totals. Pass `expandedAccountId` to also load the individual open lines for one account; each account expands independently, and pagination applies only to the expanded account's lines.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `invoiceDirection` | enum | Yes | `receivable` or `payable`. See the accounts each direction lists below |
| `status` | enum | No | `unsettled` (default), `settled`, or `all` |
| `partnerId` | UUID | No | Restrict lines and account totals to one partner |
| `expandedAccountId` | UUID | No | Load lines for this one account; omit to return account totals only |
| `sort` | enum | No | `date` (default), `reference`, `partner`, `debit`, `credit`, `openAmount`, or `status` |
| `direction` | enum | No | `asc` (default) or `desc` |
| `cursor` | UUID | No | Id of the last line from the previous page |
| `limit` | integer | No | Page size for the expanded account's lines (default 50, max 100) |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

Each direction lists the open-item accounts of the sub-types it accepts, the same ones an [Invoice](/api-reference/invoices) of that direction accepts as its control account:

| `invoiceDirection` | Account sub-types listed | In the app |
| --- | --- | --- |
| `receivable` | `receivable` | **Por cobrar** |
| `payable` | `payable` and `expense_rendition_payable` | **Por pagar** |

So **Por pagar** shows what the Entity owes its suppliers and what it owes people on approved [Expense Claims](/api-reference/expense-claims). A Rendición por pagar line names the person as its partner, so `partnerId` gives what is owed to one person.

<Note>
  `invoiceDirection` replaces the `subtype` query param.
</Note>

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `accounts` | array | Every ledger account of the requested direction that has matching lines, each with the fields below |
| `lines` | array | Open-item lines for `expandedAccountId`; empty when `expandedAccountId` is not set |
| `nextCursor` | UUID or null | Pass as `cursor` to fetch the next page of `lines`; `null` on the last page |

Each item in `accounts` extends the Ledger Account with:

| Field | Type | Description |
| --- | --- | --- |
| `openDebitAmount` | integer | Sum of open amounts on debit lines |
| `openCreditAmount` | integer | Sum of open amounts on credit lines |
| `lineCount` | integer | Number of open-item lines under this account for the current filters |

Each item in `lines` extends the ledger entry line with:

| Field | Type | Description |
| --- | --- | --- |
| `openAmount` | integer | Amount still open on the line, in the functional currency |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `partner` | object or null | `{ id, name, website }` when the line has a counterparty. `website` is the partner's website as a bare domain (`acme.cl`), or `null` |
| `dueDate` | ISO date or null | Due date carried by the source document |
| `reference` | object or null | Source document; currently `{ kind: "invoice", id, label }` |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/open-positions?invoiceDirection=receivable" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/open-positions?invoiceDirection=payable&expandedAccountId=<uuid>&limit=50" \
  -H "Cookie: <session-cookie>"
```

### Payables to plan

`GET /api/entities/:entityId/reports/payables-to-plan`

Returns the purchase invoices the Entity still has to plan a payment for: every `payable` Invoice of kind `invoice` whose [Amount to Plan](/api-reference/payment-batches#amount-to-plan) is above zero. Use it to pick the invoices of a [Payment Batch](/api-reference/payment-batches). Invoices excluded from the books never appear.

**Query params**

The report takes the same filters as the purchases listing, [`GET /invoices/pages`](/api-reference/invoices#get-/invoices/pages), except the booking status. Every filter is optional, and every bound is inclusive. Any other param is refused with `400`. The report takes no `bookId`, so a `bookId` is refused too.

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `dteType` | string | No | Keep only invoices whose DTE has this type code (`33`, `34`, ...). Repeat the param to allow several codes. Use `none` for invoices with no DTE. |
| `sourceId` | string | No | A [Source](/api-reference/sources) id, or `none` for invoices that came from no Source. |
| `partnerId` | UUID | No | Keep only the invoices of this supplier. |
| `currency` | string | No | ISO 4217 code. Lists only the invoices in that currency. Omit it to list every currency; a batch can pay invoices in any currency. |
| `paymentStatus` | string | No | `paid`, `partial`, or `unpaid`. Unbooked invoices have no payment status, so this filter leaves them out. |
| `standing` | string | No | `accepted`, `pending`, `claimed`, `annulment_requested`, `annulled`, `observed`, or `incompatible`. See `GET /invoices/pages`. |
| `followUpKind` | string | No | `proposal`, `question`, `waiting`, or `none`. Filters by the kind of the invoice's [Follow-up](/api-reference/follow-ups). |
| `issueDateFrom` | ISO date | No | Earliest issue date |
| `issueDateTo` | ISO date | No | Latest issue date. Must not be before `issueDateFrom`. |
| `dueDateFrom` | ISO date | No | Earliest due date. Invoices with no due date are kept, since most documents from the SII don't state one. |
| `dueDateTo` | ISO date | No | Latest due date. Must not be before `dueDateFrom`. Invoices with no due date are kept. |
| `taxPeriodFrom` | string | No | `YYYY-MM`. Read from the DTE; invoices without one are left out. |
| `taxPeriodTo` | string | No | `YYYY-MM` |
| `totalMin` | integer | No | Minimum `total`, in minor units |
| `totalMax` | integer | No | Maximum `total`, in minor units |
| `erpThread` | string | No | `with` keeps only invoices that have an [ERP Thread](/api-reference/notifications#talk-about-a-record-in-its-erp-thread), the conversation in the invoice's **Hilo** tab; `without` keeps only invoices with none. |

<Note>
  Unlike `GET /invoices/pages`, a due-date bound here keeps the invoices with no due date.
</Note>

**Response**

An array, earliest due date first, then earliest issue date. Invoices with no due date come last. Each item:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Invoice id |
| `partnerId` | UUID | The supplier |
| `partnerName` | string | Name of the supplier |
| `partnerWebsite` | string or null | Website of the supplier, as a bare domain (`acme.cl`); `null` when it has none |
| `documentNumber` | string | The number printed on the document |
| `currency` | string | ISO 4217 code of the Invoice |
| `total` | integer | Gross total, in minor units of `currency` |
| `issueDate` | ISO date | Issue date |
| `dueDate` | ISO date or null | Due date |
| `owedAmount` | integer | What the invoice still owes, in minor units of `currency`: its `total` while unbooked, or the Open Amount of its Control Line once booked |
| `amountToPlan` | integer | What is left to plan, in minor units of `currency`; always above zero. It's `owedAmount` minus the orders already planned for the invoice in every batch. |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/payables-to-plan?currency=CLP&dueDateTo=2026-10-31" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

To list one supplier's invoices from a single Source, combine the filters:

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/payables-to-plan?partnerId=$PARTNER_ID&sourceId=$SOURCE_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

### Balance sheet

`GET /api/entities/:entityId/reports/balance-sheet`

Returns the balance sheet on one date. The report reads the [Fiscal Year](#the-fiscal-year-in-reports) that holds `cutoffDate`, from its first day to `cutoffDate`.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `cutoffDate` | ISO date | Yes | Date of the balance sheet |
| `presentationCurrency` | string | No | Currency to present amounts in |
| `presentationRate` | decimal string | No | Rate used for conversion; required together with `presentationCurrency` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `cutoffDate` | ISO date | As requested |
| `fiscalYearStart` | ISO date | First day of the Fiscal Year that holds `cutoffDate` |
| `functionalCurrency` | string | The entity's functional currency |
| `presentationCurrency` | string | Currency the amounts are in |
| `presentationRate` | decimal string or null | Rate applied; `null` when no conversion was requested |
| `accountGroups` | array | Account Groups in code-prefix order, each `{ id, parentGroupId, codePrefix, name }` |
| `assets` | object | `{ accounts, total }` |
| `liabilities` | object | `{ accounts, total }` |
| `equity` | object | `{ accounts, total, priorPeriodResult, currentPeriodResult, conversionRounding }`. `currentPeriodResult` is the result from `fiscalYearStart` to `cutoffDate`. `priorPeriodResult` is the result of the closed Fiscal Years that no account carries; it is `0` once the Entity has a retained earnings account, which then carries it in its `balance` |
| `totalLiabilitiesAndEquity` | integer | Sum of the liabilities and equity totals |

```bash

  -H "Cookie: <session-cookie>"
```

### Income statement

`GET /api/entities/:entityId/reports/income-statement`

Returns the income statement for the requested date range.

Each account carries its result month by month in `amounts`. To read the lines behind one amount, call [Income statement lines](#income-statement-lines) for that account and month.

Pass `dimensionId` to split each account by the values of one [Dimension](/api-reference/dimensions), for example to see an income account per country or per business line. Each item of `amounts` then covers one month and one value of the Dimension, named in `dimensionValueId`, and the response lists every value of the Dimension so you can group the amounts yourself. The account totals don't change.

Pass `budgetId` to compare the actual results against a [Budget](/api-reference/budgets). Each account then carries the months the Budget plans for it in `budgetAmounts`, and the response names the Budget in `budget`.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`) |
| `dimensionId` | UUID | No | Dimension of the Entity's Organization to split the accounts by. See [Dimensions belong to the Organization](/api-reference/dimensions#dimensions-belong-to-the-organization). A Dimension of another Organization returns `404` with `DIMENSION_NOT_FOUND_ERROR` |
| `budgetId` | UUID | No | Budget of the Entity to compare against. A Budget of another Entity returns `404` with `BUDGET_NOT_FOUND_ERROR` |
| `presentationCurrency` | string | No | Presentation currency |
| `presentationRate` | decimal string | No | Required together with `presentationCurrency` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `from` | ISO date | As requested |
| `to` | ISO date | As requested |
| `functionalCurrency` | string | The entity's functional currency |
| `presentationCurrency` | string | Currency the amounts are in |
| `presentationRate` | decimal string or null | Rate applied; `null` when no conversion was requested |
| `accountGroups` | array | Account Groups, each `{ id, parentGroupId, codePrefix, name }` |
| `accounts` | array | Result accounts in code order, each with the fields below. With `budgetId`, an account the Budget plans in the range is listed even when it has no lines |
| `dimension` | object or null | The Dimension asked for in `dimensionId`: `{ id, organizationId, name, createdAt, updatedAt }`; `null` when none was asked |
| `dimensionValues` | array | Every value of that Dimension, ordered by code, each `{ id, code, name, parentId }`; `parentId` is `null` at the top level. Empty when no Dimension was asked |
| `budget` | object or null | The Budget asked for in `budgetId`: `{ id, name }`; `null` when none was asked |

Each item in `accounts`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Ledger Account id |
| `groupId` | UUID or null | Account Group the account belongs to |
| `code` | string | Account code |
| `name` | string | Account name |
| `type` | enum | `income`, `cost_of_goods_sold`, `operating_expense`, `other_income`, or `other_expense` |
| `normalSide` | enum | `debit` or `credit` |
| `amounts` | array | The account's result in the period, one item per month and Dimension value that has lines, in month order, each with the fields below |
| `budgetAmounts` | array | Months the Budget plans for the account, in month order, each `{ month, amount }`. Empty when no Budget was asked or the Budget doesn't plan the account |

Each item in `amounts`:

| Field | Type | Description |
| --- | --- | --- |
| `month` | ISO date | First day of the calendar month |
| `dimensionValueId` | UUID or null | Value of the asked Dimension the lines carry; `null` for the lines that carry none, and always `null` when no Dimension was asked |
| `amount` | integer | Net result of those lines on the account's normal side, in the presentation currency. An income is positive, and a cost or expense is positive too. A negative amount is a result on the opposite side, such as a refund on an income account |

`amount` covers only the lines between `from` and `to`: with `from=2027-03-15`, the March amount adds up the lines from March 15 on. A month with no lines has no item. With `presentationCurrency`, each line converts on its own before it adds up, so a monthly amount always equals the sum of the lines [Income statement lines](#income-statement-lines) returns for that month.

To total an account for the period, add up all its `amounts`. To total it by value, add up its `amounts` per `dimensionValueId`. To total a parent value, also add the amounts of every value under it, following `parentId`. Amounts with a `null` `dimensionValueId` make up the untagged remainder, so the values plus the remainder always add up to the account.

<Note>
  `amounts` replaces the `lines` array each account used to carry. To read the lines, call [Income statement lines](#income-statement-lines).
</Note>

Each item in `budgetAmounts` covers a whole calendar month, given by its first day in `month`. Every month the range overlaps counts whole: with `from=2027-03-15`, March is still included in full. Like `amounts`, `amount` is in the presentation currency, and it reads on the account's normal side, so a planned cost is positive.

To compare an account for a period, total its `amounts` to get the actual, and total its `budgetAmounts` for the months of the period to get the plan. The variance is actual minus plan. For an income account a positive variance is a better result; for a cost or expense account a negative variance is.

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2024-01-01&to=2024-12-31" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2024-01-01&to=2024-12-31&dimensionId=<uuid>" \
  -H "Cookie: <session-cookie>"
```

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement?from=2027-01-01&to=2027-12-31&budgetId=<uuid>" \
  -H "Cookie: <session-cookie>"
```

<Tip>
  To see only the net result per value across all accounts, use [Income statement by dimension](#income-statement-by-dimension) instead.
</Tip>

### Income statement lines

`GET /api/entities/:entityId/reports/income-statement/lines`

Returns the lines behind one figure of the [income statement](#income-statement): the lines of one result account between two dates. To explain one monthly amount, pass the account and that month's first and last days. To explain a whole column of a quarter or a year, pass that period instead.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | UUID | Yes | Result account to read. An account that isn't a result account returns no lines |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`) |
| `dimensionId` | UUID | No | Dimension whose value each line names in `dimensionValueId`. Pass the same `dimensionId` as the income statement to keep the lines of one value |
| `presentationCurrency` | string | No | Presentation currency |
| `presentationRate` | decimal string | No | Required together with `presentationCurrency` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `lines` | array | The account's lines in the period, newest entry first, each with the fields below |

Each item in `lines`:

| Field | Type | Description |
| --- | --- | --- |
| `entryId` | UUID | Parent entry |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `side` | enum | `debit` or `credit` |
| `amount` | integer | Nonnegative amount in the presentation currency |
| `partnerId` | UUID or null | Counterparty partner |
| `partnerName` | string or null | Name of the partner |
| `partnerTaxId` | string or null | Tax id of the partner |
| `partnerWebsite` | string or null | Website of the partner, as a bare domain (`acme.cl`); `null` when it has none |
| `dimensionValueId` | UUID or null | Value of the asked Dimension the line carries; `null` when the line carries none or no Dimension was asked |

Add up the lines on the account's normal side, a line on the other side counting negative, to get the income statement's amount for the same account and period. To keep the lines of one Dimension value, keep the lines with that `dimensionValueId`.

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/income-statement/lines?accountId=<uuid>&from=2026-03-01&to=2026-03-31" \
  -H "Cookie: <session-cookie>"
```

### Income statement by dimension

`GET /api/entities/:entityId/reports/income-statement-by-dimension`

Returns the income statement broken down by the values of a single dimension (for example, a cost center). The Dimension belongs to the Entity's [Organization](/api-reference/dimensions#dimensions-belong-to-the-organization): the report lists every value of that Dimension, and adds up only this Entity's lines.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `dimensionId` | UUID | Yes | Dimension of the Entity's Organization to split by. A Dimension of another Organization returns `404` with `DIMENSION_NOT_FOUND_ERROR` |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`) |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `dimension` | object | The dimension: `{ id, organizationId, name, createdAt, updatedAt }` |

### Cash flow statement

`GET /api/entities/:entityId/reports/cash-flow`

Returns the cash flow statement for the period, prepared with the direct method. It reads the entries that post to a Cash Account, a Ledger Account with the sub-type `cash`, and classifies the cash they move into operating, investing, and financing activities. Pass `groupBy` to also get one statement per month, quarter, or year.

Each entry's cash lands on the entry's other accounts, classified by their [cash flow category](/api-reference/chart-of-accounts#cash-flow-categories):

- A transfer between two Cash Accounts moves no flow.
- A line on an `internal_transfer` account counts as cash in transit (`cashInTransit`): cash that left one of your accounts and hasn't reached the other yet.
- A payment or collection allocated to an Invoice follows the Allocation to the Invoice. Its amount is spread pro rata over the Invoice's lines, and the tax lines are absorbed into the other lines. For example, a supplier payment for a fixed asset bought on credit counts as `fixed_assets`, not `supplier_payments`.
- A line on the Suspense Account, or on an account with no category and no default, lands in `unclassified`. Set a `cashFlowCategory` on the account to move it into an activity.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `exerciseStart` | ISO date | Yes | Start of the period |
| `cutoffDate` | ISO date | Yes | End of the period (must be on or after `exerciseStart`) |
| `groupBy` | enum | No | `none` (default), `month`, `quarter`, or `year` |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

A positive amount is cash in; a negative amount is cash out. Every statement satisfies `closingCash = openingCash + netChange + fxEffect + cashInTransit`, and `closingCash` equals the balance of the Cash Accounts at its `cutoffDate`.

| Field | Type | Description |
| --- | --- | --- |
| `exerciseStart` | ISO date | As requested |
| `cutoffDate` | ISO date | As requested |
| `functionalCurrency` | string | The entity's functional currency |
| `openingCash` | integer | Balance of the Cash Accounts before `exerciseStart` |
| `closingCash` | integer | Balance of the Cash Accounts at `cutoffDate` |
| `netChange` | integer | Net flow of every activity plus `unclassified` |
| `fxEffect` | integer | Effect of exchange rate changes on cash; currently always `0` |
| `cashInTransit` | integer | Net cash moved through `internal_transfer` accounts: cash that left one of your accounts and has not reached the other |
| `activities` | array | Always `operating`, `investing`, and `financing`, each `{ activity, total, categories }` |
| `unclassified` | object | `{ total, accounts }`: cash on accounts with no cash flow category, or on the Suspense Account |
| `periods` | array | One statement per calendar period of `groupBy`, in date order; empty when `groupBy` is `none` |

Each item in `categories` is `{ category, total, accounts }`. Every category of the activity is listed, in the order below, even at zero:

| Activity | Categories |
| --- | --- |
| `operating` | `customer_receipts`, `supplier_payments`, `employee_payments`, `taxes`, `other_operating` |
| `investing` | `fixed_assets`, `other_investing` |
| `financing` | `borrowings`, `interest`, `dividends`, `equity_contributions` |

Each item in an `accounts` array is `{ accountId, code, name, amount }`, in code order. An account whose flows net to zero is left out.

Each item in `periods` has the same fields as the statement, without `functionalCurrency` and `periods`. The first and last periods are clipped to the requested range. Each period opens with the `closingCash` of the period before it, and the top-level fields always cover the whole range.

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/reports/cash-flow?exerciseStart=2026-01-01&cutoffDate=2026-09-30&groupBy=quarter" \
  -H "Cookie: <session-cookie>"
```

### General ledger

`GET /api/entities/:entityId/ledger/general-ledger`

Returns the lines of one ledger account in a window, one page at a time, with a running balance that starts from what the account carries into the window. Lines come by date, oldest first, unless you pass `sort`.

The window must sit inside one [Fiscal Year](#the-fiscal-year-in-reports); one that crosses a Fiscal Year start returns `400` with `LEDGER_WINDOW_CROSSES_FISCAL_YEAR_ERROR`. In the app, the **Libro mayor** page opens on the current Fiscal Year.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | UUID | Yes | Ledger account to read |
| `from` | ISO date | Yes | Window start |
| `to` | ISO date | Yes | Window end (must be on or after `from`, in the same Fiscal Year) |
| `sort` | enum | No | `entryDate` (default), `entryMemo`, `partnerName`, `debit`, `credit`, or `runningBalance` |
| `sortDirection` | enum | No | `asc` (default) or `desc` |
| `cursor` | UUID | No | Id of the last line from the previous page |
| `limit` | integer | No | Page size (default 50, max 100) |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Sorting**

- Lines with the same sort value keep date order, oldest first.
- `entryMemo` and `partnerName` sort alphabetically. A line with no memo or no partner sorts as empty text, so it comes first in ascending order.
- `debit` and `credit` sort by the amount on that side. A line on the other side counts as zero.
- `runningBalance` is always the balance of the line in date order. A sort never recomputes it, so sorting by `runningBalance` orders the lines by that balance.
- `cursor` continues the walk in the order you asked for. Pass the same `sort` and `sortDirection` on every page.

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `lines` | array | Lines on this page, in the requested order, each with the fields below |
| `nextCursor` | UUID or null | Pass as `cursor` to fetch the next page; `null` on the last page |
| `openingBalance` | integer | What the account carries into `from`, under the [carry rule](#the-fiscal-year-in-reports) |
| `closingBalance` | integer | What the account carries out of `to` |
| `lineCount` | integer | Lines inside the window, across every page |

Each item in `lines`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Line id |
| `entryId` | UUID | Parent entry |
| `accountId` | UUID | Ledger Account |
| `entityId` | UUID | Owning Entity |
| `functionalAmount` | integer | Nonnegative magnitude |
| `side` | enum | `debit` or `credit` |
| `partnerId` | UUID or null | Counterparty partner |
| `partnerName` | string or null | Name of the partner |
| `partnerWebsite` | string or null | Website of the partner, as a bare domain |
| `transactionCurrency` | string or null | Foreign currency code, if any |
| `transactionAmount` | integer or null | Amount in the foreign currency |
| `transactionFxRate` | decimal string or null | Rate used for conversion |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `entryStatus` | enum | `active` or `reversed` (only live entries appear) |
| `reversalOfEntryId` | UUID or null | Entry the parent entry reverses; `null` otherwise |
| `intercompanyEntryId` | UUID or null | The [Intercompany Entry](/api-reference/intercompany-entries) the parent entry belongs to; `null` otherwise |
| `runningBalance` | integer | Balance after this line in date order, counted from `openingBalance` and signed by the account's normal side. It's the same whatever the sort |

### General ledger of every account

`GET /api/entities/:entityId/ledger/reports/general-ledger`

Returns the whole General Ledger of a window in one response: every account, with its opening balance, its lines, its totals, and its closing balance. Use it to export or archive the complete Libro mayor. To browse one account page by page, use the [general ledger](#general-ledger) instead.

It reads the same live lines as the general ledger (`active` and `reversed` entries), so the balances of both always agree. The response is not paginated, so a long window over a busy Entity can be large.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | ISO date | Yes | Window start |
| `to` | ISO date | Yes | Window end (must be on or after `from`, in the same Fiscal Year) |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

A `from` later than `to` returns `400`. A window that crosses a [Fiscal Year](#the-fiscal-year-in-reports) start returns `400` with `LEDGER_WINDOW_CROSSES_FISCAL_YEAR_ERROR`.

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `accounts` | array | One item per account, sorted by code, with the fields below |

An account appears when it has a line in the window or carries a nonzero balance into it. An account with no line in the window and no balance doesn't appear.

Each item in `accounts`:

| Field | Type | Description |
| --- | --- | --- |
| `code` | string | Ledger Account code |
| `name` | string | Ledger Account name |
| `openingBalance` | integer | What the account carries into `from` under the [carry rule](#the-fiscal-year-in-reports), signed by the account's normal side |
| `debitTotal` | integer | Sum of the debit lines in the window; nonnegative |
| `creditTotal` | integer | Sum of the credit lines in the window; nonnegative |
| `closingBalance` | integer | Balance after the account's last line in the window, or `openingBalance` when it has no line |
| `lines` | array | Lines in the window, sorted by entry date, each with the fields below |

Each item in `lines`:

| Field | Type | Description |
| --- | --- | --- |
| `entryId` | UUID | Parent entry |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `partnerName` | string or null | Name of the partner on the line |
| `partnerTaxId` | string or null | Tax id of the partner on the line |
| `side` | enum | `debit` or `credit` |
| `functionalAmount` | integer | Nonnegative magnitude |
| `runningBalance` | integer | Balance after this line, counted from `openingBalance` and signed by the account's normal side |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/reports/general-ledger?from=2026-01-01&to=2026-10-31" \
  -H "Cookie: <session-cookie>"
```

<Tip>
  **Download it from the app.** On the **Libro mayor** page, click **Exportar a Excel** to download this report for the window on screen as `libro-mayor-{from}-{to}.xlsx`. The sheet opens with the Entity, the window, and the currency. Each account is a block: a **Saldo inicial** row, one row per line (**Fecha**, **Asiento**, **Glosa**, **Contacto**, **RUT**, **Débito**, **Crédito**, **Saldo**), and a **Total** row with the debit total, the credit total, and the closing balance. Every row repeats the account's **Código** and **Cuenta**, so filtering on either column keeps an account's block whole. **Asiento** holds the Ledger Entry id. Amounts are in currency units, not minor units.
</Tip>

### Partner ledger

`GET /api/entities/:entityId/ledger/partner-ledger`

Returns the partner ledger for an open-item account, grouped by partner with opening/closing balances and line-level detail.

The report is paginated. A page walks each partner's opening row, then that partner's lines in date order. Partners come in name order, and the group with no partner comes last. A partner whose lines run over a page boundary appears on both pages with the same `openingBalance`, totals, and `closingBalance`, so join its `lines` across pages. To read the whole ledger, pass the `nextCursor` of each response as `cursor` until `nextCursor` is `null`, keeping the other params the same.

**Query params**

| Param | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | UUID | Yes | Ledger account (must be open-item tracking) |
| `from` | ISO date | Yes | Start date |
| `to` | ISO date | Yes | End date (must be on or after `from`). For a result account, the window must sit inside one [Fiscal Year](#the-fiscal-year-in-reports), or the request returns `400` with `LEDGER_WINDOW_CROSSES_FISCAL_YEAR_ERROR` |
| `partnerIds` | UUID[] | No | Filter to specific partners (max 100); repeat the param for each id |
| `includeUnassigned` | boolean | No | Include lines with no partner (default false) |
| `cursor` | string | No | Page cursor (`<partnerId>~<lineId>`). Pass the `nextCursor` of the previous page; omit it for the first page. A cursor that names no Partner of the Organization returns `404` with `LEDGER_ENTRY_LINE_PARTNER_NOT_FOUND_ERROR`, and one that names no line of the account returns `404` with `LEDGER_ENTRY_LINE_NOT_FOUND_ERROR` |
| `limit` | integer | No | Page size, counting each partner's opening row and each line (default 50, max 50) |
| `bookId` | UUID | Conditional | Required when the Entity has at least one Book; must be omitted otherwise |

**Response**

| Field | Type | Description |
| --- | --- | --- |
| `account` | object | `{ id, code, name, normalSide }`; `normalSide` is `debit` or `credit` |
| `currency` | string | Currency the amounts are in |
| `from` | ISO date | As requested |
| `to` | ISO date | As requested |
| `groups` | array | One item per partner on this page, each with the fields below |
| `nextCursor` | string or null | Pass as `cursor` to fetch the next page; `null` on the last page |

Each item in `groups`:

| Field | Type | Description |
| --- | --- | --- |
| `partnerId` | UUID or null | Partner; `null` for the unassigned group |
| `partnerName` | string or null | Name of the partner |
| `partnerTaxId` | string or null | Tax id of the partner |
| `partnerWebsite` | string or null | Website of the partner, as a bare domain (`acme.cl`); `null` when it has none |
| `openingBalance` | integer | What the partner's lines carry into `from`, under the [carry rule](#the-fiscal-year-in-reports) |
| `totalDebit` | integer | Debits in the period |
| `totalCredit` | integer | Credits in the period |
| `closingBalance` | integer | Balance at `to` |
| `lines` | array | The partner's lines in the period that fall on this page, each with the fields below |

Each item in `lines`:

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID | Line id |
| `entryId` | UUID | Parent entry |
| `entryDate` | ISO date | Date of the parent entry |
| `entryMemo` | string or null | Memo of the parent entry |
| `side` | enum | `debit` or `credit` |
| `functionalAmount` | integer | Nonnegative magnitude |
| `transactionCurrency` | string or null | Foreign currency code, if any |
| `transactionAmount` | integer or null | Amount in the foreign currency |
| `transactionFxRate` | decimal string or null | Rate used for conversion |
| `debit` | integer | Amount when `side` is `debit`, else `0` |
| `credit` | integer | Amount when `side` is `credit`, else `0` |
| `runningBalance` | integer | Balance after this line within the partner group |
| `documentNumber` | string or null | Number of the invoice this line books, if any |

```bash
curl -s "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/partner-ledger?accountId=<uuid>&from=2024-01-01&to=2024-12-31" \
  -H "Cookie: <session-cookie>"
```
