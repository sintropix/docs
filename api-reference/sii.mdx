The SII (Servicio de Impuestos Internos) is Chile's national tax authority. A DTE (Documento Tributario Electrónico) is a Chilean e-invoice or credit note issued through the SII. Sintropix imports DTEs from an SII feed and exposes them through the endpoints on this page so callers can read them and manage cross-DTE references (for example, a credit note referencing an original invoice). Sintropix does not emit DTEs on the caller's behalf here; issuance happens in the SII portal or through an integration that populates the feed.

A DTE can also be attached to an Invoice by hand with `PUT /invoices/:invoiceId/dte` on the [Invoices page](/api-reference/invoices); the `dte.id` returned there is the `dteId` used below.

## GET `/sii/document-types`

List the SII document type catalog available to this Entity (invoice, credit note, debit note, and their variants).

**Response:** an array of document types.

| Field | Type | Description |
| --- | --- | --- |
| `code` | string | The SII code (`33`, `34`, `39`, `61`, ...). Use it as `dteTypeCode` when attaching a DTE. |
| `country` | string | ISO 3166-1 alpha-2 code of the issuing tax authority (`CL`). |
| `label` | string | The official name of the document type. |

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/sii/document-types" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

Example response:

```json
[
  { "code": "33", "country": "CL", "label": "Factura Electrónica" },
  { "code": "34", "country": "CL", "label": "Factura No Afecta o Exenta Electrónica" },
  { "code": "39", "country": "CL", "label": "Boleta Electrónica" },
  { "code": "61", "country": "CL", "label": "Nota de Crédito Electrónica" }
]
```

## GET `/sii/dte/:dteId`

Fetch a single DTE with its detail, including its amounts and any references to or from other DTEs.

**Response:** a DTE detail object.

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | DTE id. |
| `entityId` | uuid | Owning Entity. |
| `invoiceId` | uuid or null | The Invoice this DTE backs. Null for a document the books do not track as a claim (a boleta, a guía). |
| `dteTypeCode` | string | SII document type code. |
| `folio` | integer or null | The number the SII assigned. `null` only on the DTE of a [Sales Summary](#sales-summaries) Invoice. |
| `salesSummaryId` | uuid or null | The [Sales Summary](#sales-summaries) the DTE lands. `null` on every other DTE. |
| `issuerRut` | string | Issuer RUT, canonical form (`76123456-0`). |
| `receiverRut` | string or null | Receiver RUT. |
| `issuerName` | string or null | Issuer name as printed. |
| `receiverName` | string or null | Receiver name as printed. |
| `issueDate` | string | `YYYY-MM-DD`. |
| `taxPeriod` | string or null | The F29 / IVA month, `YYYY-MM`. |
| `standing` | string or null | Where the SII holds the document: `accepted`, `pending`, `claimed`, `annulment_requested`, `annulled`, or `observed`. Only a [Source Feed](/api-reference/source-feeds#standing-and-tax-period) sync writes it; null on a DTE entered by hand. |
| `currency` | string | ISO 4217 code. |
| `total` | integer | Gross total, minor units of `currency`. |
| `netAmount` | integer or null | Net base, minor units. |
| `exemptAmount` | integer or null | Exempt part of the base, minor units. |
| `taxAmount` | integer or null | Tax amount, minor units. |
| `withheldIvaAmount` | integer or null | The part of `taxAmount` the buyer withholds, minor units. Mostly stated on a factura de compra (type `46`). Null when the DTE withholds no IVA. |
| `externalRef` | string or null | The id an external provider gave the document. Null when entered by hand. |
| `metadata` | array | Additional Information lines, `{ "label": string, "value": string }`. |
| `statedDteReferences` | array | References this DTE makes to other DTEs. Each has `targetDteId` (uuid), `referenceCode` (integer or null), `targetDteTypeCode` (string), and `targetFolio` (integer, or null when the target lands a Sales Summary). |
| `receivedDteReferences` | array | References other DTEs make to this one. Each has `dteId` (uuid, the referencing DTE), `referenceCode` (integer or null), `referencingDteTypeCode` (string), and `referencingFolio` (integer, or null when the referencing DTE lands a Sales Summary). |
| `createdAt` | timestamp | Creation time. |
| `updatedAt` | timestamp | Last update time. |

`referenceCode` is the SII code that says what the referencing document does to the referenced one: `1` voids it, `2` corrects its text, `3` corrects its amounts. Null means the DTE states a reference and no code.

A [Source Feed](/api-reference/source-feeds) sync links the references each landed DTE states, with their code, when the target DTE is already in the books. See [DTE references](/api-reference/source-feeds#dte-references). Use the endpoints below to add or remove a reference by hand.

## POST `/sii/dte/:dteId/references`

Add a reference from this DTE to a target DTE. Used, for example, to record that a credit note credits a specific original invoice.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `targetDteId` | uuid | Yes | The DTE being referenced. Must belong to the same Entity and differ from `dteId`. |
| `referenceCode` | integer or null | Yes | `1` (voids), `2` (corrects text), `3` (corrects amounts), or `null` for a reference with no code. |

**Response:** the updated DTE detail, as returned by `GET /sii/dte/:dteId`.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/sii/dte/$DTE_ID/references" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "targetDteId": "c3d4e5f6-a7b8-4c9d-8e0f-1a2b3c4d5e6f", "referenceCode": 1 }'
```

## DELETE `/sii/dte/:dteId/references/:targetDteId`

Remove a previously added reference.

**Response:** the updated DTE detail, as returned by `GET /sii/dte/:dteId`.

## Sales Summaries

For some sales types, the SII's Registro de Compras y Ventas (RCV) states no documents, only one total per month. The most common is type `48`, the vouchers of card payments. A Sales Summary holds the SII's figures for one of these types in one Tax Period of an Entity: how many documents the total counts, and the net, exempt, tax, and total amounts.

The total-only types are `35`, `38`, `47`, `48`, `105`, `919`, `920`, `922`, and `924`. Boletas (`39` and `41`) are not among them, because the SII lists each boleta; see [SII Mirror boletas](/api-reference/source-feeds#sii-mirror-boletas).

A [Source Feed](/api-reference/source-feeds#sii-mirror-sales-summaries) of family `dte` on an `sii_mirror` Integration writes the Sales Summaries and lands each one as receivable Invoices, which you book like any other sale. Only a Sync writes them. When the SII changes a figure, the Sync writes the new one over the stored one, and the [Audit Trail](/api-reference/audit-trail) keeps every earlier figure.

### The Sales Summary object

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Sales Summary id. |
| `entityId` | uuid | Owning Entity. |
| `taxPeriod` | string | The month, `YYYY-MM`. |
| `dteTypeCode` | string | The total-only SII document type. |
| `documentCount` | integer | How many documents the SII counts in the total. Zero or more. |
| `currency` | string | ISO 4217 code. |
| `netAmount` | integer | Net base, minor units of `currency`. |
| `exemptAmount` | integer | Exempt part of the base, minor units. |
| `taxAmount` | integer | Tax amount, minor units. |
| `total` | integer | Total, minor units. |
| `createdAt` | timestamp | When a Sync first wrote it. |
| `updatedAt` | timestamp | When its figures last changed. |

### GET `/sales-summaries`

List the Entity's Sales Summaries, newest Tax Period first, then by `dteTypeCode`.

**Response:** an array of Sales Summary objects.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/sales-summaries" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

### GET `/sales-summaries/:salesSummaryId`

Fetch one Sales Summary with the Invoices that land it.

**Response:** the Sales Summary object plus `invoices`, the Invoices that land it, oldest first. The first one lands the SII's figures, and each later one lands a change the SII made after the earlier ones were booked. Each item carries `id`, `documentNumber`, `documentKind`, `total`, `issueDate`, `controlLineId` (`null` until the Invoice is booked), `excludedAt`, and `createdAt`.

### Sales Summary errors

| Status | `code` | `params` | When |
| --- | --- | --- | --- |
| `404` | `SALES_SUMMARY_NOT_FOUND_ERROR` | `{ salesSummaryId }` | No Sales Summary with that id exists on the Entity. |
| `409` | `DTE_HELD_BY_SALES_SUMMARY_ERROR` | `{ dteId }` | A write or delete of the DTE of a Sales Summary Invoice, through [`PUT` or `DELETE /invoices/:invoiceId/dte`](/api-reference/invoices#put-invoices-invoiceid-dte). The SII owns these DTEs, so only a Sync writes them. |

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success. |
| `400` | Validation error, or missing `x-audit-actor` on a key-authenticated mutation. |
| `404` | Entity, DTE, target DTE, or Sales Summary not found. |
| `409` | Duplicate reference or invalid reference target (for example, a DTE referencing itself). |
