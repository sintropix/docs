A Source is a named origin an Entity uses to group documents it pulls from external systems: for example, an SII feed, a supplier email inbox, or a CSV import. A Source is a bucket; the [Source Feeds](/api-reference/source-feeds) attached to it are what actually fetch data.

## Sources that hold Expense Renditions

An **Expense Rendition** (rendición) is an expense that a person of the Entity paid with their own money and reports for reimbursement, either through a tool such as Rindegastos or Xpendit or as an [Expense Claim](/api-reference/expense-claims) approved in Sintropix. Its Partner is the person who paid, not the merchant.

Mark the Source of those documents as one that holds Expense Renditions (`holdsExpenseRenditions: true`). Every `payable` Invoice of a marked Source is an Expense Rendition:

- In the app, it's listed in **Rendiciones** (under **Datos**) instead of **Compras**, with its own totals and counts. **Rendiciones** has the filters and groupings of **Compras** except the ones that read a DTE: no document type or DTE columns, no DTE type, Standing, or Tax Period filter, and no grouping by DTE type or Tax Period. **Nueva rendición** submits an [Expense Claim](/api-reference/expense-claims), which becomes an Expense Rendition when it's approved. The **Por aprobar** and **Rechazadas** views list the claims that wait and the rejected ones.
- In the API, its Invoice row carries `isExpenseRendition: true`, and [`GET /invoices/pages`](/api-reference/invoices#get-invoices-pages) filters by it with `isExpenseRendition`.
- The home dashboard counts it in `expenseRenditionsToBook`, not in `purchasesToBook`. See [Home dashboard](/api-reference/reports#home-dashboard).

A `receivable` Invoice is never an Expense Rendition, whatever its Source. Sintropix reads the mark from the Source and never stores it on the Invoice. Unmark the Source and its Invoices go back to **Compras** right away, booked or not.

In the app, turn on **Fuente de rendiciones** for the Source in **Configuración** → **Fuentes**, or when you create it.

While an Entity's [Expense Claim setting](/api-reference/expense-claims#before-you-submit-claims) names the Source, you can't unmark it or delete it: Sintropix refuses both with `409` and `SOURCE_PINNED_ERROR`, with `params.sourceId`. Pick another Source in **Configuración → Rendiciones** first.

The same holds while an [expense Feed](/api-reference/source-feeds#expense-feeds) fills the Source: unmarking it answers `409` with `SOURCE_PINNED_ERROR`.

## GET `/sources`

List every Source for the Entity, each annotated with the count of Invoices it has produced.

**Response:** an array of Source objects.

| Field | Type | Description |
| --- | --- | --- |
| `id` | uuid | Source id. |
| `entityId` | uuid | Owning Entity. |
| `name` | string | Display name, unique within the Entity. |
| `holdsExpenseRenditions` | boolean | Whether the Source's `payable` Invoices are [Expense Renditions](#sources-that-hold-expense-renditions). |
| `invoiceCount` | integer | How many Invoices name this Source. |
| `createdAt` | timestamp | Creation time (ISO 8601). |
| `updatedAt` | timestamp | Last update time (ISO 8601). |

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/sources" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

Example response:

```json
[
  {
    "id": "5d6e7f80-91a2-4b3c-8d4e-5f6a7b8c9d0e",
    "entityId": "b2f0c1d4-7e8a-4b9c-8d1e-2f3a4b5c6d7e",
    "name": "Bsale",
    "holdsExpenseRenditions": false,
    "invoiceCount": 412,
    "createdAt": "2026-03-02T09:15:44.000Z",
    "updatedAt": "2026-03-02T09:15:44.000Z"
  }
]
```

## POST `/sources`

Create a Source.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | Yes | Caller-generated id. Retrying with the same id is answered `409`, so a retried request never creates a second Source. |
| `name` | string | Yes | Trimmed before it is stored; must be non-empty after trimming and unique within the Entity. |
| `holdsExpenseRenditions` | boolean | No | Mark the Source as one that holds [Expense Renditions](#sources-that-hold-expense-renditions). Default `false`. |

**Response** (`201`): the created Source object, with `invoiceCount` of `0`.

```bash
curl -X POST "https://api.sintropix.com/api/entities/$ENTITY_ID/sources" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "id": "5d6e7f80-91a2-4b3c-8d4e-5f6a7b8c9d0e", "name": "Bsale" }'
```

## PATCH `/sources/:sourceId`

Rename a Source, mark or unmark it as one that holds Expense Renditions, or both. Send at least one field. A field you omit keeps its value. An empty body is answered `400`.

**Body**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | No | New name. Trimmed, non-empty, unique within the Entity. |
| `holdsExpenseRenditions` | boolean | No | `true` marks the Source as one that holds [Expense Renditions](#sources-that-hold-expense-renditions); `false` unmarks it. A Source the [Expense Claim setting](/api-reference/expense-claims#before-you-submit-claims) names, or that an [expense Feed](/api-reference/source-feeds#expense-feeds) fills, can't be unmarked (`409`, `SOURCE_PINNED_ERROR`). |

**Response:** the updated Source object.

```bash
curl -X PATCH "https://api.sintropix.com/api/entities/$ENTITY_ID/sources/$SOURCE_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Bsale (ventas)" }'
```

To mark a Source as one that holds Expense Renditions:

```bash
curl -X PATCH "https://api.sintropix.com/api/entities/$ENTITY_ID/sources/$SOURCE_ID" \
  -H "x-api-key: $SINTROPIX_API_KEY" \
  -H "x-audit-actor: my-agent" \
  -H "Content-Type: application/json" \
  -d '{ "holdsExpenseRenditions": true }'
```

## DELETE `/sources/:sourceId`

Delete a Source. Sources referenced by existing Invoices or attached Source Feeds are refused. So is a Source the [Expense Claim setting](/api-reference/expense-claims#before-you-submit-claims) names, with `409` and `SOURCE_PINNED_ERROR`.

**Response:** the deleted Source object.

## Status codes

| Status | Meaning |
| --- | --- |
| `200` | Success on `GET`, `PATCH`, `DELETE`. `DELETE` answers with the deleted row. |
| `201` | Source created. |
| `400` | Validation error, an empty `PATCH` body, or missing `x-audit-actor` on a key-authenticated mutation. |
| `404` | Entity or Source not found. |
| `409` | Source id or name already exists, the Source has attached Invoices or Feeds and cannot be deleted, or the Expense Claim setting names it (`SOURCE_PINNED_ERROR`). |
