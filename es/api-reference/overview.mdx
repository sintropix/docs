La API de Sintropix es una interfaz JSON sobre HTTPS al sistema que gestiona tu contabilidad, tus facturas, tus movimientos bancarios y tus informes. Cada ruta de negocio está acotada a una sola Entidad (una empresa legal con sus propios libros) y se autentica con una clave de API. Las solicitudes y respuestas se validan de extremo a extremo, por lo que los nombres de campo, tipos y enumeraciones son consistentes en todos los endpoints.

<Note>
  Las páginas de referencia de cada endpoint están disponibles solo en inglés por ahora.
</Note>

## URL base

Todas las rutas se montan bajo el prefijo `/api`:

```text
https://api.sintropix.com/api
```

La API no lleva versión en la ruta de la URL.

## Forma de las rutas

La mayoría de los recursos de negocio viven bajo una sola Entidad:

```text
/api/entities/{entityId}/<recurso>
```

Por ejemplo:

```text
GET  /api/entities/{entityId}/ledger/accounts
POST /api/entities/{entityId}/invoices
GET  /api/entities/{entityId}/reports/balance-sheet
```

Unas pocas rutas son independientes de la Entidad: [`/api/entities`](/api-reference/entities) (listar y crear), [`/api/organizations`](/api-reference/organizations), [`/api/fx-rates`](/api-reference/fx-rates), [`/api/countries` y `/api/currencies`](/api-reference/reference-data), [`/api/onboarding/*`](/api-reference/onboarding) (solo para Superadmins) y `/api/health`.

`{entityId}` es siempre un UUID. Una solicitud sobre una Entidad a la que quien llama no tiene acceso devuelve `404`, nunca `403`, de modo que sondear rutas no revela si una Entidad desconocida existe.

## Acceso y roles

El acceso a una Entidad proviene de una **Membresía de Organización**. Una [Organización](/api-reference/organizations) agrupa las Entidades que un cliente gestiona como un solo negocio, y cada Entidad pertenece a exactamente una Organización. Una Membresía le da a un Usuario un Rol en una Organización. Ese Rol aplica a todas las Entidades de la Organización, incluidas las que se agreguen después.

| Rol | Leer datos de la Entidad | Escribir datos de la Entidad | Trabajo de Sintropix |
| --- | --- | --- | --- |
| `staff` | Sí | Sí | Sí |
| `client` | Sí | Sí | No |
| `viewer` | Sí | No | No |

- **Leer** cubre las solicitudes `GET` sobre rutas de Entidad, incluido el [Audit Trail](/api-reference/audit-trail). **Escribir** cubre `POST`, `PUT`, `PATCH` y `DELETE`.
- **Trabajo de Sintropix** cubre las rutas reservadas al equipo contable: credenciales, automatizaciones, [Agent Channels](/api-reference/agent-channels), [To-dos](/api-reference/todos), [bandejas de correo](/api-reference/integrations#email-inboxes-staff-only), sincronización de honorarios, políticas contables y la [sincronización de tipos de cambio](/api-reference/fx-rates).
- Una Entidad fuera de tus Organizaciones devuelve `404`. Una acción que tu Rol no permite devuelve `403` con `PERMISSION_DENIED_ERROR`.
- Ningún Rol es global. Un Usuario sin Membresía en una Organización no puede acceder a sus Entidades, sin importar el Rol que tenga en otras.

Un **Superadmin** es un Usuario que Sintropix designa para administrar el acceso: Usuarios, Organizaciones, Membresías y Entidades: crearlas, fijar su Entidad matriz y trasladarlas entre Organizaciones. Un Superadmin lo hace mediante la [API de Onboarding](/api-reference/onboarding), la [API de Organizaciones](/api-reference/organizations) y la [API de Entidades](/api-reference/entities). Estas rutas solo aceptan una sesión iniciada en el navegador. Una solicitud con una clave de API o un token de acceso OAuth recibe `403` con `SUPERADMIN_SESSION_REQUIRED`, aunque sea de un Superadmin, y cualquier otro Usuario recibe `403` con `SUPERADMIN_REQUIRED`. Ser Superadmin no abre ningún libro: un Superadmin accede a una Entidad solo mediante una Membresía, como todos los demás.

## Autenticación

Los clientes programáticos se autentican de una de dos formas:

- **Clave de API** en el encabezado `x-api-key`. Las claves se crean en la aplicación de Sintropix; consulta [Obtener una clave de API](/es/guides/api-keys).
- **Token de acceso OAuth** en el encabezado `Authorization: Bearer <token>`. Una app obtiene uno cuando un Usuario la aprueba para una Organización; consulta [Conectar una app con OAuth](/es/guides/connected-apps). Un token actúa como ese Usuario solo en esa Organización, con acceso de lectura o de lectura y escritura, y nunca más allá del Rol del Usuario. Claude y ChatGPT lo usan para conectarse al [servidor MCP de Sintropix](/es/guides/mcp-server).

Toda solicitud que modifica datos (`POST`, `PUT`, `PATCH`, `DELETE`) hecha con una clave de API debe enviar además un Actor Declarado y una Razón Declarada:

```http
x-api-key: <secreto>
x-audit-actor: <etiqueta-de-tu-agente>
x-audit-reason: <por qué realizas este cambio>
```

`x-audit-actor` es una etiqueta de software autodeclarada (por ejemplo `claude-opus-4.8`) que se guarda tal cual en el [registro de auditoría](/api-reference/audit-trail). Omitirla en una mutación devuelve `400`.

`x-audit-reason` es una explicación de una sola línea, en texto plano, de por qué se realiza el cambio (máx. 500 caracteres). El servidor recorta los espacios al inicio y al final, y guarda el valor en el Sobre de Auditoría. Un valor ausente o vacío devuelve `400` con el código `AUDIT_REASON_REQUIRED_ERROR`; un valor de más de 500 caracteres devuelve `400` con el código `AUDIT_REASON_TOO_LONG_ERROR`.

Una solicitud que modifica datos hecha con un token de acceso OAuth también debe enviar `x-audit-reason`. No necesita `x-audit-actor`: el registro de auditoría nombra la app aprobada.

## Formato de las solicitudes

Las solicitudes son JSON plano. Incluye `Content-Type: application/json` en cualquier solicitud con cuerpo.

```bash
curl "https://api.sintropix.com/api/entities/$ENTITY_ID/ledger/accounts" \
  -H "x-api-key: $SINTROPIX_API_KEY"
```

Los parámetros de ruta que son identificadores deben ser UUID válidos; un identificador mal formado devuelve `400`. Un `entityId` mal formado devuelve `404`, como cualquier Entidad a la que no tienes acceso.

## Formato de las respuestas

Las respuestas son el recurso en sí como JSON. No hay un envoltorio `data` de nivel superior, ni un bloque `meta`, ni un bloque `pagination` en los endpoints no paginados. Cada página de referencia lista los campos que devuelve cada endpoint.

Un recurso individual se devuelve como un objeto:

```json
{
  "id": "…",
  "name": "…"
}
```

Un endpoint de listado devuelve un arreglo JSON sin envoltorio:

```json
[
  { "id": "…" },
  { "id": "…" }
]
```

Un endpoint paginado (aquellos cuya ruta termina en `/pages`, más algunos informes) devuelve un objeto `{ rows, nextCursor }`. `nextCursor` es `null` en la última página.

```json
{
  "rows": [ /* … */ ],
  "nextCursor": "…"
}
```

<Note>
  La paginación se habilita endpoint por endpoint, no en todo el sitio. Los endpoints sin `/pages` en su ruta devuelven todas las filas y no aceptan el argumento `cursor`. Revisa la página de referencia del endpoint que estés llamando.
</Note>

## Errores

Las respuestas distintas de 2xx son JSON. Toda respuesta, exitosa o fallida, lleva un encabezado `x-request-id`; cítalo cuando contactes a soporte.

| Código | Significado |
| --- | --- |
| `200` | La solicitud se completó correctamente. |
| `201` | Recurso creado. |
| `204` | La solicitud se completó correctamente sin cuerpo de respuesta. |
| `400` | El cuerpo, la query o la ruta no pasaron la validación, o falta un encabezado obligatorio. |
| `401` | No hay una clave de API, sesión ni token de acceso OAuth válidos. Un token vencido o revocado también devuelve `401`. |
| `403` | Quien llama no tiene permiso para esta acción (por ejemplo, una clave de solo lectura intentando una mutación, o un `viewer` intentando escribir). Los rechazos por Rol llevan `PERMISSION_DENIED_ERROR`. |
| `404` | El recurso no existe, o quien llama no tiene acceso a la Entidad solicitada. |
| `409` | Conflicto de dominio (por ejemplo, un asiento contable ya contabilizado o una fila duplicada). |
| `429` | Se superó el límite de solicitudes de una clave de API. |
| `500` | Error de servidor no controlado. |

Los errores de dominio llevan en el cuerpo un `code` de tipo string estable, por ejemplo `API_KEY_READ_ONLY_ERROR`. Compara contra `code`, no contra el mensaje legible por humanos.

## Límites de solicitudes

Cada clave de API está limitada a **25.000 solicitudes por hora** en una ventana deslizante. Superar el límite devuelve `429`; no existe un contrato de encabezados `X-RateLimit-*` en la respuesta.

## Estado del servicio

Sintropix publica el estado en vivo de la API del ERP y de la app de clientes en [status.sintropix.com](https://status.sintropix.com). Revísalo cuando las solicitudes fallen con errores `5xx` o se agote el tiempo de espera, antes de contactar a soporte.

## Llamadas desde el navegador

La API está diseñada para uso servidor a servidor con una clave de API. Llamarla directamente desde un navegador requiere que Sintropix incluya tu origen en una lista de permitidos; contacta a soporte si lo necesitas.

## Qué no forma parte de la API

<Warning>
  **No hay sistema de webhooks**. Sintropix no envía notificaciones de eventos a URL externas. Consulta periódicamente los endpoints que te interesen, o el [registro de auditoría](/api-reference/audit-trail) como feed de cambios.
</Warning>

<Warning>
  **No hay paginación por cursor en la mayoría de los endpoints**. Solo los endpoints cuya ruta termina en `/pages` (más los paginadores de libro mayor, partidas abiertas, diario y asientos contables) devuelven `{ rows, nextCursor }`. El resto devuelve la lista completa.
</Warning>

<Warning>
  Las claves de API van en el encabezado `x-api-key`, nunca en `Authorization: Bearer`. El encabezado `Authorization: Bearer` lleva solo tokens de acceso OAuth de [apps conectadas](/es/guides/connected-apps).
</Warning>

<Warning>
  **No hay prefijo `/v1`**. La ruta base es `/api`.
</Warning>
