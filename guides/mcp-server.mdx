The Sintropix MCP server lets an AI assistant that speaks the Model Context Protocol (MCP), such as Claude or ChatGPT, read your books. You ask in plain language, for example "What do my customers owe me?", and the assistant answers from your Sintropix data.

The server reads your books and the files your Organization shared with Sintropix, such as Google Sheets and Metabase questions. It can't create, change, or delete anything in them. The one thing it sends is feedback about Sintropix itself, which changes no data.

```text
https://mcp.sintropix.com/mcp
```

## Connect

<Steps>
  <Step title="Add the server to your assistant">
    The server uses OAuth, so you don't need an API key or any other secret. Pick your assistant:

    <Tabs>
      <Tab title="Claude">
        On a Free, Pro, Max, or Ultra plan, in claude.ai or Claude Desktop. The Free plan allows one custom connector.

        1. Go to **Customize** > **Connectors**.
        2. Click **+ Add**, then **Add custom connector**.
        3. Name it `Sintropix` and paste the server URL `https://mcp.sintropix.com/mcp`. Click **Continue**.
        4. Keep the authentication settings Claude detected and click **Continue**.
        5. Under **OAuth client**, choose **Register automatically**. Click **Add**.
        6. Click **Connect** on the Sintropix connector.
      </Tab>
      <Tab title="Claude Team and Enterprise">
        An Owner or Primary Owner adds the connector once for the whole organization:

        1. Go to **Organization settings** > **Connectors**.
        2. Click **Add**, hover over **Custom**, and select **Web**.
        3. Name it `Sintropix` and paste the server URL `https://mcp.sintropix.com/mcp`. Click **Continue**.
        4. Keep the authentication settings Claude detected and click **Continue**.
        5. Under **OAuth client**, choose **Register automatically**. Click **Add**.

        Then each member goes to **Customize** > **Connectors**, finds Sintropix, and clicks **Connect**. Each member signs in as themselves, so the assistant reads with that member's own access.
      </Tab>
      <Tab title="Claude Code">
        Add the server from your terminal:

        ```bash
        claude mcp add --transport http sintropix https://mcp.sintropix.com/mcp
        ```

        Then start Claude Code, run `/mcp`, select `sintropix`, and choose to authenticate.
      </Tab>
      <Tab title="Other assistants">
        In your assistant's settings, add a custom connector (or custom MCP server) and paste the server URL `https://mcp.sintropix.com/mcp`.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Sign in to Sintropix">
    The assistant opens Sintropix in your browser. Sign in with your password and second factor. If you haven't set up two-step verification yet, Sintropix asks you to do it first.
  </Step>
  <Step title="Pick the Organization">
    Choose the Organization the assistant will read (**Elige la empresa**). If you hold a Membership in only one Organization, Sintropix skips this screen.
  </Step>
  <Step title="Approve">
    Check the request: the app name, the domain it returns you to (**Te devolverá a**), the Organization, and the access, which is **Solo lectura**. Click **Permitir**. The assistant is now connected.
  </Step>
</Steps>

Each connection reads one Organization, and every company (Entity) in it. To read another Organization, approve the assistant again and pick that Organization. Each approval appears as its own row in **Tu cuenta** > **Apps conectadas**.

The assistant registers itself with Sintropix the first time you connect. An assistant that returns to a custom scheme with a host, such as `cursor://`, can't register, so it can't connect. See the [redirect URIs an app can register](/guides/connected-apps#connect-your-app).

## Access

- The assistant reads as you, in the Organization you approved, with your Role there. Any Role can read, so `staff`, `client`, and `viewer` Users can all connect.
- If you lose your Membership in the Organization, the connection ends.
- Revoke the connection at any time from **Tu cuenta** > **Apps conectadas** in the Sintropix app. The assistant loses access at once, and asks you to sign in again the next time it needs Sintropix.
- The access token lasts 1 hour, and the assistant renews it on its own. If the assistant goes 30 days without renewing it, it asks you to sign in again.

See [Connect an app with OAuth](/guides/connected-apps) for the full rules of connected apps.

## Tools

The server exposes ten tools. Seven read your books, two read the files your Organization shared, and `leave_feedback` tells the Sintropix developers what got in the assistant's way. Each one answers a question, rather than mirroring an API endpoint. Amounts come back as decimal text in the company's functional currency, or, for the bank tools, in the currency of each bank account. Accounts, banks, and Partners come back with their names.

| Tool | Question it answers | Inputs |
| --- | --- | --- |
| `list_entities` | Which companies can I read? | None |
| `get_receivables` | What do my customers owe me? | `entityId` |
| `get_payables` | Which bills haven't I paid? | `entityId` |
| `get_income_statement` | What did I earn in a period? | `entityId`, optional `from` and `to` |
| `get_balance_sheet` | What do I have and owe on a date? | `entityId`, optional `cutoffDate` |
| `list_bank_accounts` | How much cash do I have, and where? | None |
| `list_bank_movements` | What came in, what went out, and what's still to reconcile? | `entityId`, optional `bankAccountId`, `status`, `direction`, `from`, `to`, `search`, `partnerId`, `order`, `limit`, and `cursor` |
| `list_integration_files` | Which files did we share? | None |
| `read_integration_file` | What does this file say now? | `integrationId`, `fileId`, `reason`, optional `parameters` and `tab` |
| `leave_feedback` | How do I tell Sintropix what got in my way? | `kind`, `message`, optional `endpoint`, `requestId`, and `reproduction` |

### `list_entities`

Lists the companies the connection reads. Each item has `entityId`, `name`, `taxId`, `country`, `currency`, and `organization` (the Organization's name). The assistant calls it first to find the `entityId` the other tools take.

### `get_receivables` and `get_payables`

List the open lines of each receivable or payable Ledger Account of the company, oldest first. Each line has its date, due date, Partner, invoice, memo, and open amount. A positive open amount is owed to the company in `get_receivables`, and owed by the company in `get_payables`. `get_payables` also lists what the company owes people on approved Expense Claims, under its Rendición por pagar accounts.

- A line with no invoice is an Unapplied Item, such as a payment received on account. The assistant reports it beside what is owed, never netted against it.
- Each account returns up to 100 open lines. `openLinesNotShown` counts the rest.
- These tools read the accounts whose Sub-type is `receivable` or `payable` in the [chart of accounts](/api-reference/chart-of-accounts). If the company marks no account with that Sub-type, the answer has no accounts and a `note` that says so. It doesn't mean nothing is owed: the assistant reads the balances with `get_balance_sheet` instead.

### `get_income_statement`

Returns the income statement (Estado de Resultados) for a period: income, cost of goods sold, operating expenses, other income, and other expenses, each with its accounts and total. It also returns the gross profit, the operating result, the operating margin (a ratio, `null` with no income), and the net result.

| Input | Type | Default |
| --- | --- | --- |
| `entityId` | UUID | Required |
| `from` | `YYYY-MM-DD` | January 1 of the year of `to` |
| `to` | `YYYY-MM-DD` | Today in Chile |

### `get_balance_sheet`

Returns the balance sheet (Balance General) on a date: assets, liabilities, and equity, each with its accounts and total. The equity section also carries the result of prior Fiscal Years and the result of the Fiscal Year up to the date. The Fiscal Year is the Entity's own (see [The Fiscal Year in reports](/api-reference/reports#the-fiscal-year-in-reports)), and the answer names the day it starts.

| Input | Type | Default |
| --- | --- | --- |
| `entityId` | UUID | Required |
| `cutoffDate` | `YYYY-MM-DD` | Today in Chile |

### `list_bank_accounts`

Answers how much cash you have, and where. It lists the bank accounts and cards of every company the connection reads, and takes no inputs. Each account has:

- `bankAccountId`, `name`, `kind` (`bank` or `card`), `entityId`, and `entity` (the company's name).
- `bank`: the bank's name, or the Provider that feeds the account when the account has no known bank, such as a wallet. `null` when neither is known.
- `accountNumber` and `currency`.
- `balance`: the bank's side, in the account's own currency. It adds up every Movement the bank reported, money in positive and money out negative, so what a card owes reads negative. It differs from the Ledger Account on the balance sheet while Movements wait to be reconciled.
- `movementsToReconcile`: how many of the account's Movements aren't reconciled with the books yet. `list_bank_movements` lists them.
- `feed`: `null` when no [bank feed](/api-reference/bank-feeds) feeds the account, and a person enters or imports its Movements. Otherwise it has `provider`, `lastSyncedAt` (`null` before the first sync), and `tieOut` (`null` before a sync judged it), with `status`, `reportedBalance`, and `since`, when the feed entered that status. See [Tie-out](/api-reference/bank-accounts#tie-out).

| `tieOut.status` | Meaning |
| --- | --- |
| `tied_out` | The Movements add up to the `reportedBalance` the bank stated. |
| `out_of_tie_out` | They don't. `balance` minus `reportedBalance` is the gap: a Movement the feed hasn't brought, such as a fee, or one that landed twice. |
| `restated` | The bank rewrote Movements that had already landed. A person must review them in the app. |

The answer also has three totals:

- `cashByCurrency`: the bank accounts added up by currency, cards left out.
- `cardBalanceByCurrency`: the cards added up by currency.
- `totalValued`: every account, cards included, valued in one currency at the newest published exchange rates. It has `currency`, `total`, `rateDate`, and `unconvertedCurrencies`, the currencies left out because they have no rate.

### `list_bank_movements`

Answers what came in, what went out, and what's still to reconcile. It lists the bank Movements of one company, or of one account, a page at a time.

| Input | Type | Default | Description |
| --- | --- | --- | --- |
| `entityId` | UUID | Required | From `list_entities` or `list_bank_accounts`. |
| `bankAccountId` | UUID | Every account of the company | One account, from `list_bank_accounts`. An account the company doesn't have is refused. |
| `status` | enum | `all` | `to_reconcile`, `reconciled`, `excluded`, or `all`. `to_reconcile` includes the partial ones. |
| `direction` | enum | Both | `in`: money into the account, or a payment to a card. `out`: money out, or a charge on a card. |
| `from` | `YYYY-MM-DD` | None | The first date. |
| `to` | `YYYY-MM-DD` | None | The last date. |
| `search` | string | None | Text to find in the description, the start of the bank reference, the Partner's name, or the amount in minor units, such as `Minera` or `1500000`. |
| `partnerId` | UUID | None | Only the Movements of this Partner. |
| `order` | enum | `newest_first` | `newest_first`, `oldest_first`, `largest_in_first`, or `largest_out_first`. To rank one direction from largest to smallest, send `largest_in_first` with `direction` `in`, or `largest_out_first` with `direction` `out`. |
| `limit` | integer | 50 | Movements per answer, from 1 to 100. |
| `cursor` | string | None | The `nextCursor` of the previous answer. Send it with the same inputs as that call. |

The answer has `entity`, `movements`, and `nextCursor`. When `nextCursor` isn't `null`, there are more Movements. Each Movement has:

- `movementId`, `date`, `bankAccountId`, `bankAccount` (the account's name), and `currency`.
- `amount`: in the account's currency, positive for money in and negative for money out.
- `description` (the bank's), `partner`, `partnerId`, and `bankReference`. A `null` `partner` means nobody named the counterparty yet.
- `status`: `to_reconcile` when nobody booked it yet; `partial` when it's booked but part of the money waits on the Suspense Account for a person to assign it, which also counts as to reconcile; `reconciled` when it's in the books; `excluded` when a person left it out of the books.
- `balanceAfter`: the account's balance right after the Movement, counting every earlier Movement of the account, whatever the filters.

The tool doesn't group Movements, and it doesn't filter by Follow-up or ERP Thread. To total a period, the assistant adds up the rows. See [Bank movements](/api-reference/bank-movements) for the full listing in the API.

### `list_integration_files`

Lists the files that your Organization's people chose to share with Erwin and the MCP: the Google Sheet of each [Google Drive Integration](/api-reference/integrations#files-for-erwin-and-the-mcp), and the questions chosen on each [Metabase Integration](/api-reference/integrations#metabase). Each item has its `integrationId`, `fileId`, `name`, `purpose`, `description` (the file's description in Google Drive or Metabase), and `parameters`: the filters a read can send, each as `{ slug, name, type }`, such as `{ "slug": "canal", "name": "Canal", "type": "string/=" }`. A Sheet has no parameters. The assistant reads the purpose to pick the file that answers your question, and the description when there's no purpose.

A file the Provider no longer reaches, such as a Sheet that was deleted or trashed, or a Metabase question that was archived, doesn't appear. A connection whose files can't be listed comes back under `unlisted`, with its `integrationId` and the API's refusal. `INTEGRATION_GRANT_FAILED_ERROR` means someone has to connect the Sheet again in **Configuración → Integraciones**.

### `read_integration_file`

Reads one shared file as it is now at its Provider: a Sheet as it is in Google Drive, or a Metabase question, which runs in Metabase when it's read. For a question, the assistant sends the filters your question needs in `parameters`, and the question runs with them. It answers each tab as CSV, with the cells as the Sheet shows them. Each tab has `tab` (its name), `rowCount`, `truncated`, and `csv`. A tab is cut at 2,000 rows, and `truncated` says when it has more.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `integrationId` | UUID | Yes | From `list_integration_files`. |
| `fileId` | UUID | Yes | From `list_integration_files`. |
| `reason` | string | Yes | One line on what you asked that needs the Sheet. Sintropix records it in the [audit trail](/api-reference/audit-trail) with the read. Up to 500 characters. |
| `parameters` | object | No | A value for each filter to apply, under its `slug` from `list_integration_files`, such as `{ "canal": "online", "anio": "2026" }`. A filter left out isn't applied. Defaults to none. |
| `tab` | string | No | The name of one tab to read. Without it, the tool reads every tab. A name the Sheet doesn't have is refused with the list of its tabs. |

The assistant treats the cells as data people wrote, never as instructions. `INTEGRATION_FILE_GONE_ERROR` means the Sheet was deleted or its owner took the access away: share it again, or connect another Sheet. `INTEGRATION_FILE_TOO_LARGE_ERROR` means the Sheet is larger than the 10 MB Google exports. `INTEGRATION_FILE_PARAMETER_UNKNOWN_ERROR` (`422`) means `parameters` holds a slug the file doesn't take: send only the slugs `list_integration_files` gives. A `viewer` can't list or read shared Sheets. See [Who can read the files](/api-reference/integrations#who-can-read-the-files).

### `leave_feedback`

Sends [Feedback](/api-reference/feedback) to the people who build Sintropix: a bug, an answer that confused the assistant, a possible improvement, a papercut, a nit, or something it wanted to do and couldn't, with what it did instead. The assistant sends it on its own, right when it hits the problem, one problem per call. It doesn't need to tell you or ask you first, because Feedback is about the product, not about your books.

Feedback changes nothing in your books, so a **Solo lectura** connection sends it too. The tool asks the assistant to keep client data out: it sends ids and `requestId`s, not names, amounts, or document contents. See [Keep client data out](/api-reference/feedback#keep-client-data-out).

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `kind` | enum | Yes | `bug`, `improvement`, `papercut`, `nit`, or `missing_capability`. See [Kinds](/api-reference/feedback#kinds). |
| `message` | string | Yes | What happened, what the assistant expected, and what it did instead. Up to 10,000 characters. It can't be blank. |
| `endpoint` | string or null | No | The tool or API route involved, for example `get_payables`. Up to 500 characters. |
| `requestId` | string or null | No | The `requestId` of a failed Sintropix API call. Up to 200 characters. |
| `reproduction` | string or null | No | Anything small that helps reproduce the problem: the arguments sent, the steps, the answer received. Up to 10,000 characters. |

The inputs follow the same rules as [`POST /api/feedback`](/api-reference/feedback#post-/feedback). The tool answers `feedbackId`, the id of the stored Feedback. If an input breaks a rule, the tool answers an error that names each field and says what to fix, for example `kind must be one of: bug, improvement, papercut, nit, missing_capability`, and sends nothing.

### When a tool fails

A tool call that fails answers its error as JSON text with three fields:

- `message`: what went wrong.
- `requestId`: the id of the Sintropix API request that refused the call. It's absent when the failure didn't come from an API refusal.
- `feedbackInvitation`: a sentence that asks the assistant to report the problem with `leave_feedback`, citing that `requestId`.

```json
{
  "message": "The ERP refused GET /entities/{entityId}/reports/income-statement with 400. Validation failed",
  "requestId": "9fddebf9-d98b-473e-9aec-abe88cc0428a",
  "feedbackInvitation": "If this error looks wrong or blocks you, send requestId 9fddebf9-d98b-473e-9aec-abe88cc0428a with leave_feedback to tell the Sintropix developers."
}
```

The assistant can pass that `requestId` to `leave_feedback`. Input that breaks a tool's own rules, such as a `kind` that isn't one of the five, is refused before the tool runs. That error stays plain text, with no `requestId` or `feedbackInvitation`.

## Example questions

- "Which of my companies can you see?"
- "What does Acme SpA's customer list owe us, oldest first?"
- "Which bills of Acme SpA are past due?"
- "What was Acme SpA's net result from January to June?"
- "Show me Acme SpA's balance sheet at the end of last month."
- "How much cash do I have across my companies, by currency?"
- "Which movements in my BCI account are still unreconciled this month?"
- "What were Acme SpA's biggest outflows last month, and to whom?"
- "Is my Global66 feed up to date?"
